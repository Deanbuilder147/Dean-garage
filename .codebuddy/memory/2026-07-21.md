改为条件中间件：对 `/images`、`/views`、`/factions/logo` 三个前缀跳过鉴权，其余仍 `authenticate`+`requireAuth`。
```ts
const PUBLIC_IMAGE_RE = /^\/?(api\/units\/)?(images|views|factions\/logo)\//;
router.use('/api/units', (req, res, next) => {
  if (PUBLIC_IMAGE_RE.test(req.path)) return next();
  return authenticate(req, res, () => requireAuth(req, res, next));
});
```
**关键坑**：`router.use('/api/units', mw)` 会把已匹配前缀从 `req.path` 剥离，中间件内 `req.path` 形如 `/views/...`（不是 `/api/units/views/...`）。首版正则用 `/^\/api\/units\/(images|views|...)/` 测 node 为 true，但运行时 req.path 已被剥离 → 不匹配 → 仍 401。必须让正则兼容剥离后的路径（故用 `/^\/?(api\/units\/)?(images|views|factions\/logo)\//`）。

## 用户实测弹窗 [HTTP 400] 请上传图片文件 → 拿到真因（最终修复部署）
硬刷后重传弹窗：`主图上传失败 [HTTP 400] (/units/upload-image) 请上传图片文件`，控制台 `AxiosError 400`。后端 `!req.file` 才返回 400，故**文件没被当成 multipart 收到**。

### 真因（两轮修复教训）
- 第一轮删手动 Content-Type 反而更糟：`apiClient` 实例默认 `Content-Type: application/json` 接管 → FormData 当 JSON 发 → multer 收不到 → 400。
- 手动写 `'multipart/form-data'`（无 boundary）也错：Content-Type 缺 boundary → multer 收不到。
- **正确**：请求级 `delete config.headers['Content-Type']`，让浏览器 XHR 自动补 `multipart/form-data; boundary=xxx`。

### 最终修复（已部署，新 JS index-CbCMSxW5.js）
`client.js` 请求拦截器：`if (config.data instanceof FormData) delete config.headers['Content-Type']`。
部署：rsync client.js → `npm run build`（index-CbCMSxW5.js）→ `build --no-cache mecha-frontend` → `up -d --no-deps`。容器内 grep `instanceof FormData` 命中、首页 200 确认。
