## 战场部署排查：棋子无法部署（404 + 400）
控制台报错 `[factions] 加载失败 404` 与 `AxiosError 400`。已生成桌面报告 `/Users/dingxuyang/Desktop/战场部署问题报告_2026-07-21.md`。

### 已确认 Bug A（404，高置信）
`backend-gateway/src/routes/units.ts`：静态 `GET /api/units/factions`（约 204 行）定义在参数路由 `GET /api/units/:unitId`（约 89 行）**之后** → Express 路由顺序劫持，`/api/units/factions` 被当 `unitId='factions'` 处理 → 查库无果返回 `404 UNIT_NOT_FOUND`。服务器实测两条路径同落参数处理器已证实。修复：将静态路由移到参数路由前，或改用 `/api/units/meta/factions`。

### 400 分析（待确认触发参数）
`POST /api/combat/:battleId/deploy-unit`（combat.ts:547）校验 `!unit_id || q===undefined || r===undefined` → 400。注意 `String(unit.id)` 对 null/0/undefined 均非空串，故纯 id 缺失会走 404 而非 400；400 更可能由 q/r 未定义或 unit_id 为空串触发。网关不记录 400，用户战斗日志不在其中（仅 unit-inject-* 测试战斗成功）。需用户 Network 面板提供 400 请求的 URL+body，或我加临时日志抓取。

### 背景根因（潜在，非 400 元凶）
- `battleStore` 为网关内存态，每次 `docker compose build` 重建即清空所有战局（含 pendingUnits）。
- `NewBattleView.vue:2767` 兜底 `createBattle({ battlefield_id: 1 })` 硬编码 1，而 maps 表用 UUID → 易 404/空战局 → 部署池为空 → 无法部署。
- `setPendingUnits(battleId,{units})` 仅传 units，但后端 pending-units 只校验 Array.isArray(units)（combat.ts:179）→ 不触发 400。
