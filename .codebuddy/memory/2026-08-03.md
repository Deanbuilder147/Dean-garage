## 射程纯加法模型 + 删除中文解析（Phase 36-RangeAddModel，2026-08-03）
- 用户最终裁定（原话）：1) 读技能类型；2) 类型基准射程(近战=1/远程=3/自动化=0=自身)；3) 加词条中显式数值额外定义(可为0)→写入range。中文射程解析已无法完成目标，**删除**。词条射程搞不清时预留计算通路，之后用户在词条库侧规范化再接入。
- 删除内容：shared-kernel/前端/normalizer 三处 `/\d+/g` 中文抽数字逻辑（`"1~4格"→[1,4]` 等）；normalizer 的"类型护栏"(ranged<2→3 兜底)；一切"远程护栏"二次修正。
- 新模型（三端统一，加法）：`maxRange = DEFAULT_RANGE_BY_CATEGORY[cat] + parseExtra(词条显式数值)`。`parseExtra` 仅接受**纯数字 / 标准区间(a~b / a-b) / {max}**；字符串须 `^\s*(\d+)\s*(?:[-~]\s*(\d+))?\s*$` 全匹配，含中文/其它字符→返回 0（不计加成）。minRange：词条显式 min 数值→采用；否则按类型基准(近战/远程=1, auto=0)。
- normalizer.mapSkills：仅透传词条纯数字射程（中文/缺省→全部 undefined），不再写死类型基准。role：数据源只透传，真相源运行时加类型基准。
- 验证（加法模型真实数据）：mega `{type:"远程",range:"1~4格"}`→maxRange=**3**(中文不计→类型基准)；mega 数字`range:1`→4(3+1)；撕裂`range:"周围两圈"`→1；D-field`range:"/"`→0；远程无词条→3；近战无词条→1。
- ⚠️ 语义关键：词条数值=**额外加成**（非绝对值）。用户未来在词条库规范 mega 射程时，应填"额外值"（如想要4则填1=3+1），而非绝对值4（会算成3+4=7）。已向用户确认此加法语义。
- 部署：shared-kernel build→rsync→服务器 frontend build→重建 gateway/frontend→Healthy v29.0.0/8081=200。验收须重开新局。
- ★ 终态铁律：射程 = 类型基准(近战1/远程3/auto0) + 词条显式纯数字额外定义(可为0)；中文/混乱文本一律不计（extra=0），预留词条库规范化通路；严禁任何覆盖/护栏二次修正。

## 第三轮 bugfix：环数标注错误 + 画布居中（2026-08-03 晚，已部署）
用户反馈截图显示两个问题：
1. **环数标注全错**：中心(8,8)标0正确，但右上格标了"8"而非"1"。根因：HexCanvasEditor 的 `offToAx` 用了 **odd-r** 偏移公式 `(row - (row&1))/2`（减号），而 hexUtils 的 `hexDistance` 内部用 **even-r** 公式 `(r + (r&1))/2`（加号）。绘制用 `pointyTopCenter`(even-r) 但距离算 odd-r → 坐标系不统一。
