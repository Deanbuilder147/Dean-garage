### 三类反模式的系统性归因
- 中文Label/英文Key错位 ← 展示层字段与业务层字段**共用同一存储位**（effect 既当下拉展示又当业务标识）。
- 非对称读写白名单 ← **缺共享 schema**，前端 payload/后端解构/引擎转换三处各自维护字段列表，遗漏时编译期零报错（全弱类型）。
- 硬外键空缺+降级失效 ← 所有兜底分支（`default:` / `?? {}` / `|| 0`）设计为**静默返回空**而非报错，断链在生产完全不可观测。

根治建议：`shared-kernel/src/contracts/` 建 zod 实体 schema 三端共用；反查字典只允许存在于词条库本身（组件内 `EFFECT_TO_KEY_FALLBACK` 是过渡兜底，需排期删）；降级必须 warn 并写战报 `diagnostics[]`；CI 加「写入端字段集合 ⊇ 消费端读取字段集合」断言。

## HexCanvasEditor 六角格缝隙修复（2026-08-06，已上线 8081）

用户反馈射程预览网格列之间有可见缝隙。根因：`drawHex()` 用 `w=size, h=size*√3` 扁平近似 + `-90°` 起始角绘制六边形，与 `pointyTopCenter()` 的尖顶格间距公式（水平 `size*√3` / 垂直 `size*1.5`）存在微小偏差，加上 canvas 抗锯齿产生视觉缝隙。

### ⚠️ 重要修正：之前记录的「尖顶外接圆 + -30°」修复是错的
第一次改 `w=size*√3/2, h=size, -30°` 导致六边形**重叠**（因为旧 `drawHex` 本是扁平六边形 `w=size` 是 x 半径，水平直径 `2*size` 本就大于格间距，几何上重叠，原"缝"实为描边错觉）。回滚后用户要求"参考地图编辑器怎么画"。

### ✅ 正确终态（与地图编辑器一致）
- 地图编辑器 `HexGridCanvasEngine` 用的 `drawHexPath`（hexDraw.js）是**外接圆半径**画法：`ang=π/3*i-π/2`，顶点 `cx+R*cos(ang), cy+R*sin(ang)`，宽 `R*√3`、高 `2R`，与 `pointyTopCenter(size=R)` 间距**恰好相接**。
- HexCanvasEditor 的 `drawHex` 改为同公式：`ang=Math.PI/3*i-Math.PI/2`，半径 `r=size*k`（`k=(size*√3-1)/(size*√3)` 实现 1px 缩进），`const GAP_PX=1` 可调控缝隙。
- **绘制逻辑被 vite 打包进 index chunk（非 GlossaryHub chunk）**——验收时必须查 `index-*.js` 而非 GlossaryHub。minify 后 `GAP_PX`/`drawHex` 等标识符被混淆，验证用 `spacingH`/`Math.sqrt(3)` 特征串。
- 部署验证：线上 `index-JgkR6ac7.js` 含 `spacingH`、`Math.sqrt(3)`；容器重启后 curl 8081 一致。

## Phase 4A 实现：主动技能【条件词条效果级门控】（2026-08-06 已上线）

**目标**：主动释放带 `trigger.condition`（如 hp_below_pct）的词条时，条件不满足则逐 effect 跳过（不写 statusEffects_added / 不加额外伤害），但技能基础动作照常结算。

**改动文件**：
- `conditionEvaluator.cjs`：新增 `evaluateTriggerCondition(condition, {unit,target,nearestEnemyDist?})` + `_hexDist`，支持 `hp_below_pct`/`distance_less_than`/`distance_greater_than`；主体(subject)默认取被作用单位 `target`（无则 `unit`）。顶部引入 `hexDistance`。
- `skillExecutor.cjs`：
  1. 新增 `_effectTriggerMet(effect, uf, unit, target)`：取 `effect.trigger.condition`（优先）或 `uf.trigger.condition`（回退），无条件→放行，有条件→委托 `ConditionEvaluator.evaluateTriggerCondition`。
  2. **关键修复**：`_getUniversalFields` 此前**漏把 `effects` 归一化进 `uf`**（只拷了 `status_effects`），导致 `uf.effects` 恒为 `undefined`、攻击/AOE 的 `effects[]` 形同死代码。补 `effects: Array.isArray(cfg.effects)?cfg.effects:[]`。
  3. 攻击基础 `.find` 排除带 `trigger.condition` 的伤害 effect（避免被算进基础伤害）。
  4. 攻击结算新增"条件额外伤害"循环：仅对带 `trigger.condition` 的 damage effect 在条件满足时累加（公式 `round(flat + (mult>1?(mult-1)*base:0))`），基础伤害不受影响。
  5. buff/debuff `applies_on` 写 status 前加 `this._effectTriggerMet(null, uf, ...)` 门控（replace_all 两处相同块）。
  6. AOE 攻击 status 追加 `this._effectTriggerMet(e, uf, unit, tu)` 门控。
- 被动路径（combat.ts `evaluatePassives`）**保留其内联条件逻辑**不改动（避免 ESM 引入 ConditionEvaluator 风险）；主动路径统一调新的 `ConditionEvaluator.evaluateTriggerCondition`。

**语义约定（需用户知晓）**：主动技能 `trigger.condition.hp_below_pct` 判定**目标（被作用单位）**——契合"攻击X%血量目标"示例；被动仍判定自身（重构时传 `target=unit`）。

**验证**：新增 `mecha-universe-engine/scripts/verify-conditional-effects.cjs`（8/8 通过，本地+服务器均验）。技巧：测试固定 `_evaluateDice` 消除掷骰方差；目标单位需放在相邻格（否则 `isTargetInRange` 判超距 `out_of_range`）；攻击伤害断言用 `final_damage`（非 `damage`）并与"无效果参照攻击"比对以避开防御/体型减伤管线。
