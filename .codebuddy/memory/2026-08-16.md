## 白屏 Bug 修复：router.replace 路由前缀错误
- **根因**：NewBattleView.vue onMounted 中 getBattleState 404 兜底逻辑调用 `router.replace('/battle/' + newId)`，但 `/battle/:id` 路由**没有 component**（仅作重定向入口，由守卫分流到 `/battle-pc/:id` 或 `/battle-mobile/:id`）。replace 后 URL 停在 `/battle/UUID`，router-view 渲染为空 → **白屏**。
- **症状**：用户截图显示 `[socket] Cannot access 'Ae' before initialization`（实为 minified 变量 TDZ，是 socket.io-client 在错误时序下的次要报错）、getBattleState 404、factionLogo 全部加载失败、最终白屏。`<main>` 区域 DOM 为 `<!---->`（Vue 空注释节点）。
- **修复**：`router.replace('/battle/' + newId)` → `router.replace('/battle-pc/' + newId)`（一行改动）。
- **排查过程**：通过 agent-browser 无头浏览器复现 → 确认 setup/onMounted 均执行但模板渲染为空 → 注入 DOM 调试标记确认 onMounted 只触发一次 → 发现 router.replace 后 URL 为 `/battle/UUID` 而非 `/battle-pc/UUID` → 定位路由配置中 `/battle/:id` 无 component。
- **部署验证**：rsync → 服务器 npm run build → docker compose rebuild mecha-frontend → agent-browser 截图确认完整 UI 渲染（Canvas + 右侧栏 + 底部四区块 + 单位卡片），URL 正确为 `/battle-pc/c145d507-...`。

## 战场编辑器地形画笔颜色修改后地图不更新 Bug
- **症状**：在战场编辑器（/battlefield-edit）的「管理」弹窗中修改地形颜色并保存后，底部「当前画笔」和「地形笔刷」两栏显示新色正确，但画布上已有格子颜色不变；新刷格子也不变（用户反馈）。
- **根因分析**：
  - 渲染链路验证通过：`UNIVERSAL_TERRAIN_MAP[id].color` → `renderTerrainInline()` → `ctx2d.fillStyle` → Canvas 填色。通过强制注入 `#FF0000` 颜色确认画布能正确渲染红色格子。
  - `syncTerrainFromGlossary()` 能正确更新 `UNIVERSAL_TERRAIN_MAP[id].color`（控制台日志确认）。
  - **核心缺陷**：`saveTerrainConfig()` 保存成功后调了 `syncTerrainFromGlossary`（更新内存颜色表）和 `rebuildTerrainPalette`（更新 UI 调色板），但**没有调用 `hexGrid.invalidateTerrain()` 触发画布重绘**。导致已有格子保持旧颜色。
  - 数据流：UI input (v-model) → `editableTerrains[key].color` → `saveConfig` → `syncTerrainFromGlossary(editableTerrains)` → `UNIVERSAL_TERRAIN_MAP[id].color = 新值` ✓ → 但画布不重绘 ✗。
- **修复**：在 `saveTerrainConfig()` 的 `syncTerrainFromGlossary(editableTerrains)` 之后、`rebuildTerrainPalette()` 之后新增 `if (hexGrid.value) hexGrid.value.invalidateTerrain()`。
- **文件**：`frontend/src/views/NewBattlefieldView.vue` 第 445 行附近。
- **部署**：rsync → 服务器 npm run build → docker compose rebuild mecha-frontend → 已上线。
