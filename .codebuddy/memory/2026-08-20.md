# 2026-08-20

## 修复 PC 端战场黑屏

问题：用户从准备房开战或访问旧 `/battle/:id` 入口后，PC 端右侧主内容区全黑，Console 报 `Cannot access 'Ie' before initialization` 与 WebSocket 连接失败。

根因：
1. 准备房 `NewPreparationRoom.vue` 写死跳转 `/battle/:id`，该兼容入口依赖导航守卫 `redirectByDevice` 重定向到 `/battle-pc/:id`；守卫偶发不生效或 meta 解析问题导致空白。
2. `NewBattleView.vue` 中存在 `const myFaction = myFaction.value || 'earth'`，minified 后变成 `const Ie=Ie.value||"earth"`，触发 Temporal Dead Zone 报错，使 `connectBattleSocket` 抛错并回退轮询，间接影响初始化。
3. `NewBattleView` 兜底 `createBattle` 后 `router.replace('/battle/' + newId)` 会跳回旧兼容入口，形成二次黑屏风险。

修复（已部署 8081）：
- `NewPreparationRoom.vue`：开战时直接按 `detectDevice()` 跳 `/battle-pc/:id` 或 `/battle-mobile/:id`，不再经过 `/battle/:id`。
- `main.js`：给 `/battle/:id` 加 `BattleEntryRedirect` 组件兜底，组件内 `onBeforeMount` 主动 `router.replace` 到设备专属路由，双保险。
- `NewBattleView.vue`：变量重命名为 `myFactionValue` 消除 TDZ；兜底 replace 改为设备专属路由。
- 服务器 `npm run build` 通过，镜像重建 `mecha-frontend`，bundle 更新为 `index-Bslkjqmg.js`。

验证：agent-browser 真实 Chromium 登录后访问 `/battle/:id`，URL 正确变为 `/battle-pc/:id`，战场渲染正常（工具栏、Canvas、部署模式均显示），Console 无 TDZ 报错与 WebSocket 帧头报错。
