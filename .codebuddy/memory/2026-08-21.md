# 2026-08-21 工作日志

## 地图编辑器「新增地形刷新后丢失」诊断与修复
- 现象：用户在地图编辑器（NewBattlefieldView.vue，侧边栏「地图编辑器」→/battlefield-edit）涂刷/新增地形，保存后刷新页面地形消失。
- 后端链路核查（正确）：`PUT /api/map/battlefields/:id`（backend-gateway/src/routes/maps.ts）确实调用 `persistChanges()`（落盘 sql.js 磁盘文件）+ GET `/:id` 无 auth 返回 `cells:[{q,r,terrain}]`。服务器实测数据正常，无「表名/路径不匹配」回归（2026-07-30 旧 bug 已修复）。
- 根因锁定在前端 `saveMap`（frontend/src/views/NewBattlefieldView.vue）：
  1. **res 未声明（必现）**：`await mapAPI.updateBattlefield(...)` 没赋值给 res，但下方 `(res && res.data && ...)` 访问未声明变量 → ReferenceError → 被 catch → 每次保存都误显「保存失败!」，掩盖真实结果。
  2. **新建地图 id=null 直接 PUT 404（场景必现）**：`createNewMap` 把 `battlefield.value.id` 设 null，但 saveMap 不判断 id 是否为空就 `updateBattlefield(null,...)` → PUT `/api/map/battlefields/null` → 404 → 保存失败 → 地形丢失。这最吻合用户「新增地形刷新后没有了」（新建地图场景）。
- 修复（已部署 8081，bundle index-Br65bXlz.js）：saveMap 改为「有 id 则 update，无 id 则先 create 拿 id 再回填」；修复 res 声明；catch 打印真实错误；新增保存后回读 GET 校验（本地格子数 vs 后端 cells 数不一致时告警），杜绝「显示保存成功但刷新即丢」的盲点。
- 部署：rsync frontend → 服务器 npm run build → docker compose build --no-cache mecha-frontend → up。验证 index.html 哈希 == 容器内 /usr/share/nginx/html/assets/index-Br65bXlz.js，且产物含 createBattlefield/保存落库校验。
- 关联历史：2026-06-22 曾发生 terrainMap 未声明导致地形丢失（Python 补丁注入失败），现已修复（terrainMap 在 NewBattlefieldView.vue 第238行正确声明）。本次是不同根因的新 bug。
