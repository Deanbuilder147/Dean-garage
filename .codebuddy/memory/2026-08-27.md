## dominator 地图视图设置：改为服务端跨设备共享
- 原实现用 localStorage（仅本机），用户要求"跨设备共享"。
- 方案：存后端网关 SQLite 的 `kv` 表，key=`mapViewSettings.default`，所有 dominator 共享一份全局默认（符合用户"不因账号/战场改变"）。
- 后端改动：
  - `backend-gateway/src/db/sqlite.ts`：migrateTables 增加 `kv (key TEXT PRIMARY KEY, value TEXT)` 表。
  - `backend-gateway/src/routes/admin.ts`：新增 `GET/PUT /api/admin/map-view-settings`，用 `requireRole(UserRole.DOMINATOR)` 保护；sanitize 校验字段（terrainOpacity/terrainOverrideColor/gridLineOpacity/unitOpacity/showCoords/spacingHScale/spacingVScale）。
- 前端改动：
  - `frontend/src/api/client.js`：adminAPI 加 `getMapViewSettings` / `updateMapViewSettings`。
  - `frontend/src/views/NewBattleView.vue`：onMounted 调 `syncMapViewSettingsFromServer()`（dominator 拉取服务端覆盖本地）；保存时 `saveMapViewSettings()` 同时写 localStorage 兜底 + PUT 服务端。
  - `frontend/src/components/MapViewSettingsPanel.vue`：dominator 专属面板组件（本机创建，需一并部署）。
- 验证：`npm run build --workspace=backend-gateway` tsc 通过；前端 lint 0 错误。

- 运行方式：Docker Compose（项目根 docker-compose.yml）。容器：mecha-gateway(3006) / mecha-comm(3005) / mecha-frontend(8081→80) / mecha-battle-db(postgres, 持久化)。网关 DB 持久化卷 `gateway_data`。
- 部署流程（已实测成功）：
  1. 本地改文件 → scp 到服务器对应路径（注意保留子目录，如 `backend-gateway/src/routes/`、`frontend/src/components/`）。
  2. 服务器 `cd /root/mecha-universe-engine/frontend && npm run build`（重新生成 dist，含 check:mirror 校验）。
  3. `cd /root/mecha-universe-engine && docker compose up -d --no-deps --build mecha-gateway mecha-frontend`。
  4. 加 `--no-deps` 避免 compose 误重建已在跑的 mecha-battle-db（否则容器名冲突）。
- 教训：scp 多文件到目录时务必写全目标子路径，否则文件错放到父目录（曾把 admin.ts 错放到 src/ 下）。前端 Dockerfile 仅 `COPY dist`，必须先服务器端 `npm run build` 再 build 镜像，否则用旧 dist。
- 验证接口：网关 `/health` 存活；`GET /api/admin/map-view-settings` 未带 token 返回 401 AUTH_TOKEN_MISSING（证明路由挂载+鉴权生效）。
