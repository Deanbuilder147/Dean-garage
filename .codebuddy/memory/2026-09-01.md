## 战场部署过场组件 BattlefieldDeploy 封装完成
- 新增 `mecha-universe-engine/frontend/src/components/BattlefieldDeploy.vue`（全屏覆盖层过场）。
- 关键：坐标**直接 import 项目的 `pointyTopCenter(q,r,HEX_RADIUS=36,...)` + `HEX_RADIUS`**，复刻 `HexGridCanvasEngine.hexToPixel`（含 offsetFactor），与底层 Canvas 战场**像素级重合**；不重抄公式（避免奇偶错位）。
- 颜色**直接读 `TERRAIN_COLORS[id].color`**（来自 `@/utils/hexUtils.js`，运行时会被 `syncTerrainFromGlossary` 动态改写），每格显示其真实地形色，自动响应 glossary 改色，零硬编码。

- 用法：`<BattlefieldDeploy v-if="deploying" :grid-data="gridData" @done="deploying=false" />`，props spacingH/spacingV/offsetFactor 须与引擎一致（默认 1/1/0）。
- 之前独立 demo 在 `anime-demo/battlefield-deploy.html`（http://localhost:8126/battlefield-deploy.html），已是偶数行错位、与引擎一致，演示成立。

## ⚠️ 方案修正：部署过场改为画在引擎 Canvas 上（非 DOM 覆盖层）
- 真实战场 `HexGridCanvasEngine` 默认 **iso 模式**（NewBattleView 未传 mode，默认 'iso' 且传 `:iso-config`）。DOM 覆盖层无法与 iso 挤压+镜头(`focusCentralGrid(10)`)对齐，揭幕会跳变。
- 引擎在调用 `drawFn` 前已把完整 CTM（viewport scale+translate + ISO shear）应用到 ctx（`HexGridCanvasEngine.vue` draw() line 802 setTransform + line 831 叠 ISO）。因此 **在 drawFn 里用平面坐标调 `drawHexPath` 画正六边形，即与地形 iso 六边形像素级重合**，且天然规避 dpr/画布偏移/初始镜头问题。
- 删除 DOM 版 `BattlefieldDeploy.vue`，改为可复用 composable **`frontend/src/battle/useBattleDeploy.js`**：
  - `deployLayout` computed：从 `gridData.cells` 算每格平面目标坐标(复刻 hexToPixel: pointyTopCenter + offsetFactor) + `TERRAIN_COLORS[id].color` + 按到中心距离算飞入延迟 + 整图中心。
  - `drawDeploy(ctx)`：暗幕(from #050a12 压暗淡出) + 每格从中心 smoothstep 飞入、填地形色、蓝色描边；ctx 已带 ISO → 自动 iso。
  - `startDeploy/finishDeploy/replayDeploy` 用 rAF 驱动 `hexGrid.redraw()`；`resolveEngine()` 兼容「脚本传 ref / 模板传解包实例」两种传参。
  - `bindAutoStart(hexGrid)`：watch gridData.cells>0 自动播放一次。
- 接入点：
  - `NewBattleView.vue`：import + `useBattleDeploy(gridData)`（别名避免与既有单位上场 `deploying` 冲突，用 `deployAnimOn` 等）；`safeDrawBattleScene` 顶部 `if(deployAnimOn.value){drawDeployAnim(ctx);return}`；模板加部署控制条(↺重新部署/透视检查/开始战斗)；`bindDeployAutoStart(hexGrid)`。
  - `MobileBattleView.vue`：同上；补 `const hexGrid = ref(null)`（原仅模板 `ref="hexGrid"` 未声明）；`drawBattleScene` 顶部分支。
- **已部署 8081 验证**：服务器 `npm run build`(219 模块无错) → `docker compose build --no-cache mecha-frontend` + `up -d --no-deps` → 容器 Started；curl 8081 资产 `index-DZ8PRFrn.js` 含「开始战斗（揭开战场）」确认上线。**视觉像素级重合需用户在浏览器确认**（无法在本环境截图）。
- 关键坑：模板里 `hexGrid` 会被 Vue 自动解包为引擎实例，故 composable 必须兼容 ref 与实例两种传参（已用 resolveEngine 处理）。

## 进场镜头 + 部署可见性再修（用户反馈「进场要缩放」「部署一闪而过」）
- 根因：引擎进场默认 `focusCentralGrid(10)`（只适配中心 10×10），且「尺寸自愈」会在容器稳定时再重置回 10×10。大地图进场只看到中心一小块。
- 修复：引擎新增可选 prop `fitAllOnMount`（默认 false，保编辑器原行为）；置 true 时 `initCanvas`、尺寸自愈 rAF、redraw 尺寸分支、onMounted 一并改为 `focusCentralGrid(9999)`（适配整张非 void 地图）。`NewBattleView`/`MobileBattleView` 的 `<HexGridCanvasEngine>` 加 `:fit-all-on-mount="true"` → 进场即见完整战场。
- 部署「一闪而过」根因：fit-all 后整图偏小、组装过程仅 ~1.27s 且暗幕偏重，观感像闪。已：① 拉长 `DEPLOY_DUR 650→1000 / MAX_DELAY 500→800 / TAIL 80→300`（总 ~2.1s）；② 暗幕 0.82→0.78 偏弱，地形/六边形更可见；③ `NewBattleView` 部署期间顶部加 DOM 标题条「⚙ 战场部署中 · 单位就位」+ 2.1s 进度条（canvas 动画弱时一眼可见）。底边控制条已有 ↺重新部署/透视检查/开始战斗。
- 侧边栏体验：用户要求进场 canvas 更大 → `NewBattleView` 的 `rightSidebarCollapsed` 与 `lowerZoneCollapsed` 默认 `false→true`（右侧栏 + 底边栏默认收起，露出更多地图空间）。
- 已部署 8081 验证：bundle `index-Drm2VTPu.js` 含 `战场部署中`/`fitAllOnMount`/`deployProgressBar`。
