## 一、Excel 解析器旧版兼容改造 (v2.0 → v2.1)

### 问题描述
新版 `backend-gateway` 的 Excel 解析器使用**自定义坐标体系**（v2.0），与旧版 `hangar-service` 的 `/import-excel` 直导模式**坐标完全不同**。用同一份设定器 Excel 文件上传时：
- 基本信息（机体番号、行动代号、阵营）读不到正确值
- 单位属性行偏移 3 行（新版从第7行读，旧版实际数据在第4行）
- 技能列表起始行和分配逻辑不匹配

### 影响范围

## 二、数据库迁移崩溃 Bug

### 问题描述
服务启动时执行 SQLite 表结构迁移，报错：
```
duplicate column name: is_public
```
导致整个进程崩溃退出，容器进入重启循环。

### 根因分析
1. sql.js (SQLite WASM 版) 的 `PRAGMA table_info()` 对**已持久化的 .db 文件**返回的列列表可能不准确
2. 代码先检查 `!unitColNames.includes('is_public')` → 返回 false（以为不存在）
3. 执行 `ALTER TABLE ADD COLUMN is_public` → 实际列已存在 → **sql.js 直接崩溃抛出**
4. 内层 try-catch **未能捕获**（可能 sql.js 的错误是非标准 Error 对象）

### 修复方法

#### 方法 A: DDL 补全 (对新库)
在 `CREATE TABLE units` 的 DDL 中直接包含 `is_public` 和 `review_status` 列：
```sql
is_public INTEGER DEFAULT 0,
review_status TEXT DEFAULT 'pending',
```
这样全新数据库不会触发 ALTER TABLE。

#### 方法 B: 顶层 try-catch (对存量库)
将整个 `_migrateExistingTablesInner()` 用外层 try-catch 包裹：
```typescript
function migrateExistingTables(): void {
  try {
    _migrateExistingTablesInner();
  } catch (e: any) {
    const msg = e?.message || String(e);
    if (msg.includes('duplicate column') || msg.includes('already exists')) {
      console.log(`[DB] 迁移信息（已存在，跳过）: ${msg}`);
      return; // 安全忽略
    }
    throw e; // 其他错误继续抛出
  }
}
```

### 附加发现
Docker build 使用了**缓存层**，导致修改后的 `.ts` 源码没有反映到镜像中的 `.js` 编译产物。
**解决**: 必须加 `--no-cache` 参数重新构建。

## 三、登录接口 502 Bad Gateway

### 问题描述
前端登录请求：
```
POST http://106.54.197.69:8081/api/auth/login
→ 502 Bad Gateway (nginx/1.31.2)
```

### 根因分析
Docker 网络隔离：

| 容器 | Docker 网络 | IP 地址 |
|------|------------|---------|
| `mecha-frontend` (nginx) | **mecha-universe-engine_mecha-net** | 172.18.0.5 |
| `mecha-gateway` | **bridge** (默认) | 172.17.0.2 |

前端 nginx 配置代理规则：
```nginx
location /api/auth/ {
    proxy_pass http://mecha-gateway:3006;  # ← DNS 解析失败！不在同一网络
}
```
两个容器在不同网络中，`mecha-gateway` 这个主机名在前端容器的网络里无法解析。

### 修复方法
```bash
docker network connect mecha-universe-engine_mecha-net mecha-gateway
```
将 gateway 容器加入前端的 Docker 网络，使其互相可达。

**修复后验证**:
```
PING mecha-gateway (172.18.0.4): 64 bytes, time=0.096ms  ✅
POST /api/auth/login → {"error":"AUTH_CREDENTIALS_INVALID"}  ✅ (正常业务响应)
```

### ⚠️ 注意事项
此修复是**临时性**的 — 如果 `mecha-gateway` 容器被重建（如再次 docker run），网络连接会丢失。

**永久解决方案**（二选一）：
1. 启动时指定网络：`docker run --network mecha-universe-engine_mecha-net ...`
2. 将 gateway 纳入 `docker-compose.yml` 统一管理
