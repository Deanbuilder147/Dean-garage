# 六段式画布 UI 规范（统一编辑器）

> 适用对象：词条编辑器设计者、前端/后端开发者
> 目的：定义取代「词条框 + 六段编排画布 + 原子面板」三件套的**统一可视化编辑器**的交互、布局与数据模型。
> 关联文档：
> - `docs/六段式编辑器与分段模型解释.md`（分段/子段语义、WHO 响应者语义、落库结构）
> - `mecha-universe-engine/services/combat-service/src/services/combatCore/atomRegistry.cjs`（语义原子 → 引擎 handler 翻译）

---

## 〇、设计总纲

原三件套：

| 旧组件 | 问题 |
|--------|------|
| 词条库里的词条框 | 只展示、不能编，与编排画布割裂 |
| 六段编排画布 | 段格空、要点进去另开原子面板 |
| 原子面板 | 独立悬浮，离段格上下文远，易填错段 |

新画布**三合一**：

```
六边形词条栏（列表）
   └─ 点击 ─→ 单词条展示（六段式全貌）
                 └─ 点击某段格 ─→ 段格展开（原子以「下拉菜单 + 参数表单」就地添加）
```

**原子画板不再独立存在**：折叠进每个段格，作为该格的下拉选项。点段格 → 下拉选原子类型 → 出现参数表单 → 填值即落库。

## 一、三层界面流程

### 第一层：六边形词条栏（类词条布局）

- 所有词条以**六边形花卡片**网格排列（沿用现有词条视觉）。
- 每张卡片只显示：词条名 + 关键标签（如「攻击 / 射击 / d6」）。
- 不展开任何六段细节。
- 图例色：卡片本体 = 词条占位（深红/灰表空占位或已选中）。

### 第二层：单词条展示

- 点击第一层某卡片 → 进入单词条详情视图。
- 形态：中心技能名（如「扫射」）+ 围绕中心的**六大段格**辐射布局：
  `时机 / 代价 / 条件 / 随机性 / 执行 / 后效`
- 每个段格是一个六边形，内部可显示已填原子的**缩略标签**（如代价段显示「AP -1」而非仅「资源消耗」）。
- 空段格以**深红/灰色**显示，提示"可填"。

### 第三层：段格展开逻辑

- 在第二层点击任意段格 → 按段格类型展开为原子编辑区。
- **原子以「下拉菜单 + 参数表单」就地添加**，不再弹出独立面板。
- 展开层级按段格类型分三种视觉形态（见第二章）。

## 二、六段定义（统一命名）

> 注：本规范采用新段名，对应引擎 `phase` key 与旧文档语义如下：
> 时机=WHEN、条件=IF、执行=DO、随机性=ROLL（分叉触发器）、后效=**AFTER**、代价=COST。
> - **AFTER（后效）已于 2026-08-23 落地引擎**（`skillExecutor._walkPhaseTree` 的 `ORDER` 加入 `'AFTER'`，
>   位于 DO 之后、COST 之前；ROLL 取代式 `rollBranchHas` 同步含 AFTER）。落库 `phase` 用 `"AFTER"`。
> - 旧文档无独立"后效"主段（其语义散落在 COST/结算后回调）；本规范将"后效"提升为独立主段。
> - 旧文档 WHO（作用对象）并入「执行」段的目标解析，不单列主段（引擎 ORDER 仍保留 WHO 位，缺段自动跳过）。

| 段 | 含义 | 是否必填 | 段格颜色 |
|----|------|----------|----------|
| **时机** | 触发时机/事件（如"声明行动""回合开始"） | 必填 | 黑色主段 |
| **代价** | 发动者付出的代价（AP/能量/耐久/充能） | 可选 | 黑色主段 |
| **条件** | 发动前附加判定（射程/地形/充能层数/敌我） | 可选 | 黑色主段 |
| **随机性** | 掷骰分叉触发器；普通情况一段，配置多区间即裂变分段 | 可选 | 青色（裂变母线） |
| **执行** | 本次发动**即时**结算的效果：立即伤害/治疗/位移/控制 + 目标解析 | 必填 | 黑色主段 |
| **后效** | 伤害/效果**结算之后**，基于本次结果**延续到未来时间**的效果（持续 buff/debuff、基于结果的链式触发、清理回收） | 可选 | 黑色主段 |

**执行 vs 后效（核心区分）**：
- 执行段 = 本次发动**当下立即**结算（立即扣血、立即击退、立即上控制）
- 后效段 = 结算**完成之后**才生效、且**作用延伸到未来回合**（持续状态、击杀叠层、结算后清状态）
- 例：「立即造成 10 伤害」→ 执行；「受击者接下来 3 回合机动 -5」→ 后效；「击杀后自身叠 1 层充能」→ 后效

**后效段独立地位（用户确认 2026-08-23）**：
- 后效（AFTER）是六段之一，拥有独立主段格（黑色，与时机/代价/条件/执行同级）。
- 它**不是**代价段的附属，也不是执行段的内嵌；是主链上"执行结算完毕"之后的独立延伸点。

**「延时」界限判据（用户裁定）**：
> **只要且只有该效果不是在本次调用触发生效的回合，都算「延时」，归 AFTER。**
- 只看"生效回合是否等于本次调用回合"，不依赖 duration 长短、不依赖是否持续、不依赖是否事件钩子。一刀切，无歧义。
- 例：立即造成 10 伤害（本次回合生效）→ DO；受击者机动 -5 持续 3 回合（未来 tick）→ AFTER；
  击杀后自身叠 1 层充能（结算结果之后）→ AFTER；下回合开始获护盾（单次未来事件）→ AFTER；
  均摊 15 伤/3 回合（未来 tick）→ AFTER。

**AFTER 效果模型（三元）**：
- 效果 = `(时效, 位, 值)` 三元组。
  - 时效：作用延续的回合/时机（`duration` / `expiry_phase`）
  - 位：作用对象（self / enemy / ally / aoe 范围内）
  - 值：特定数值的改动量（含 `stat` 说明作用在哪个数值上）
- **增减由「值」的符号判定**：`值 > 0` 增益，`值 < 0` 减益。`增减`不再作为独立维度（避免与值符号矛盾）。
- **原子护栏（强制）**：AFTER 段所有原子的 `value` 必须带符号；禁止用 `type` 字段另表增减
  （如 `{type:'debuff', value:5}` 此类矛盾写法前端须拦截）。
- **派生原子族（待规划）**：均摊型 `{total, split:'equal', rounds:n}` → 展开为每回合 `total/rounds`、持续 `rounds` 回合的 status。

**执行 vs 后效（一句话）**：
- 执行(DO) = 本次调用回合即时结算；后效(AFTER) = 生效回合 ≠ 本次调用回合。两者以"生效回合"一刀分。

**主链顺序（前端不可乱序）**：
```
时机(WHEN) → 条件(IF) → 随机性(ROLL) → 执行(DO) → 后效 → 代价(COST)
```
> 说明：代价段放末尾，因为它在发动后才结算（与执行后的 AP 池扣减叠加，详见第六章）。

## 三、段格展开逻辑（三种形态）

### 形态 A：普通段格（时机/代价/条件/执行/后效）

- 黑/青中心六边形 + 周围 6 个空位。
- 点击中心 → 展开为**原子下拉菜单**：列出该段合法原子类型。
- 选一个原子 → 该原子以黄色小六边形落入段格，并展开**参数表单**（字段来自 atomRegistry 的 `params` schema）。
- 可叠加多个原子（形成段内原子序列）。

### 形态 B：随机性段（裂变触发器）

- 青色中心六边形（骰子图标）+ 周围 6 个空位。
- 点击中心 → 先弹出**「分段配置」**：设定掷骰面数（默认 d6）+ n 个区间。
- 每个区间生成**一个分段入口卡片**（一级大节点，橙框，见第四章）。
- 分段内部不再展开主六段，而是直接挂原子（按用户约定：随机性子段只填效果，不套六段）。

### 形态 C：已填原子的段格编辑态

- 黑色/青色中心 + 周围一圈黄色小六边形（每个 = 一个已填原子）。
- 点击某黄色小六边形 → 展开该原子的参数表单可改。
- 拖拽/删除按钮在黄色六边形角标。

**颜色图例（固定）**：
| 颜色 | 含义 |
|------|------|
| 红色 | 介绍/说明段落 |
| 黑色 | 主段（时机/代价/条件/执行/后效） |
| 青色 | 随机性段（裂变母线） |
| 黄色 | 原子输入 |
| 深红 | 空段格（可填占位） |
| 灰色 | 被选中段格 |
| 橙色 | 一级分段（挂在主链随机性下） |
| 蓝色 | 二级子段（挂在某分段随机性下） |

## 四、分段与子段（核心区分）

### 4.1 随机性段 = 分叉触发器

当随机性段配置了多个掷骰区间时，主链在该处裂变为 n 个**分段**，每个分段由"掷出某区间"触发。

```
主链: 时机 → 条件 → ●随机性(分叉)
                         ╲ 橙色裂变母线
        ┌──────────────┼──────────────┐
     [分段①]         [分段②]         [分段③]
     掷1~3           掷4~6           掷7~9
     直接挂原子        直接挂原子        直接挂原子
```

> **用户约定（来自「扫射」确认）**：随机性段内的子段**只填效果原子，不再做六段式划分**。
> 即分段/子段内部直接是原子列表，不出现"分段内的时机/代价/条件…"。

### 4.2 分段（一级）

- 挂在**主链随机性**下。
- 视觉：一级大节点，与主段等大，**橙框**，标题显式写掷骰区间（如「分段① 掷1~3」）。
- 标题区间从主段随机性配置**自动带出展示，不重复输入**。

### 4.3 子段（二级）

- 挂在**某分段的随机性**下（分段内再次分叉）。
- 视觉：嵌套在该分段框内，小一号，**蓝框**，标题前缀「子段A」。

### 4.4 区分判据（唯一可靠）

| 层级 | 父裂变节点 | 视觉量级 | 框色 | 标题前缀 |
|------|-----------|----------|------|----------|
| 主段 | — | 一级大节点 | 黑/青 | 时机/代价/条件/随机性/执行/后效 |
| 分段 | 主链随机性 | 一级大节点（与主段等大） | **橙** | `分段①` |
| 子段 | 某分段随机性 | 二级嵌套（小一号） | **蓝** | `子段A` |

**不靠内容区分**（分段/子段内部都是原子列表），只靠层级位置 + 框色 + 前缀。

## 五、原子下拉菜单（折叠进段格）

### 5.1 数据来源

下拉菜单的选项 = `atomRegistry.listMeta()` 输出的语义原子清单
（`{ semantic, handlerKey, kind, params:[{name,type,required,guard,desc}], guard, desc }`）。

前端**直接消费此清单派生 dropdown 与参数表单**，不二次硬编码原子类型。

### 5.2 按段过滤原子

每个段格展开下拉时，只展示该段合法原子（前端可按 `kind`/段类型做白名单）：

| 段 | 建议可用原子族（示例） |
|----|------------------------|
| 时机 | trigger / 时机类 marker |
| 代价 | resource(ap/energy/durability) 消耗类 |
| 条件 | predicate / 射程·地形·充能判定 |
| 执行 | D 组伤害族、status/buff、displace、aoe、map_cannon |
| 后效 | 持续 status、chain、cleanup |
| 随机性分段 | 任意执行类原子（子段只填效果） |

### 5.3 参数表单

- 选中原子 → 按 `params` schema 渲染表单字段（number/enum/string）。
- 字段带 `guard`（护栏，如 D6 护甲穿透 ≤0.8）前端做越界警示。
- 必填字段标 `*`，缺填不可保存。

### 5.4 原子输入触发流程

```
点空段格（深红）
  → 下拉菜单出现（黄色原子候选）
  → 选原子类型
  → 参数表单展开（按 schema）
  → 填值 → 黄色小六边形落入段格 → 落库
```

## 六、AP 叠加规则（画布提示）

代价段扣 AP 与"发动基础消耗"叠加（同池 `actionPoints`，回合回满制）：

- 基础发动（攻击类）= 1 AP
- 代价段写 `ap:-1` → 实际耗 1+1=2 AP
- **前端越界警示**：若 `代价段 AP 总和 + 基础 1 > maxActionPoints(默认3)`，
  该段格标红警告"本回合将清空/超额，技能可能无法发动"。

代价段若 `target` 指向敌人（让他 -AP），本质是 debuff，应放**执行段**而非代价段。

## 6.5 各段原子规划（占位 · 待用户二次规划）

> ⏸ **状态：待指挥**。本节为六段对应的原子族与输入字段预留框架，具体原子清单、参数 schema、
> 段-原子白名单由用户二次规划后填充。当前仅列**占位结构与约束**，不锁定具体内容。

### 约束原则
1. 每个主段（时机/条件/随机性/执行/后效/代价）在画布下拉菜单中应有**独立原子白名单**。
2. 原子定义唯一来源 = `atomRegistry.listMeta()`，本表只做"段 → 原子族"映射，不重定义原子。
3. 每个原子须声明：语义名 / 参数表（字段名·类型·必填·护栏）/ 可填段位。
4. 子段（随机性裂变内）不展开六段，原子平铺，靠 `duration>0` 自动归后效语义。

### 占位框架

| 段 | 规划中的原子族（占位） | 输入字段基调 | 是否必填 |
|----|------------------------|--------------|----------|
| 时机 WHEN | _[待规划]_ | 触发事件枚举 / 时机点 | 必填 |
| 条件 IF | _[待规划]_ | 判定谓词 + 阈值 | 可选 |
| 随机性 ROLL | _[待规划]_ | 骰子面数 / 区间划分 | 可选 |
| 执行 DO | _[待规划]_ | 伤害/位移/控制 + 目标解析 | 必填 |
| 后效 AFTER | _[待规划]_ | 持续状态/链式/清理 + 延续回合 | 可选 |
| 代价 COST | _[待规划]_ | 资源类型 + 数值（发动者自付） | 可选 |

### 待二次规划时需明确
- [ ] 每段的原子族完整清单（语义名 + handlerKey）
- [ ] 每个原子的参数 schema（含 `guard` 护栏值）
- [ ] 段-原子白名单的最终归属（哪些原子可跨段、哪些段专属）
- [ ] 随机性分段内原子是否允许出现"后效语义原子"的显式标注还是纯靠 `duration`
- [ ] 子段内是否需要 `phase_hint` 字段（见前文边界讨论）

## 6.6 原子分类总表（候选清单 · 待确认）

> 下表按六段（WHEN/IF/ROLL/DO/AFTER/COST）列出**各段可能涉及的原子候选**，
> 格式：`段头：触发时机 WHEN ｜ 原子名称：「回合开始」｜ 原子分类：「时机」`。
> 原子名称取自语义命名习惯，handlerKey 待与 `atomRegistry` 对齐后补全。
> **本表为规划草稿，具体原子去留 / 参数 / 跨段许可由用户二次规划裁定。**

**展现形式（通用规则，贯穿全画布）**：每个原子的画布控件类型由 `展现形式` 字段决定，三选一：
- **下拉菜单**：从枚举选项中单选其一（如维度①「主动/被动」、各段原子类型选择）。
- **勾选菜单**：可多选的复选框清单（如时机锚点多选、伤害类型多选）。
- **手动输入**：自由填值（如数值、文本、自定义区间），受 atomRegistry 的 `guard` 护栏校验。
> 时机锚点（含「全部时机」）统一为「勾选菜单」；维度①「主动/被动」为二值单选，控件用「下拉菜单」。

**勾选菜单的「OR / AND」切换（用户确认 2026-08-23）**：
> 凡「勾选菜单」类原子（含 WHEN 时机锚点、IF 多条件勾选等），需额外提供一个 **「OR」勾选框**：
> - **未勾 OR（默认 AND）**：所勾多项须**同时满足**才触发（取交集）。
> - **勾选 OR**：所勾多项中**任一符合即触发**（取并集）。
> 落库在勾选原子上带 `match:'AND' | 'OR'` 字段，引擎按此判定多选条件的逻辑关系。

**原子分类：主分类 + 修饰分类（用户确认 2026-08-23）**：
> 原子分类不止"挂在哪段"。部分原子专门用来**修饰 / 具体化**其它原子（如作用域、数值、范围），
> 它们跨段复用、不成独立效果。故将原子分类分为两层：

- **主分类（相位归属）**：时机 / 条件 / 随机性 / 执行 / 后效 / 代价。
  原子挂在哪一段（相位），决定结算时机。六段表里的「原子分类」列即指主分类。
- **修饰分类（横切、修饰 / 具体化）**：用来修饰主原子的**参数构造块**，可跨段复用，
  便于后端统一修正、前端统一展示。

**修饰分类清单（已确认，共 9 + 7 = 16 项）**：

| 修饰分类 | 用途 | 取值枚举（草稿） | 状态 |
|----------|------|------------------|------|
| **作用域** | 生效对象归属 | 我方 / 敌方 / 我方全体 / 敌方全体 / 全体 / **自身**（用户确认 2026-08-23：补「自身」区间） | 用户确认 |

### 【DO 执行】（即时结算）

**动作原子分层模型（用户确认 2026-08-23，修订于本轮）**：
> 不要把"动作"全做成平铺主原子。按"是否作用于数值"分两层：
> - **A 类 · 数值动作**：伤害/治疗/护盾/加减属性/数值型状态——**取消独立主原子**，用修饰组合表达：
>   `数值域(HP/机动/AP/护甲…) + 流转方式(消耗/产出/转移/移除) + 数值运算(固定/倍率/百分比) + 带符号值`。
>   增减**完全靠 `值` 的符号**（`值>0`=增益/产出，`值<0`=减益/消耗），与 AFTER 三元模型一致，不另设"伤害/治疗"谓词。
>   - 例：敌方全体 HP `-15` 固定值 = 直接伤害；自身 HP `+10` = 治疗；自身 HP `+8` 带"本次帧时效"= 护盾。
>   - **非数值状态枚举化（用户裁定 2026-08-23）**：眩晕/沉默 = `数值域:AP, 值:-n`（AP 耗尽即无法行动/释放）；定身 = `数值域:机动, 值:-999`（移动力归零）；
>     二者均归 A 类修饰组合，**无需"施加状态"主原子**。仅「标记」类纯标签状态需引用一个**状态词条**（见下方「词条」原子）。
> - **B 类 · 非数值谓词**：位移/召唤/词条联动/目标解析/事件钩子——这些是修饰**无法描述**的动作（改变坐标/场实体/规则链而非数值），
>   **保留为少量主原子（数量收敛至个位数）**，靠后续修饰补全。

| 延时效果 AFTER | 「事件钩子·击杀叠层」 | 后效 | 手动输入 | **B 类事件钩子**：击杀后自身叠 N 层充能（层数数值，触发条件非数值谓词） |
| 延时效果 AFTER | 「事件钩子·命中回调」 | 后效 | 下拉菜单 | **B 类事件钩子**：命中后触发某「词条」效果（枚举效果） |
| 延时效果 AFTER | 「结算清理」 | 后效 | 下拉菜单 | **B 类主原子**：结算后清除某状态/回收资源（枚举，引用状态词条 key） |

> A 类数值延时示例（取代原「持续增益/减益/未来护盾」三行）：
> ```json
> { "type": "apply_value", "modifiers": [
>     {"category":"作用域","value":"敌方"}, {"category":"数值域","value":"机动"},
>     {"category":"流转方式","value":"消耗"}, {"category":"数值运算","value":"固定值"},
>     {"value":-5}, {"category":"时效","value":"回合"}, {"duration":3}
> ] }
> ```
> （= 受击者未来 3 回合机动 -5，归 AFTER 因生效回合≠本次调用回合）

**状态叠加语义（用户确认 2026-08-23）**：
> 当单位已存在某状态且计时生效，再次施加同/异状态时的规则：
> - **同状态 + 同数值（a→a）**：**叠加时效**——延长该状态的剩余时长，不新增实例。
> - **同状态 + 异数值（a1→a2）**：**分别计时 + 状态叠加**——a1、a2 各自独立计时、各自存续；
>   若 a2 的数值运算为 **百分比 / 倍率**，则其计算**基于 a1 的结果值**（链式叠加，而非各自基于基础值）。
> - 落库护栏：status 机制须记录每个状态实例的 `{key, baseValue, op, remain}`；百分比/倍率实例在 tick 时读取"当前已生效值"而非原始基础值。
> 此规则同时约束 AFTER 延时状态与 DO 即时挂上的持续状态。

沿用 `docs/六段式编辑器与分段模型解释.md` 第五节，新段名映射：

```json
{
  "schema_version": 2,
  "tree": [
    { "phase": "时机", "atoms": [{ "type": "trigger_declare_action" }] },
    { "phase": "代价", "atoms": [{ "type": "resource", "resource": "ap", "value": -1 }] },

    {
      "phase": "随机性",
      "atoms": [{ "type": "roll_segments", "sides": 6 }],
      "segments": [
        {
          "label": "分段①",
          "dice_min": 1, "dice_max": 3,
          "atoms": [
            { "type": "direct_damage", "flat_value": -2, "note": "最终伤害-2" },
            { "type": "target_single", "target_type": "SINGLE_ENEMY" }
          ]
        },
        {
          "label": "分段②",
          "dice_min": 4, "dice_max": 6,
          "atoms": [
            { "type": "map_cannon", "split_mode": "equally|each", "total_damage": 15 },
            { "type": "modify_stat", "stat": "mobility", "value": -5, "duration": 3,
              "note": "受击者接下来3回合机动值-5" }

    },
```

## 九、速查总结

1. **三合一画布**：词条栏 → 单词条六段 → 段格就地展开原子下拉，原子面板不再独立。
2. **六段固定**：时机(WHEN)/条件(IF)/随机性(ROLL)/执行(DO)/后效(AFTER)/代价(COST)，顺序不可乱。
   - **AFTER 已于 2026-08-23 落地引擎**，落库 `phase:"AFTER"`，位于 DO 后、COST 前。
   - **动作原子分层（2026-08-23 修订）**：A 类数值动作（伤害/治疗/护盾/加减属性/**数值型状态**）**无独立主原子**，由 `数值域+流转方式+带符号值（+时效）` 修饰组合表达；**非数值状态枚举化**——眩晕/沉默=`AP-n`、定身=`机动-999`，均归 A 类，**删除"施加状态"主原子**，仅「标记」纯标签走「状态词条」引用。B 类主原子收敛为：**位移 / 召唤 / 词条（含普通·特殊·阵营·状态四类词条）/ 目标解析 / 地图炮 / 事件钩子 / 结算清理**。新增「状态词条」类目（待词条库侧补 `entryType:status`）。
3. **随机性 = 裂变触发器**：多区间 → 橙框分段；分段内再分叉 → 蓝框子段。
4. **子段只填效果**：随机性子段不套六段，直接挂原子。
5. **原子来自 atomRegistry**：下拉菜单与参数表单由 `listMeta()` 派生。
6. **AP 叠加**：代价段 -AP 与基础发动消耗同池叠加，超额前端标红。
7. **区分分段/子段**：看父裂变节点 + 橙蓝框色 + 前缀，不靠内容。
