# 六段式编辑器与「分段 / 子段」模型解释文档

> 适用对象：词条编辑器使用者、战斗逻辑设计者、前端/后端开发者
> 目的：统一「六段式」「分段」「子段」「ROLL 分叉」「WHO 语义」的概念认知，消除歧义。

---

## 一、什么是六段式（主链）

一次技能发动由一条**主链**描述，固定六段，顺序不可乱：

```
WHEN → IF → WHO → ROLL → DO → COST
```

| 段 | 含义 | 说明 |
|----|------|------|
| **WHEN** | 触发条件 | 什么时机/事件下可发动（如"目标选定时""回合开始"） |
| **IF** | 前置判定 | 发动前的附加条件（如射程、地形、充能层数） |
| **WHO** | 作用对象（响应者） | 技能打谁——**定义的是"响应者"，不是"发动者"**（详见第四节） |
| **ROLL** | 掷骰段 | 普通情况是一段；但它是**潜在的分叉点**（详见第二节） |
| **DO** | 效果执行 | 实际造成伤害/治疗/增益等 |
| **COST** | 消耗 | 充能/耐久/行动点等代价 |

主链的每一段都是**一级大节点**，在编辑器画布上等大、同级。

---

## 二、分段（Segment）：ROLL 段的裂变

### 核心认知

**ROLL 段不是"一个普通段"，而是分叉触发器。**

当 ROLL 段配置了多个掷骰区间时，主链在 ROLL 处**裂变成 n 个并列的分段**，每个分段由"掷出某个区间"触发，并自带**完整的剩余五段**（IF / WHO / ROLL / DO / COST）。

```
主链: WHEN → IF → WHO → ●ROLL(分叉触发器)
                         ╲ 橙色裂变母线
   ┌──────────────────────┼──────────────────────┐
 [分段①]               [分段②]               [分段③]
 掷 1~3 触发           掷 4~6 触发            掷 7~9 触发
   IF→WHO→ROLL→DO→COST  IF→WHO→ROLL→DO→COST  IF→WHO→ROLL→DO→COST
```

### 展示规则（关键）

- **先展现「roll1 / roll2 / roll3…」**：即 ROLL 裂出的 n 个掷骰区间，每个是一个分段入口
- **再展现「依据该 roll 出现的内容」**：即这个分段自己的剩余五段

所以用户看到的是：**ROLL 段 → 平铺 n 个分段卡片 → 点开某分段才展开它背后的五段。**

### 分段身份标注

每个分段卡片的**标题显式写出它对应哪个掷骰结果**（如「分段① 掷1~3」），让玩家/编辑者一眼区分。
这个"掷骰区间"是从主段 ROLL 的配置**自动带出并展示在分段头上**——**展示但不重复输入**（避免双写漂移）。

### 分段内部的 WHEN 段

分段内部的 WHEN 段**不再承载掷骰区间**（已在分段标题标注），而是可放**额外叠加条件**（如"且目标为敌人"）。大多数情况为空，显示「WHEN：无额外条件（触发依据=主段ROLL X~Y 已在分段头标注）」。

---

## 三、子段（Sub-segment）：分段内部的二级分叉

### 核心认知

**子段 ≠ 分段。** 子段是"分段内部再次分叉"产生的二级项。

- **分段**：直接挂在**主链 ROLL** 下面的一级并列项（与主段等大）
- **子段**：挂在**某个分段的 ROLL** 下面的二级项（嵌套在该分段框内，比分段小一号）

```
分段①  [掷1~3]
   WHEN(空) → IF → WHO → ●ROLL(分段①内分叉)
                              ╲ 蓝色裂变母线
                    ┌──────────┼──────────┐
                [子段A]      [子段B]
                掷1~2        掷3~3
                DO/COST      DO/COST
```

### 前端如何区分「分段」与「子段」（核心关机点）

**唯一可靠判据：看它挂在谁的下面。**

| 层级 | 父裂变节点 | 视觉量级 | 边框/母线颜色 | 标题前缀 |
|------|-----------|----------|--------------|----------|
| 主段 | — | 一级大节点 | 标准 | WHEN/IF/WHO/ROLL/DO/COST |
| **分段** | 主链 ROLL | **一级大节点（与主段等大，不塞进任何段框内）** | **橙色** | `分段①` |
| **子段** | 某分段的 ROLL | 二级嵌套（缩进在分段框内，小一号） | **蓝色** | `子段A` |

**布局铁律**：
- **分段必须和主段等大、同级**，绝不能是"塞在 ROLL 框里的小卡片"
- **子段才是嵌套在某分段框内的二级小节点**（现有嵌套框没问题）
- 颜色是"裂变层级"的硬信号：橙=一级分段，蓝=二级子段；尺寸本身也是区分信号（大节点=主段或分段，小节点=子段）

**不能靠内容区分**（分段和子段内部的五段长得一样），只能靠**层级位置 + 视觉外壳（橙/蓝）+ 前缀**区分。

## 四、WHO 段语义：对象是「响应者」不是「发动者」

### 直接结论

一次技能发动有两个固定角色：
- **发动者（source / unit / attacker）**：施放技能的单位
- **响应者（target / primary / defender）**：被技能指向/作用的单位

**WHO 段定义的是"作用对象（响应者）是谁"，不是"发动者是谁"。**

### 引擎证据（effectExecutor.cjs `_resolveEffectTargets`）

| target_scope | 解析结果 |
|--------------|----------|
| `self` | 发动者自己（作用对象=自身，仍属"响应者侧"定义） |
| `primary` | 被指向的响应者 |
| `enemy` / `AREA_ENEMY` | 全场中与 source 敌对的单位 |
| `ally` / `AREA_ALLY` | 全场中与 source 同阵营的单位 |
| `area` / `AREA` | 以 primary（响应者）为中心、半径筛选的单位 |
| `all` | 全场所有单位 |

`source`（发动者）仅作为"敌我判定的参照锚点"，**不是 WHO 的宾语**。

### 编辑器标注建议

在 WHO 段旁明确标注：「**作用对象 = 响应者；发动者恒为 source（仅作敌我判定参照）**」，避免编辑者误以为 WHO 选的是发动者。

### 与群体效果的陷阱

WHO 段定义"响应者集合的筛选规则"，但**真正落地打哪些单位的是 DO 段效果的 `target_scope`**。两者口径必须一致，否则会出现"WHO 写了 ALL_UNITS 但引擎无此 case 走 default 只打单体"的静默失效（注意：引擎 `_resolveEffectTargets` 当前**没有 `ALL_UNITS` 分支**，`target_scope` 合法值为上表所列）。

## 五、落库结构（前后端对照）

当前落库（`normalizeSkillForSave`）使用 `branches` / `children` 字段。建议语义升级（向后兼容）：

```json
{
  "phase": "ROLL",
  "atoms": [{ "type": "roll_segments", "sides": 6 }],
  "segments": [
    {
      "label": "分段①",
      "when": { "dice_min": 1, "dice_max": 3 },
      "sublane": {
        "lanes": [
          { "phase": "IF",   "atoms": [] },
          { "phase": "WHO",  "atoms": [{ "type": "target_all", "target_type": "SINGLE_ENEMY" }] },
          { "phase": "ROLL", "atoms": [{ "type": "roll_none" }] },
          { "phase": "DO",   "atoms": [{ "type": "direct_damage", "flat_value": -2 }] },
          { "phase": "COST", "atoms": [] }
        ]
      }
    },
    {
      "label": "分段②",
      "when": { "dice_min": 4, "dice_max": 6 },
      "sublane": {
        "lanes": [
          { "phase": "IF",   "atoms": [] },
          { "phase": "WHO",  "atoms": [{ "type": "target_all", "target_type": "ALL_UNITS" }] },
          { "phase": "ROLL", "atoms": [{ "type": "roll_none" }] },
          { "phase": "DO",   "atoms": [{ "type": "direct_damage_split", "total_damage": 10, "split": "equally", "target_scope": "area" }] },
          { "phase": "COST", "atoms": [] }
        ]
      }
    }
  ]
}
```

- `segments[]` = 一级分段（对应主链 ROLL 的 n 个掷骰区间）
- `segment.sublane.lanes` = 该分段自带的完整五段（IF/WHO/ROLL/DO/COST）
- 若 `sublane.lanes` 中某 ROLL 再次分叉 → 其下为**子段（二级）**

引擎 `_walkPhaseTree` 当前逻辑（命中 branch 后走其 children 取代主链剩余段）行为已正确，仅需把日志前缀从 `[子段:]` 翻转为 `[分段N:段名]` 以匹配新认知。

## 六、靶场展示（验证分段分叉）

靶场端点（`/simulate-skill`）应支持 tree 维度：
1. 识别 `schema_version === 2` 且有 `tree`
2. 支持 `dice_result` 强制掷骰，驱动分段分叉
3. 用 `context.allUnits` 多目标原生结算（让群体均摊正确命中含友军的多单位）
4. 返回结构区分分段/子段：

```json
{
  "triggered": true,
  "segment": { "label": "分段②", "dice_min": 4, "dice_max": 6, "dice_roll": 5 },
  "sublane_phases": ["IF", "WHO", "ROLL", "DO", "COST"],
  "sublane_effects": [
    { "phase": "DO", "type": "direct_damage_split", "targets": ["ALLY", "E1", "E2"], "per_target": 3 }
  ],
  "damage": 9
}
```

前端靶场面板据此渲染：「🎲 掷5 → 命中【分段② 4~6】→ 其五段依次执行 → 受击：ALLY/E1/E2 各-3」。

## 七、速查总结

1. **ROLL 段 = 分叉触发器**：出现即裂出 n 个分段，每个分段是带完整五段的独立路
2. **分段 = 一级大节点**（与主段等大，橙框，挂在主链 ROLL 下）
3. **子段 = 二级嵌套节点**（蓝框，挂在某分段的 ROLL 下）
4. **区分分段/子段**：看父裂变节点是谁 + 橙蓝颜色 + 分段/子段前缀，**不靠内容**
5. **WHO = 响应者**：定义作用对象，发动者恒为 source 仅作敌我参照
6. **分段标题显式写掷骰区间**，但不作为 WHEN 内的重复输入项
