### B.1 位移方向三分法（扩展 `displace`）
- 现状：`handleDisplace` 仅支持 `q/r 绝对` 或 `dx/dy 偏移`。
- 改造：新增 `direction` 参数解析：
  - `random`：从六向 `{+q,-q,+r,-r,+(q+r),-(q+r)}` 随机取一。
  - `fixed6`：按 `fixed_dir`(0~5) 取六角轴向偏移。
  - `relative`：按施法者→目标方位计算相对方向单位向量 × `cells`。
- 落库：段树写 `{type:'B_DISPLACE', direction:'relative', cells:2}`，registry 翻译为 `{type:'displace', direction:'relative', cells:2}`。
- 护栏：`cells ≥ 1`；越界格由 `skillExecutor` 落点校验拦截。

### B.2 召唤/生成真实实现（新 `spawn_unit`）
- 现状：`handleSpawnItems` 是空壳（仅回传 items 列表）。
- 改造：新增 `handleSpawnUnit`：
  - **必须走战局工厂函数 `createBattleUnit`**（或等价工厂），确保新单位拥有完整的 `faction` 标记、行动队列初始化、网关快照所需字段。
  - 生成后**在 `battleStore.set` 之前**将其注册进当前行动轮转数组 `factionTurnOrder`，避免客户端/服务端地图状态不同步。
  - `count ≤ 5`；`at` 决定落点（自身周围/落点/射程内）。
- 护栏：单技能生成数 ≤ 5，防战场爆炸；新单位落点需通过网关广播校验。

### B.3 词条联动触发（新 `trigger_entry`，含递归护栏）
- 现状：`rewrite_entry` 是"改写词条前置"，非"联动触发效果"。
- 改造：新增 `handleTriggerEntry`：
  - 读 `entry_id` → 经 `skillRegistry`/`entryRegistry` 取该词条的结算结果 → 作为子效果在当前上下文执行（递归调用 `effectExecutor.executeSync`）。
  - `on: hit|kill` 用于事件钩子区分触发时机（由 `skillExecutor` 在命中/击杀节点调用）。
- 护栏（防递归死循环，用户补充 2026-08-23）：
  - 引入全局执行追踪 `context.entryCallStack = Set<string>()` 与深度护栏 `context.entryDepth`（硬上限 **≤ 2**）。
  - 触发前若 `entry_id` 已在 `entryCallStack`（环路/A 自触发 A）→ 阻断并抛 `CIRCULAR_ENTRY_TRIGGER` 告警，不递归。
  - `entryDepth` 达上限亦阻断。

### B.4 目标解析（新 `resolve_target`）
- 新增 `handleResolveTarget`：
  - 综合 `scope`(阵营) + `range`(空间) → 计算 `context.resolvedTargets`。
  - 供同段后续 DO 原子（A 类 `apply_value` / 位移 / 词条）消费。
- 语义固化文档规则："范围+作用域=在某范围内的合适作用对象"。

### B.5 驱散/结算清理真实实现（补 `remove_buff`）
- 现状：`handleRemoveBuff` 空壳（return success）。
- 改造：真实删除 `target.statusEffects` 中匹配 `buff_key`（或 scope=all 全清）的实例；引用"状态词条"key 时经 `M_STATUS` 校验。

### B.6 状态叠加语义（改 `modify_stat` + `buffManager`）——【档位 X · 局部修正 + 纯函数计算】

> **落地深度决策（用户 2026-08-23 拍板）**：坚决选**档位 X**——只在 `statusEffects` 内部规范化 `stat_modifier` 实例并提供 `calculateEffectiveStat` 纯函数，**不强行收口全局 `currentStats` 读写**（避免牵动受伤扣血/消耗等直接写入点引发回归灾难）。
> **现状审计**：`handleModifyStat` 已能将带 duration 的修正 push 进 `statusEffects`（实例含 `type:'stat_modifier', stat_type, value, consumption.remaining`），但**无 `op` 分层、无叠加三规则、无 recalc 函数**；引擎**不存在 `currentStats` 聚合层**（各模块直接读写 `currentStats.hp` 等），故档位 X 是最佳过渡态。
> **永久强化 / 不可驱散（用户认可默认）**：永久强化直接改 `unit.baseStats[stat]`（不进栈、不可驱散）；临时不可驱散 Buff 挂 `undispellable:true`，`B_CLEANUP`/`remove_buff` 跳过。

#### B.6.1 状态实例数据结构 `StatModifierInstance`
```javascript
{
  type: "stat_modifier",
  key: "buff_atk_up",        // 状态 key (对应 M_STATUS)
  stat_type: "melee_attack", // 作用属性 (对应 M_STAT)
  op: "percent",             // "add" | "percent" | "multiplier" (默认 "add")
  value: 0.20,               // 修正数值 (+20%)
  duration: 2,               // 初始时长
  consumption: { remaining: 2 }, // 剩余回合/轮次
  undispellable: false,      // 是否不可驱散
  source_id: "u_01"
}
```

#### B.6.2 叠加三规则（在 `handleModifyStat` / `BuffManager.addStatModifier` 执行）
```javascript
// 规则 1：同 key 同 value 同 op -> 叠加时效（不新增实例）
const matched = unit.statusEffects.find(
  e => e.type === 'stat_modifier' && e.key === key
    && e.value === val && (e.op || 'add') === op
);
if (matched) { matched.consumption.remaining += duration; return; }
// 规则 2：同 key 异 value 或异 op -> 独立计时压栈（各自 remaining 独立递减）
unit.statusEffects.push(newModifierInstance);
// 规则 3：百分比/倍率基于"当前已生效值" —— 由 calculateEffectiveStat 管线天然保证（见 B.6.3），无需快照
```

#### B.6.3 动态算值纯函数 `BuffManager.calculateEffectiveStat(unit, statType)`
```javascript
function calculateEffectiveStat(unit, statType) {
  const base = Number(unit.baseStats?.[statType] ?? unit.currentStats?.[statType] ?? 0);
  const mods = (unit.statusEffects || []).filter(
    e => e.type === 'stat_modifier' && e.stat_type === statType && e.consumption?.remaining > 0
  );
  let addSum = 0, pctSum = 0, mulProd = 1;
  for (const m of mods) {
    const op = m.op || 'add';
    if (op === 'add') addSum += Number(m.value || 0);
    else if (op === 'percent') pctSum += Number(m.value || 0);
    else if (op === 'multiplier') mulProd *= Number(m.value || 1);
  }
  // 规则 3 固定顺序：base + 固定值累加 -> 百分比叠加 -> 倍率叠乘
  return (base + addSum) * (1 + pctSum) * mulProd;
}
```
- **消费侧**：技能伤害计算、命中/暴击判定等处调用 `calculateEffectiveStat(unit, stat)` 精准取值，而非直接读 `currentStats[stat]`。
- **自洽**：`modify_stat`（带 duration）按 B.6.2 压栈；`remove_buff`/B.5 驱散移除实例后，后续 `calculateEffectiveStat` 调用自动反映回退（天然无脏数据）。
- **向后兼容**：旧 `stat_modifier` 实例无 `op` 字段时按 `'add'` 处理；旧 `buffManager` 标量 API（`attack_buff` 等）保留不删（存量兼容），新逻辑只走 `stat_modifier` 实例栈。

### B.7 OR/AND 勾选逻辑（改 `skillExecutor` WHEN 路由）
- 现状：WHEN 段时机锚点为勾选，但无 AND/OR 语义字段。
- 改造：
  - 勾选菜单原子落库带 `match: 'AND' | 'OR'`（默认 AND）。
  - `skillExecutor` 在判定 WHEN 触发时：收集所有勾选锚点命中情况，`AND`=全部命中才触发；`OR`=任一命中即触发。
  - 同步应用于 IF 段多条件勾选。

## 三·补、用户补充的三处隐患修正（已采纳 2026-08-23）
