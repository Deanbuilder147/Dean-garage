1. 系统架构总览

项目中存在 4 个独立计算距离/移动/范围的系统，各自维护一套邻居表/距离逻辑/地形消耗表。当其中任何一层与另外三层不一致时，就会出现「客户端显示可到达，但服务端拒绝」或「范围显示包含某格，但使用时服务端不阻止」的不可达错位。

2. 🔴 严重问题 #1：combat-service 地形消耗表遗漏 6 种地形

严重 文件：services/combat-service/src/state/battleState.js 第 9–14 行

现象

战斗内核 battleState.js 的 TERRAIN_COST_MAP 只定义了 14 种地形，而词条库系统中已存在 21 种地形（前端 UNIVERSAL_TERRAIN_MAP 含完整 21 种）。缺失的 6 种地形全部以默认值 1 处理，导致移动消耗严重失准。

地形消耗对比

地形 ID中文名 应消耗（UNIVERSAL_TERRAIN_MAP） 实际消耗（TERRAIN_COST_MAP） 偏差
void留白 999 1（默认值回退） 可通行 vs 应阻断 ⚠️
plain平原 11（默认值） 无偏差 ✓
ruins废墟 2 1 移动消耗减半
crystal晶矿 2 1 移动消耗减半
rubble残骸 2 1 移动消耗减半
city_building城市建筑 11（默认值） 无偏差 ✓

影响范围

  • void 消耗 1 → 单位可穿越「留白」区域（画布外不可通行区），与前端 999 消耗彻底矛盾
  • ruins/crystal/rubble 消耗 1 而非 2 → 复杂地形无代价，移动范围虚增 2×
  • 受影响函数：getReachableHexes、canMoveTo、findPath、所有使用 terrainCost 的逻辑

如何发现

对 battleState.js 第 8–14 行计数：定义了 14 个 key。对 hexUtils.js 第 347–371 行计数：定义了 21 个 key。差值 7 个 → 其中 void 在 battleState.js 不存在，其余 6 个（plain/ruins/crystal/rubble/city_building + void）共 6 个缺失（lunar/empty 已存在）。

修复方案

const TERRAIN_COST_MAP = { space: 1, moon: 1, lunar: 1, empty: 1, base: 1, mothership: 1, repair_station: 1, spawn_earth: 0, spawn_maxion: 0, spawn: 0, desert: 1.5, forest: 2, water: 2.5, mountain: 3, fortress: 5, wall: 99, // ★ Phase 29-GlossaryMerge: 新增 6 种词条库地形，与前端 UNIVERSAL_TERRAIN_MAP 对齐 void: 999, // 留白：不可通行 plain: 1, // 平原 ruins: 2, // 废墟 crystal: 2, // 晶矿 rubble: 2, // 残骸 city_building: 1, // 城市建筑 };

3. 🔴 严重问题 #2：/skill 路由完全没有距离校验

严重 文件：backend-gateway/src/routes/combat.ts 第 616–698 行

现象

POST /api/combat/:battleId/skill 接收 casterUnitId、targetUnitId 后直接调用 executor.executeUniversalSkill()，全程没有验证 caster 与 target 之间的 hex 距离是否在技能范围内。

攻击流程对比（当前 vs 应有）

具体攻击场景示例

假设单位 A（坐标 q=5,r=10）持 range=1 的剑，攻击目标 B（坐标 q=9,r=12）：

hex 距离：用 Even-R offset→axial→cube 转换计算：A(5,10)→axial(0,10)，B(9,12)→axial(3,12)，距离 = (3+2+5)/2 = 恰好 5 格。但剑的 range=1。

当前行为：直接命中，造成伤害（因为无校验）。
应有行为：返回 400 OUT_OF_RANGE，禁止攻击。

SVG 图例：距离计算原理

修复方案

在 /skill 路由中，调用 executeUniversalSkill 之前插入距离校验步骤：

// ★ 在 combat.ts /skill 路由中，第 661 行之前插入： // ===== 距离校验（Even-R Offset 坐标） ===== if (exeCaster?.position && exeTarget?.position) { const dist = hexDistanceOffset(exeCaster.position.q, exeCaster.position.r, exeTarget.position.q, exeTarget.position.r); // 读取技能定义的范围 const skillDef = skillDefinition || (context?.glossarySkillMap||{})[skillType] || null; const skillRangeMax = skillDef?.range_max ?? skillDef?.range ?? 1; const skillRangeMin = skillDef?.min_cast_range ?? 0; if (dist > skillRangeMax) { res.status(400).json({ success: false, error: 'OUT_OF_RANGE', message: `距离 ${dist} 超出技能最大范围 ${skillRangeMax}` }); return; } if (dist < skillRangeMin) { res.status(400).json({ success: false, error: 'TOO_CLOSE', message: `距离 ${dist} 小于技能最小范围 ${skillRangeMin}` }); return; } }

注意：hexDistanceOffset 已在 combat.ts 上方定义（基于 offset→axial 转换的 Even-R 距离函数），可直接复用。

4. 🟡 中等问题 #3：min_cast_range 仅展示不校验

中等 文件：combat.ts + frontend/src/views/NewBattleView.vue

现象

词条库 glossary-skill-config.json 中定义了 min_cast_range 字段（例如狙击枪 "最小 3 格"），前端也在技能卡片显示 ≥N格 标签。但服务端完全不校验最小距离，导致狙击枪可以贴脸射击。

位置代码状态
词条库 glossary-skill-config.json "min_cast_range": 3 ✅ 已定义
前端技能卡片 NewBattleView.vue:788 tags.push({ label: `≥${gs.min_cast_range}格` }) ✅ 已显示
前端技能范围预览 getSkillRange:2334 return Math.max(skill.range_min, skill.range_max) ⚠️ 用了 range_min 但不排除过近格
网关 /skill 路由 combat.ts:661 executor.executeUniversalSkill(...) ❌ 完全不校验

SVG 图例：min_range 的效果

修复方案

与 #2 合并修复（见上节 /skill 路由修复代码），在距离校验中同时检查 dist >= skillRangeMin。这将自动覆盖 min_cast_range。

5. 🟡 中等问题 #4：前端技能范围预览不排除最小距离格

中等 文件：frontend/src/views/NewBattleView.vue 第 1666–1693 行

现象

当选择有最小距离的技能（如 range_min=3, range_max=6）时，前端 BFS 从 caster 扩散后添加所有 dist ≤ max 的六角格，没有过滤掉 dist < min 的格。用户看到 self 周围的 hex 也高亮为「可攻击」，但实际这些格是不可用的。

当前代码（问题处）

const range = getSkillRange(selectedAttackSkill.value) // 只返回 max 值 // BFS for hex range ring const startKey = `${su.q},${su.r}` const visited = new Set([startKey]) const queue = [{ q: su.q, r: su.r, dist: 0 }] while (queue.length > 0) { const cur = queue.shift() if (cur.dist >= range) continue // 只检查上限 for (const n of getHexNeighbors(cur.q, cur.r)) { const nKey = `${n.q},${n.r}` if (visited.has(nKey)) continue // ... bounds check ... visited.add(nKey) queue.push({ q: n.q, r: n.r, dist: cur.dist + 1 }) if (cur.dist + 1 <= range) { skillRangeHexes.add(nKey) // ← dist=1,2,3 全部加入！ } } }

修复方案

// 从技能定义中提取 range_min const skillRangeMin = selectedAttackSkill.value ? (selectedAttackSkill.value.range_min ?? 0) : 0 // BFS 循环内： const newDist = cur.dist + 1 if (newDist <= range && newDist >= skillRangeMin) { skillRangeHexes.add(nKey) }
