⚙ 战场 Canvas 图层架构说明

NewBattleView · HexGridCanvasEngine · ShapedCanvas　|　梳理于 2026-09-01

核心结论：战场上的 <canvas> 实际只有 1 个（HexGridCanvasEngine 的 mainCanvas）， 外加一个独立的小地图 canvas（BattleMinimap，另算）。地图视图设置面板里那串开关 （背景 / 地形 / 网格 / 间距 / 4 边 / 外框SVG / 单位层 / 坐标 / 透明度）并不是 7、8 个独立 canvas， 而是这 1 个 canvas 的不同绘制层 + 几个 DOM / SVG 层。

① 从底到顶的图层堆叠（z 序，后绘制的盖在上面）

z 最高 DOM

4 · DOM 浮层（UI / 提示）

地图图例 map-legend · 地图视图设置面板 MapViewSettingsPanel · 小地图 BattleMinimap · 骰子 / 胜利 / 伏击 / 反应奇袭遮罩 · 部署过场控制条 · 单位详情卡。

受 z-index 控制，永远压在最上做交互与提示。
SVG

3 · 外框 SVG 层（ShapedCanvas）

<polygon> 用同一份 rawPoints 描边 + drop-shadow 发光，即「地形外框 / 4 边长度」可视化。

pointer-events:none（不挡交互）；交互命中由 .sc-hit 的 clip-path 限制在异形内（异形外不触发点击）。
CANVAS

2 · mainCanvas 单画布（3 个绘制层，见下节）

每帧 draw() 按 L1 地形 → L2 高亮 → L3 战斗叠加的顺序绘制；坐标标签 / 悬停高亮属引擎（L1 内），drawFn（L3）只画战斗专用叠加。

这是唯一真正画像素的 <canvas> 元素（透明），下方背景透过它显示。
z 最低 DOM

1 · 背景层（DOM，不是 canvas）

HexGridCanvasEngine 的 .hex-engine-sandbox 容器用 CSS background-color(背景色) + background-image(背景图) 铺底； mainCanvas 自身 clearRect 透明，背景透过显示，受 ShapedCanvas 的 clip-path 自动裁成异形。

地图视图设置「背景」开关控制的就是它。

② mainCanvas 内部每帧绘制顺序（L1→L3）

  1. L1 地形层（renderTerrainCache / renderTerrainInline）：地形填充 + 网格线。 地形色 / 不透明度由「地形」设置项控制；间距 H/V 来自 spacingHScale / spacingVScale； 地形缓存内还含坐标标签与悬停高亮（引擎职责，对应「坐标」「网格」开关）。
  2. L2 高亮格子层（renderHighlights）：通用 highlightCells（move / attack / select / warning）覆盖在地形上，指示可走 / 可点格。
  3. L3 战斗叠加层（drawFn → drawBattleScene）：经 ctx.transform(ISO…) 绘制移动 / 技能 / AOE 范围、合法目标、 单位精灵、HP 条、选中环、部署动画等。unitOpacity 经参数传入控制「单位层」透明度。盖在最上，保证单位清晰。

③ 各层互相作用关系

上下遮挡

背景在最底、透过透明 canvas 显形；地形是基底；L2 高亮压在地形上；L3 单位与范围盖在地形之上；外框 SVG 只做边框装饰；DOM 浮层永远最上。

职责边界

坐标标签 / 悬停属引擎 L1 职责，drawFn(L3) 只画战斗专用叠加。二者不冲突——这是「渲染管线」宪法红线（引擎无状态，只收 props / drawFn，不读 Vue 状态）。

命中与裁切

异形框由 ShapedCanvas 的 clip-path 在 DOM 层裁切；SVG 边框 pointer-events:none 不挡交互；点击命中被限制在异形内（异形外不触发）。

缩放与单位

4 边长度滑块改 rawPoints 实时重算外框；间距 H/V 改地形排布；单位透明度只影响 L3。所有改动都映射到同 1 个 canvas 的不同绘制层。
