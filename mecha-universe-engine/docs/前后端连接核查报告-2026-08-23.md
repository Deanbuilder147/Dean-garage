## 二、未连接 / 单向缺口（真实）

### 缺口 1（单向死写）：`d.after` 扁平字段后端从不读取 ⚠️
- **前端**：`writeLanesToDraft` L1612 写出 `d.after = { effects: atomsToContract(afterLane.atoms) }`。
- **后端**：全量检索 `glossary.ts`，仅 `casterAfter` / `targetAfter`（模拟结果快照字段），**从不读取 `skill.after` / `d.after`**。后端战斗核心/模拟管道消费的是 `d.tree` 的 `{phase:'AFTER'}` 节点。
- **影响**：无害但冗余——主链 tree 已含 AFTER，该扁平字段是死写，若后续有人误读 `d.after` 会拿到与 tree 不一致的孤立数据。
- **建议**：删除 L1612 的 `d.after` 写出（保持 tree 单一真相源）。

### 缺口 2（字段约定灰色缺口）：ROLL 分段"自选目标型"判定字段错配 ⚠️ → **已采用方向2修复（2026-08-23）**
- **后端**：`glossary.ts` L697-703（`Phase 33-PureSegment`）用 `roll.segments[].effects[].target_scope` 判断"自选目标型"（引擎自选靶、靶场仅调用一次），否则对每个目标独立调用 + AOE Fork。
- **前端**：ROLL 分段内原子经 `atomsToContract` 透传 params。前端原子面板中**仅 `D3 伤害均摊`（L1669）显式带 `target_scope` 字段**（值 `'area'`）；其余伤害/效果原子用 `target_type` / `target_kind` 等字段，**不产生 `target_scope`**。
- **影响**：ROLL 分段内放置非 D3 原子时，后端 `engineDrivenTargeting` 恒为 false → 走"对每个目标独立调用"旧行为，可能与设计意图（引擎自选多目标）不符。
- **修复方案（方向2·后端增强判定）**：在 `glossary.ts` 扩展 `engineDrivenTargeting` 真值表达式，将**顶层 `target.type`** 以及**分段内 `target_type` 的群体/区域枚举**（`AREA_*`/`ALL_*`/`MULTIPLE_*`）统一纳入识别：
  ```ts
  const MULTI_RE = /^(ALL_|AREA_|MULTIPLE_)/i;
  const isTopLevelMultiTarget = MULTI_RE.test(skillDef?.target?.type || skillDef?.target_type || '');
  const engineDrivenTargeting =
    isTopLevelMultiTarget ||
    segs.some(s => Array.isArray(s?.effects) &&
      s.effects.some(e => !!e?.target_scope || MULTI_RE.test(e?.target_type || '')));
  ```
  理由：目标范围本由 W 组 `target_selection` 收敛在顶层 `target.type`，前端零改动、存量数据 0 成本兼容。
- **靶场回归验证**（线上 `mecha-gateway` 重建 + `POST /api/combat-glossary/test-skill`，key=`_regress_d1_area`，D1 direct_damage + `target.type=AREA_ENEMY`）：
  - 引擎仅被调用**一次**（单次结算路径），`engineDrivenTargeting=true` 生效；
  - 射程内目标 t1 命中（final_damage=10），超距候选 t2/t3 由引擎内部统一判 `out_of_range`（collateral 模式），**无"每目标独立掷骰/重复结算"旧行为**；
  - 对照：旧逻辑会对每个目标各自调引擎、各自掷骰。验证确认修复达成预期。
  - 测试词条已清理（count 回到 10），容器重启干净态，健康接口 200。
