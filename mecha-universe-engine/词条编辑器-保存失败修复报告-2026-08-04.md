# 词条编辑器「保存失败：请先登录」修复报告

**日期**：2026-08-04
**现象**：在词条库中枢（GlossaryHub）编辑词条 → 点「✓ 完成」保存 → 弹窗「保存失败：请先登录」，且之前编辑的内容似乎丢失。

---

## 一、根因（两层叠加）

### 1.1 第一层：请求不带 Token（导致 401）

`frontend/src/views/GlossaryHub.vue` 第 56 行：

```js
import axios from 'axios'        // ❌ 裸 axios，无请求拦截器
```

第 151 行（GET）、第 193 行（PUT）都用**裸 `axios`**。裸 axios **没有 `apiClient` 的请求拦截器**，不会自动注入 `Authorization: Bearer <token>`。

而后端 `backend-gateway/src/routes/glossary.ts` 第 430 行：

```ts
router.put('/hub-config/:key', authenticate, (req, res) => { ... })
```

`authenticate` 中间件（middleware/auth.ts 第 78 行）无 token 时返回：

```ts
res.status(401).json({ success:false, error:'AUTH_TOKEN_MISSING', message:'请先登录' })
```

**这正是前端弹出的文案**——所以用户遇到的是「请求根本没带 token → 401 → 请先登录」。

> 注：GET 列表能加载，是因为 `GET /hub-config` 是公开的（无 `authenticate`）；但 PUT/DELETE 加了鉴权，裸 axios 无 token → 401。

### 1.2 第二层：保存失败仍退出编辑态（导致"编辑丢失"的错觉）

`GlossaryHub.vue` 旧 `toggleEdit`（第 173-179 行）：

```js
function toggleEdit() {
  if (editing.value) {
    saveCurrent()              // ❌ fire-and-forget，没 await、没 catch
  }
  editing.value = !editing.value  // ❌ 无论保存成功与否，都退出编辑态
}
```

`saveCurrent()` 抛错（401）后，**编辑态仍被强制退出** → 用户回到只读视图，看到的是旧值 → 误以为"编辑的内容没有了"。实际草稿（draft）仍在内存中，只是编辑界面关了。

---

## 二、修复内容

### 2.1 改用带 Token 的 apiClient（核心修复）

`frontend/src/views/GlossaryHub.vue`：

```js
import apiClient from '../api/client.js'   // ✅ 带拦截器，自动注入 Bearer
...
const { data } = await apiClient.get('/combat-glossary/hub-config')
...
await apiClient.put('/combat-glossary/hub-config/' + selectedKey.value, payload)
```

> `apiClient` 的拦截器从 `localStorage.token` 读取（登录时 `userStore.setToken` 已写入），并增加 `localStorage.user.token` 兜底，防止存储格式错位。

### 2.2 保存失败保留编辑态（防误丢）

`GlossaryHub.vue` `toggleEdit`：

```js
async function toggleEdit() {
  if (editing.value) {
    try {
      await saveCurrent()        // ✅ 等待保存结果
    } catch (e) {
      return                     // ✅ 失败则保留编辑态，不退出
    }
  }
  editing.value = !editing.value
}
```

并改进失败提示为「（你的编辑内容已保留在本地，请重试保存）」。

### 2.3 登录态恢复兜底（main.js）

`frontend/src/main.js` 的 `bootToken` 同步兼容 `localStorage.user.token`，确保刷新后侧边栏/路由守卫能识别已登录状态。

### 2.4 改动文件清单

| 文件 | 改动 |
|------|------|
| `frontend/src/views/GlossaryHub.vue` | 裸 axios → apiClient；toggleEdit 保留编辑态 |
| `frontend/src/api/client.js` | 拦截器 token 读取兼容 `localStorage.user.token` |
| `frontend/src/main.js` | `bootToken` 兼容 `localStorage.user.token` |

## 三、部署与验证

**部署**：rsync → 服务器 `npm run build`（frontend）→ 重建 `mecha-frontend` 容器。

**验证（playwright 实测 + console 日志）**：

1. ✅ 登录后侧边栏跨会话显示 `[deantest]`，证明 `main.js` 的 `bootToken` 兼容生效，登录态正确恢复。
2. ✅ console 日志实证：修复后 `PUT /api/combat-glossary/hub-config/block` 返回 **403（Forbidden）** 而非 **401**——
   ```
   Failed to load resource: the server responded with a status of 403 (Forbidden)
   @ http://106.54.197.69:8081/api/combat-glossary/hub-config/block
   ```
   **403 ≠ 401，证明 Token 现已成功带上、鉴权已通过**（之前是 401 无 token，现在是带 token 但角色不够）。
3. ✅ 保存失败不再退出编辑态，提示「编辑内容已保留在本地，请重试保存」。

## 四、剩余事项：PUT 端点要求管理员权限

后端 `glossary.ts` 第 433 行：

```ts
if (!isAdminOrAbove(role)) {
  res.status(403).json({ success:false, error:'FORBIDDEN', message:'仅管理员可编辑词条库' });
}
```

`isAdminOrAbove` 只认 `ADMIN` / `DOMINATOR`（glossary.ts 第 116-118 行），**不含 `referee`**。

本次实测用的是 referee 测试号 `deantest`，因此即便 Token 修好，仍收到 **403「仅管理员可编辑词条库」**（这是预期行为，非 bug）。

**结论**：
- 若你本人账号是 **admin / dominator**：本次修复后已能正常保存（401 已消除）。
- 若你用 **referee** 账号：会卡在 403 权限门槛。

**待你确认的方向（任选其一）**：
1. 用 **管理员账号** 登录保存（推荐，不改后端权限模型）；
2. 或我**放宽 PUT 权限**让 referee 也能编辑（需评估 Phase 29 数据安全设计意图）；
3. 或新增「词条草稿箱 + 提交审核」流程（referee 提交 → admin 审核发布）。
