# 词条编辑器（词条库中枢）· 词条编辑属性逻辑报告

> 生成日期：2026-07-20
> 适用范围：`mecha-universe-engine/`
> 涉及文件：
> - 编辑器 UI：`frontend/src/views/GlossaryView.vue`（55KB，模板 + `<script setup>`）
> - 后端路由：`backend-gateway/src/routes/glossary.ts`
> - 配置中枢：`services/combat-service/src/config/glossary-skill-config.json`（v5.0）
> - 前端 API：`frontend/src/api/client.js` → `glossaryAPI`
> 说明：本报告整理"编辑器里能编辑哪些词条属性、编辑逻辑如何运转"，并顺带标记出我发现的**其他错误/隐患**（你担心的点）。

---

## 一、概览：编辑器的数据流

| 层 | 职责 | 关键点 |
|---|---|---|
| 后端 `glossary.ts` | 提供 `GET /combat-glossary/config`（游客可读）、`POST /combat-glossary/config`（仅 admin/dominator 可写） | 写入时**深度合并** skills，且 `CORE_SKILLS`（6 个硬编码核心技能）不可被覆盖/删除；支持 `_delete_skills` 删除指令（同样不能删核心技能） |
| 配置 `glossary-skill-config.json` | 真值来源，含 `damage_kinds(5)` / `action_types(5)` / `skills(11)` / `systems(3)` / `terrains(10)` | 编辑器只读写其中一部分（见 §五·5.2） |
| 前端 `GlossaryView.vue` | 拉取配置 → `editableConfig`(reactive) → 双向 `v-model` 编辑 → 保存 | `editableConfig = { _meta, skills, systems }` |

> 数据流：`loadConfig()`（GET）→ 填充 `editableConfig` → 用户编辑（卡片 / 向导 / AI 导入）→ `saveConfig()`（POST）→ 后端合并落盘 → 重新 `loadConfig()` 确认同步。

### 2.2 系统参数（`systems`，按字段平铺编辑）

`getSystemParams()` 过滤掉 `label / description / deterministic / deterministic_probability` 后逐字段编辑：
- `ambush`：`trigger`、`damage_percent`
- `fog_of_war`：`visibility`（下拉 normal/reduced/blind）、`accuracy_modifier`
- `crit`：`chance`、`multiplier_min`、`multiplier_max`

### 2.3 配置元信息（`_meta`）

只读展示 `version / date / principle`，保存时自动刷新 `date` 与 `generated_from`，不提供手工编辑。

## 三、三条词条创建 / 编辑通道

### 3.1 内联卡片编辑（主通道）
- `addNewSkill()` 生成 `new_skill_<timestamp>`，预填一份"标准骨架"（type=active、category=melee、damage_kind=kinetic、dice_type=1d6…）。
- 所有字段通过 `v-model` 直接双向绑定到 `editableConfig.skills[key]`，**未显示的字段因整对象保留而不丢失**（关键前提：保存时把整个 skill 对象回传，见 §四）。

### 3.2 万能槽位分步向导（Phase 11，6 步：主/谓/宾/定/状/补）
- Step1 主语：`action_type` / `attack_stat` / `requires_unmoved` / `requires_stealth` / `requires_hp_below` / `target_on_terrain`
- Step2 谓语：`target_filter` / `cast_range` / `min_cast_range` / `aoe_radius` / `range_type` / `beam_width`
- Step3 定语：`damage_kind` / `category` / `description`
- Step4 状语：`height_bonus_per_diff` / `dice_type` / `success_line` / `success_bonus_damage` / `is_manual_roll` / `accuracy_mod` / `evasion_mod`
- Step5 补语：`base_damage` / `status_effects_str`（逗号分隔）
- Step6 确认 → `commitWizardSkill()` 组装成 skill 对象写入 `editableConfig.skills`
- ⚠️ 向导**不设置 `type` 字段**（卡片骨架会设 `type:active`），导致向导创建的技能缺 `type`。

### 3.3 AI 技能 JSON 导入（Phase 12，`importAiSkills`）
- 粘贴 JSON（对象或数组），标准化后写入。
- 🔴 **该通道完全失效**（见 §五·5.1）。

### 3.4 删除通道
- `deleteSkill(key)` → 弹确认 → 推入 `pendingDeletes` 并从 `editableConfig.skills` 移除（UI 标记 `deleted-card`）。
- 保存时把 `pendingDeletes` 作为 `_delete_skills` 发给后端；后端忽略对核心技能的删除。
- ⚠️ 核心技能（见 §五·5.6）在 UI 可"删"，保存后会被后端拒绝并"复活"，误导用户。

## 四、保存与同步逻辑

```js
// 前端 saveConfig() 构造的 payload
const config = {
  _meta: { ...editableConfig._meta, date, generated_from },
  skills: { ...editableConfig.skills },   // 整对象回传，未显示的字段因此保留
  systems: { ...editableConfig.systems },
}
if (pendingDeletes.length) config._delete_skills = [...pendingDeletes]
await glossaryAPI.saveConfig(config)
await loadConfig()  // 保存后重新拉取确认同步
```

后端 `POST /config`：
1. 鉴权：`isAdminOrAbove` 否则 403。
2. `readConfig()` 读全量（含 `terrains/damage_kinds/action_types` + 合并 `CORE_SKILLS`）。
3. 仅用传入的 `skills` 中非核心部分做合并；用 `_delete_skills` 删除非核心技能。
4. `writeConfig()` 整文件写回 → **因此 `terrains/damage_kinds/action_types` 在服务端被保留**（前端虽不发，后端基于旧文件合并，不丢）。

✅ 结论：保存不会丢失服务端已有的 `terrains/damage_kinds/action_types`；但前端对这三块**完全没有读写入口**（见 §五·5.2）。

## 五、我发现的其他错误 / 隐患（重点）

### 5.1 🔴 AI 导入功能彻底失效（最高优先）
`importAiSkills()` 中存在两个硬伤：
1. **引用未定义变量**：`const config = JSON.parse(JSON.stringify(skillsData.value))`（L962）与 `skillsData.value = config`（L1012）中的 `skillsData` **在整个 `<script setup>` 中从未声明** → 运行时 `ReferenceError`，函数直接抛错，导入 0 个技能。
2. **`saveConfig(config)` 传参被忽略**：定义的 `saveConfig()` 不接受参数、固定读取 `editableConfig`。而导入的技能是写进局部 `config.skills`，**从未进入 `editableConfig`**，即使第 1 点修复，保存的仍是原 `editableConfig`，导入内容全部丢失。
> 修复方向：导入时直接写入 `editableConfig.skills[id] = normalized`，再调用无参 `saveConfig()`；删除所有 `skillsData` 引用。

### 5.2 🟡 地形 / 伤害种类 / 动作类型 三类配置无编辑入口
`GlossaryView.vue` 全文**不含 `terrains` / `damage_kinds` / `action_types` 任何引用**（已 grep 验证，0 命中）。编辑器只有「技能词条 / 系统参数 / 配置元信息」三个面板。
- 后果：这三类共 20 项配置**在 UI 上完全不可见、不可改**，只能手工改 json 文件。若策划要调地形减伤/伤害种类，编辑器帮不上忙。
- 注意：它们靠后端"读旧文件合并"在服务端存活，但属于**编辑器能力缺口**。

### 5.3 🟡 词条专属字段不可编辑（且仅靠"整对象保留"不丢）
配置里大量专属字段在 UI 无任何控件：`reduction`(格挡)、`trigger`、`sector_angle`/`mode`(扫射)、`stat_comparison`(决斗)、`condition`/`damage_multiplier`(抢夺)、`no_consecutive`(再动)、`effect`/`value`/`aoe_range`(投掷)、`hp_threshold_percent`(斩杀)、`requires`(专注射击)。
- 这些字段**之所以不丢**，完全依赖 §四 的"整 skill 对象回传"。一旦将来保存逻辑改为只发"已编辑字段"，就会静默丢失。
- 更隐蔽的子问题：向导创建的 `requires_hp_below` / `target_on_terrain` 在卡片 UI 里**没有对应编辑控件**，创建后无法再改（除非改 JSON）。

### 5.4 🟡 向导创建技能缺 `type` 字段
`addNewSkill()` 设 `type:'active'`，但 `commitWizardSkill()` 不写 `type` → 向导生成的技能 `type` 为 `undefined`。`skillExecutor` 若依赖 `type` 区分 active/passive 可能行为异常。

### 5.5 🟡 `category` 与 `type` 语义重叠、易误配
- `type` ∈ {active, passive}（是否主动释放）
- `category` ∈ {melee, ranged, special, **passive**}（战斗分类，竟包含 passive）
两者正交却共用 "passive" 一词，极易配出 `category=passive` 且 `type=active` 这种矛盾组合。建议 `category` 去掉 `passive` 选项，或明确文档区分。

### 5.6 🟡 核心技能"假删除"误导
后端 `CORE_SKILLS`（melee_strike / ranged_shot / shield_wall / repair / overdrive / beam_cannon，共 6 个）在编辑器列表里出现，且 UI 提供删除按钮；但保存时后端拒绝删除并"复活"。用户会困惑"为什么删不掉"。建议 UI 对核心技能标记只读/隐藏删除键。

### 5.7 🟢 数值约束不一致
- 卡片端 `base_damage` 无 `min/max`（L377-380），向导端有 `0–100`；`cast_range` 等卡片端有 0–20 而 `base_damage` 没有。
- `dice_type` 是自由文本框，向导给的是 `1d4/1d6/1d8/2d6/1d10/1d20` 下拉，但卡片端又是文本框 → 两处控件类型不一致，且文本不校验格式。

### 5.8 🟡 `beam` ↔ `energy` 术语错位（与 Excel 对照报告 §十·10.6 同源）
编辑器 `damage_kind` 下拉用的是 **`beam`**（光束），但装备耐久系统 `equipmentDurability.cjs` 判定"抗性涂层"时用 **`energy`**。这是上一报告已标记的真 bug 在编辑器侧的体现——编辑器产出的 `damage_kind=beam` 单位，其"抗性涂层"在战斗里因 `energy` 不匹配而**永不触发**。

## 七、修复建议（按优先级）

| 优先级 | 问题 | 建议动作 |
|---|---|---|
| **P0** | AI 导入失效（5.1） | 删除 `skillsData` 引用；导入直接写 `editableConfig.skills`，再调无参 `saveConfig()` |
| **P1** | 地形/伤害种类/动作类型无入口（5.2） | 新增对应编辑面板（或至少只读展示 + 可编辑），避免只能手改 JSON |
| **P1** | 专属字段不可编辑（5.3） | 为关键专属字段（`reduction`/`trigger`/`sector_angle`/`requires` 等）补控件；或明确"仅 JSON 可改"并在 UI 提示 |
| **P1** | 向导缺 `type`（5.4） | `commitWizardSkill` 补 `type: wizardForm.action_type === 'passive' ? 'passive' : 'active'` |
| **P2** | category/type 语义重叠（5.5） | `category` 下拉移除 `passive`，或加注释说明二者区别 |
| **P2** | 核心技能假删除（5.6） | UI 对 `CORE_SKILLS` 标记只读、隐藏删除键 |
| **P2** | 数值/控件不一致（5.7） | 统一 `base_damage` 约束；`dice_type` 统一为下拉或加格式校验 |
| **P0(跨报告)** | beam/energy 错配（5.8） | 同 Excel 对照报告 P0：统一 `beam`↔`energy`（改 `equipmentDurability`/`equipManager`） |
