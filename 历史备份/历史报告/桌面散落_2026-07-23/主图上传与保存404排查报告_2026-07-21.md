## 四、当前状态：保存后 404（最新问题）

### 现象
主图上传成功后（文件名前出现 `✓`），点击"保存"单位，浏览器 network 面板显示该保存请求 **404 not found**。

### 代码核查结论（已确认）
- **路由存在、路径正确**：`backend-gateway/src/routes/units.ts:240` 定义 `router.put('/api/units/:unitId', authenticate, ...)`；`app.ts:91` 以 `app.use(unitRoutes)` **无前缀**挂载，故实际路径为 `/api/units/:unitId`，与前端 `updateUnit(id)` → `PUT /units/${id}`（baseURL `/api`）一致。**排除路由缺失导致的 404。**
- **保存接口含 owner 权限检查**：`units.ts:252-257` 执行
  ```sql
  SELECT * FROM units WHERE id=$1 AND owner_id=$2
  ```
  查不到即 `return res.status(404).json({ error:'UNIT_NOT_FOUND', ... })`。
- **列表 / 单单位 GET / PUT 均带 `WHERE owner_id=?`**（`units.ts:71, 92, 252`），非 owner 一律 404。
- **前端编辑 id 回填正确**：`NewUnitEditorView.vue:603` `editUnit` 设 `editingUnit.value = JSON.parse(JSON.stringify(unit))`（unit 含 `id`）；`:614` `saveUnit` 用 `editingUnit.value.id`。**排除"id 为空 → /api/units/undefined"假设。**

### 初步诊断（二选一，需用户确认）
- **A（最可能）：当前登录账号非 BEXM-21(W) 的 owner** → `PUT` 触发 owner 检查返回 404 UNIT_NOT_FOUND。
  - 佐证：用户能进入编辑页（列表按 owner 返回，说明登录账号在列表里能看到该单位，即应为 owner），但 Excel 导入单位的 `owner_id` 可能与当前浏览器登录账号不完全一致，或存在导入账号与登录账号差异。
- **B：路由层 404（非后端 JSON）**：前端实际请求路径与后端不匹配。但代码核查已排除（路径一致），仅当线上运行代码与本地不一致时才可能，需核对。

### 验证缺口
服务器侧用 `testadmin` / `e2etest` 实测均未能复现 owner 场景：
- `testadmin` 登录后 `GET /api/units` 返回 `{"error","message"}`（登录态/账号异常），无法取得 BEXM 的 id；
- `e2etest` 单位列表 `count:0`（无单位），`PUT` 空 id 得 404（无代表性）。
- 故未能在服务器侧直接复现"owner 不匹配→404"，需用户在浏览器侧确认。
