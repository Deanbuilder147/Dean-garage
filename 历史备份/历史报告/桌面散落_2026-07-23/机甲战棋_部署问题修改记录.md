## 三、根因分析

### 3.1 "场上不显示 + 未知阵营"
- `createBattleUnit`(battleStateFactory.ts) 产出的 `BattleUnit` 只含 `unitId/matrixId/ownerId/position/currentStats/skills/action_points`，**缺 `faction/name/codename/unitCode/type/viewUrls`** → 前端无法上色 → "未知阵营"。
- 坐标只存 `position.{q,r}`，而棋盘 `NewBattleView.vue` 读顶层 `unit.q`（约 24 处），且 `unitSpriteState` 用 `unit.id` 作 key（BattleUnit 仅 `unitId`）→ 部署单位 `q` 为 `undefined` → 被 `filter(u => u.q !== undefined)` 过滤 + `pointyTopCenter(NaN)` → 完全不渲染。

### 3.2 UNIT_NOT_IN_POOL
- `deploy-unit` 硬性要求 `unit_id` 命中后端 `pendingUnits` 池，否则 404。两类触发场景：
  1. **重复点击已上场单位**：部署阶段 `factionGroups` 把"已在场（有 `q`）"和"未部署池"单位混排进阵营框，点任意卡片都会走 `startDeployUnit`→`deployToHex`，已部署单位 id 已不在池中。
  2. **回退池 id 不匹配**：若 `NewPreparationRoom` 的 `pending-units` POST 静默失败（catch 吞错），后端池空，`loadDeployPool` 回退到 hangar/localStorage 的 id，与空池不匹配。

```typescript

  if (typeof v === 'string') {
    try { return JSON.parse(v); } catch { return v; }
  }
  return v;
}
```
