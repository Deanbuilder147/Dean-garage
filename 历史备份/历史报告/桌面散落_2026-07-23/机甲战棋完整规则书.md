## 1. 棋盘与坐标系统

### 1.1 六边形网格
- 采用 **尖顶（pointy-top）+ Even-R Offset** 坐标系。
- 单元格标准尺寸常量集中在 `hexUtils.js`：
  - `HEX_WIDTH = 64`，`HEX_HEIGHT = 72`（**严禁硬编码**，统一从此导入）。
- 坐标以 `{q, r}` 轴向坐标表示。

### 1.2 数学真理（唯一来源）
- `pixelToHex` / `hexToPixel`：保持 1.0 标准倍率 **绝对纯净**。
- 缩放 / 平移 / 等距压缩均在核心公式外部做矩阵逆运算：
  - 渲染：`2D标准坐标 → ×scale → +offset →（等距时 Y×0.5）→ 绘制`
  - 点击：`鼠标像素 → -offset → ÷scale →（等距时 Y÷0.5）→ 核心公式逆推`
- 参考：`frontend/src/utils/hexUtils.js`，宪法红线见 `MEMORY.md`「战棋开发宪法 v2.0」。

### 1.3 距离与邻接
- 六角距离（cube 距离）：`dist = (|dq| + |dq+dr| + |dr|) / 2`，其中 `dq=q1-q2`，`dr=r1-r2`。
- 邻居：每个格 6 向相邻（NE/SE/S/SW/NW/NE…视朝向而定）。
- 参考：`combat-service/src/services/turnManager.js:627 calculateDistance`。

## 2. 阵营与回合结构

### 2.1 三方阵营（默认角色）
| faction key | 默认角色 role | 中文 | 默认定位 |
|-------------|---------------|------|----------|
| `earth` | `attack` | 攻击方 | 主攻 |
| `maxion` | `ambush` | 偷袭方 | 奇袭/隐匿 |
| `balon` | `defense` | 防守方 | 坚守/增援 |

> 角色与 faction 的映射在整备室（NewPreparationRoom）通过 `factionTurnOrder` 注入战局；空角色被跳过。

### 2.2 阵营轮转（factionTurnOrder）
- 战局持有 `factionTurnOrder: string[]`（如 `['earth','balon','maxion']` 对应 攻击→防守→偷袭），`activeFaction` 为当前行动阵营，`activeFactionIndex` 为指针，`round` 为轮次。
- **轮转规则（end-turn）**：
  1. `nextIdx = (activeFactionIndex + 1) % factionTurnOrder.length`
  2. 若 `nextIdx === 0`（即最后活跃阵营结束）→ `round + 1` 并 **统一重置全部单位行动点**；
  3. 否则仅切换 `activeFaction` 到下一阵营，**不重置行动点**。
  4. 兼容旧战局：`factionTurnOrder` 为空时退化为"全阵营结束即重置"。
- 参考：`combat.ts:438` end-turn；`battleStateFactory.ts` createBattleState 初始化。

### 2.3 行动点（Action Points）
- 每单位持有 `action_points: { MOVE: number, ATTACK: number }`。
- 标准值：**MOVE = 1、ATTACK = 1 / 轮**（每轮开始时重置，见 2.2）。
- 移动消耗 MOVE，攻击/技能消耗 ATTACK。
- 参考：`combat.ts` /action-points/consume、/action-points/:unitId。

## 5. 移动规则

移动是战棋最核心的基础动作：选中己方单位后，在棋盘高亮的可达格内点击落点，单位沿计算出的路径行走。移动消耗 **1 点 MOVE 行动点（每轮重置）**，与攻击/技能互相独立。

### 5.1 入口与坐标契约

- 路由：`POST /combat/:id/move`，payload `{ unit_id, target_q, target_r }`。
- 后端在 `battle.units`（Map，键为 `String(unitId)`）中按 `unit_id` 取单位，`unit.position` 为当前 `{q, r}`；成功后写回 `position` 并返回逐段 `path` 供前端平滑行走动画。
- 前端链路：`NewBattleView.executeMove(tq, tr)` → `combatAPI.move(id, {unit_id, target_q, target_r})` → 网关 `move` 路由（`combat.ts` 约 1089 行）→ `tsFindPath`（约 58 行）。

### 5.2 移动范围（核心公式，已修正）

单位移动力由两个字段承载（均来自 `currentStats`，原始量纲 0–99）：

| 字段 | 来源 | 含义 |
|------|------|------|
| `moveRange` | `currentStats.speed` = 副机体机动 + 载具机动之和 | 总机动（0–99） |
| `mobility` | `currentStats.mobility` = 副机体机动 | 机体机动（0–99） |

> **可走格数 = `max(1, round(rawMob / 10))`**，其中 `rawMob` 优先取 `mobility`（>0），否则取 `moveRange`，再否则兜底 3。
> 即原始 0–99 量纲的机动，除以 10 折算成"每回合可走多少格"（例如机动 60 → 6 格，机动 95 → 9–10 格）。**前端高亮预览与后端 `move` 路由使用同一公式，确保所见即所得。**

### 5.3 BFS 寻路（tsFindPath）

- 在 `state.map.cells` 构成的六角格集合内做 **BFS**，逐格累加地形 `move_cost` 作为路径代价，`cur.dist >= maxRange`（`maxRange`= §5.2 折算后的可走格数）即截断。
- 代价语义：`plain/moon`=1、`ruins/rubble/crystal/forest`=2、`mountain`=3、`water`=99（视为不可通行）。落点不得落在 `move_cost=99` 的水域。
- 占用判定：已被其它单位占据的格（`occ` 集合）跳过，不可作为落点（**单位自身起点除外**）。
- 防御性：`state.map.cells` 为空（地图数据缺失）时不再阻断移动，仅按 `maxRange` 与占用判定可达性。

### 5.4 阵营门控

- 受 `activeFaction` 门控：仅当前行动阵营（`state.activeFaction`）的单位可移动，否则返回 `NOT_YOUR_TURN`。
- 移动不重置行动点；仅 `end-turn` 按 §2.2 轮转时才统一重置全部单位 MOVE/ATTACK。

### 5.5 auto 型 Royroy 随动

主机移动成功后，若 `unit.royroy.deployed && unit.royroy.isAuto`，Royroy 自动重定位至主机落点邻域的空格（不消耗主机 MOVE，详见 §9）。

### 5.6 当前运行状态与已知缺陷（已定位并修复）

1. **「无法在棋盘上移动」根因**：原代码 `movementRange = unit.moveRow ?? unit.mobility ?? 3` 使用 **`??`（空值合并）**，`??` 不捕获数字 `0`。当部署单位的 `currentStats.speed` 未注入（如部署池 `stats` 缺 `speed`、或走 fallback `{mobility:5}`）时 `moveRange=0` → `movementRange=0` → `tsFindPath(maxRange=0)` 对任何目标都返回 `null` → 网关恒返回 `OUT_OF_RANGE`。**修复**：改用真值判断 `rawMob`（mobility→moveRange→3）并对折算结果取 `max(1, …)`，保证至少可走 1 格。
2. **「移动范围不对」根因**：折算公式三处互不一致——前端预览原写 `Math.floor(mobility/2)`（且注释却说 /10）、后端 `move` 路由原直接用原始 `moveRange`（未折算）、`combat-service` 的 `getMoveRange` 用 `Math.floor(mobility/2)`。原始 `mobility/moveRange` 为 0–99 量纲，未统一折算导致预览与实走范围相差数倍。**修复**：前端与后端统一为 `max(1, round(rawMob/10))`。
3. 修复代码已落地于 `combat.ts`（move 路由 + `tsFindPath` 空格兜底）与 `NewBattleView.vue`（移动高亮预览），**需重新部署后生效**（见 §14）。

## 6. 战斗与伤害系统

### 6.1 伤害类型（DamageType，5 种）
动能 kinetic / 光束 beam / 爆炸 explosive / 腐蚀 corrosive / 热熔 thermal。
- 各伤害类型受 **地形 `damage_kind_modifiers`** 与 **单位防御** 共同修正。
- 参考：`glossary-skill-config.json` damage_kinds。

### 6.2 暴击系统（crit）
- 每次攻击固定 **33.3% 暴击率**（`chance=0.333`）。
- 暴击倍率区间 **1.0 ~ 1.5**（`multiplier_min=1.0`，`multiplier_max=1.5`）。
- 参考：`glossary-skill-config.json` systems.crit。

### 6.3 伤害计算管道（damagePipe）
- 大一统伤害管道（`backend-gateway/src/damagePipe.ts`）：支持 dicescript 对接、层叠（Stacking）与互斥池。
- 执行顺序：**定语（Qualifier）→ 状语（Adverbial）→ 补语（Complement）**。
  - 定语：卡口/代价（如消耗 MOVE 行动点，失败则熔断）。
  - 状语：投骰判定（如 `1d6 >= 成功线` → 暴击）。
  - 补语：伤害加算（flat / dice_bonus）。
- 保底伤害 `GUARANTEED_DAMAGE = 1`；能量伤害倍率 `ENERGY_MULTIPLIER = 1.5`。
- 实战案例「稳定光束狙击」：`CONSUME_AP(MOVE>0)` → `1d6=6 暴击` → `基础伤害 +5，暴击追加能量 +5`。

### 6.4 高地优势
- 攻击方相对目标存在高度差时，按技能 `height_bonus_per_diff` 获得加成。

### 6.5 攻击入口现状（重要）
- 前端"攻击"按钮调用 `combatAPI.attack`（`POST /combat/:id/attack`），但 **网关无此路由**，当前返回 404。
- 可用的实战伤害入口：
  - `POST /combat/:id/skill`：以技能方式发起攻击/治疗/增减益。
  - `POST /combat/:id/damage`：直接造成伤害（含 Royroy 受击用 `damage_royroy` 动作）。
- 参考：`combat.ts:496` /damage、`combat.ts:568` /skill；`frontend/src/api/client.js:138`。

## 9. Royroy 浮游辅机（核心新机制）

Royroy 采用 **属性模型**：它是宿主单位的属性 `unit.royroy: RoyroyState`，**不是独立的 BattleUnit**。

### 9.1 RoyroyState 字段
`name` / `attack` / `defense`(默认 0) / `hp` / `maxHp` / `isAuto` / `deployMode:'follow'|'fixed'` / `status:'inactive'|'deployed'|'destroyed'` / `deployed`(已部署) / `q?` `r?` / `cooldownRound?`

- `isAuto`：技能含 `category==='auto'` 时为 true（随主机移动自动重定位）。
- `deployMode`：`follow`（跟随）/ `fixed`（定点不可动）。

### 9.2 动作入口（/action 路由）
- `deploy_royroy`：在宿主行动环节部署到 **相邻空格**。校验：status 可用、冷却未达、HP>0、activeFaction 匹配、目标相邻且未占用。**不消耗行动点**。
- `retrieve_royroy`：回收 Royroy，**回血至满**，`cooldownRound = round + 2`（两回合内不可再部署）。**不消耗行动点**。
- `damage_royroy`：对 Royroy 造成伤害；`hp ≤ 0` → `status='destroyed'`，**本局不可再部署**。

### 9.3 六个核心规则
1. 部署/回收 **不消耗** 行动点（MOVE/ATTACK）。
2. 仅 Royroy 攻击消耗宿主 **ATTACK** 行动点。
3. `auto` 型 Royroy：主机移动后自动重定位至邻域空格（跟随）。
4. 回收回血至满 + 冷却 `round+2`。
5. `hp=0` → `destroyed`，本局不可再部署。
6. `fixed` 型定点部署后不可移动。

### 9.4 前端联动
- 整备室（NewPreparationRoom）注入 `factionTurnOrder`。

## 10. 胜利条件

可配置 5 种（`victoryConditions` 数组，经 `/victory-conditions` 设置/读取）：

| 条件 | 判定 |
|------|------|
| `annihilate` 全歼 | 仅剩 1 个阵营有存活单位 → 该阵营胜 |
| `assassinate` 刺杀ACE | 某阵营 ACE 单位 hp≤0 → 对方胜 |
| `destroy_facility` 摧毁设施 | 设施格 `destroyed=true` → 攻击方胜 |
| `hold_position` 坚守 | 轮次 ≥ `holdRound`（默认 8）→ 防守方胜 |
| `capture` 占领据点 | 所有据点被单一阵营单位占据 → 该阵营胜 |

> ⚠️ 注意：判定逻辑 `turnManager.js checkVictoryConditions` 已存在，但 **网关实时对局未自动调用结算**；当前需玩家/前端依据局面人工确认胜负（配置可正常存取）。

## 12. 一局对战的标准流程

1. **整备阶段（Preparation）**：选地图/单位，配置 `factionTurnOrder`、可选 `victoryConditions`/`ace_unit`，上传部署池。
2. **部署阶段（Deploy）**：在棋盘点击放置单位（`/deploy-unit`），结束后 `end-deployment` 初始化 `round/activeFactionIndex/activeFaction`。
3. **战斗阶段（Battle）**：
   - 当前 `activeFaction` 阵营操作；选中单位可 **移动（/move）**、**释放技能（/skill）**、**直接伤害（/damage）**、**部署/回收 Royroy（/action）**。
   - `isMyTurn` 门控确保仅当前阵营可操作。
4. **结束回合（end-turn）**：按 §2.2 轮转；最后阵营结束进 `round+1` 并重置全部行动点。
5. **胜负判定**：依据 §10 配置，人工/前端确认（实时自动结算待接入）。

## 13. 已知缺口与后续路线

1. **`/attack` 主路由缺失**：前端攻击按钮 404；攻击需走 `/skill` 或 `/damage`。建议补齐 `POST /combat/:id/attack` 路由（对接 damagePipe/combatResolver）以恢复普通攻击。
2. **胜利条件未实时结算**：`checkVictoryConditions` 未接入网关对局循环，仅配置可存取。
3. **掩体系统未实装**：仅标签存在，无实际减伤/命中修正。
4. **装备独立耐久未全面接入**：`BattleEquipment` 类型已定义，攻击结算尚未完整使用。
5. **combat-service 的 TurnManager 与网关解耦**：部分精细判定（奇袭反击、ACE 校验）在 `combat-service` 中存在，但网关主战斗循环以自身 `combat.ts` 实现为准。
6. **移动缺陷已修复（2026-07-22）**：「无法在棋盘上移动」系 `movementRange = unit.moveRange ?? unit.mobility ?? 3` 中 `??` 不捕获 `0`，当 `currentStats.speed` 未注入时 `moveRange=0` 导致 `tsFindPath(maxRange=0)` 恒返回 `OUT_OF_RANGE`；「移动范围不对」系前端预览 `floor(mobility/2)`、后端原用原始 `moveRange`、combat-service `floor(mobility/2)` 三处折算互不一致（原始量纲 0–99）。修复：前后端统一 `max(1, round(rawMob/10))` 并对 `state.map.cells` 为空做兜底，详见 §5.6。代码已落地，需重新部署生效。
