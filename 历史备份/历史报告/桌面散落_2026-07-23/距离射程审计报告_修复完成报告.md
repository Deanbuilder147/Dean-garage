## 二、#1 修复详情：补齐 `/attack` 主路由

### 2.1 根因
- 前端 `NewBattleView.vue` 的 `executeAttack`（行 2542）与 `executeSkillAttack`（行 2692）均调用 `combatAPI.attack(route.params.id, payload)`。
- `client.js` 中 `attack: (id, data) => apiClient.post('/combat/${id}/attack', data)` → `POST /api/combat/:id/attack`。
- 但 `backend-gateway/src/routes/combat.ts` 只有 `/skill`、`/move`、`/damage`、`/action` 等路由，**不存在 `/attack`**，返回 404。
- 后果：点击攻击按钮 → 404 → 前端 `catch` 仅记日志并 `cancelAction()`，**攻击完全不结算、距离校验形同虚设**。

### 2.2 修复方案（`combat.ts:788-878`，新增 `POST /api/combat/:battleId/attack`）
复用已落地的 `/skill` 执行链路（`.cjs` 核心战斗引擎 + `hexDistanceOffset` 距离校验 + HP 写回），并做三处对齐：

1. **单位解析与身份映射**
   - 基础攻击：`attack_type` 为 `melee`/`ranged`（前端按 `attacker.range>1` 判定），按 `melee`/`ranged` 走内联技能定义。
   - 技能攻击：`attack_type='skill'` + `skill_id`（UUID）。从施法者已拥有技能 `exeCaster.skills` 中按 UUID 匹配出 glossary `key`，再交给引擎执行（与 `/skill` 语义一致）。

2. **内联基础攻击定义（驱动 `.cjs` 结算）**
   ```js
   inlineDef = {
     type:'active', label: at==='ranged'?'远程攻击':'近战攻击',
     category: at, action_type:'attack', attack_stat: at,
     damage_kind:'kinetic',
     cast_range: rangeVal, max_range: rangeVal, min_cast_range:0, min_range:0,
     base_damage: at==='ranged' ? (exeCaster.ranged||exeCaster.attack||0)
                                  : (exeCaster.melee ||exeCaster.attack||0),
     dice_type:'1d6', success_line:4, success_bonus_damage:0,
     is_manual_roll:false, target_filter:'enemy', requires_hit:true, height_bonus_enabled:true,
   }
   ```
   `rangeVal` 取 `casterUnit.currentStats.range`（缺失时近战兜底 1、远程兜底 2）。

3. **距离 + 最小距离校验（与 `/skill` 同一套逻辑，复用 `resolveSkillRange` + `hexDistanceOffset`）**
   - `dist > max` → `400 OUT_OF_RANGE`（携带 `distance`/`maxRange`）
   - `dist < min` → `400 BELOW_MIN_RANGE`（携带 `distance`/`minRange`）
   - 无目标 / 无法解析射程 → 跳过校验（安全默认，不阻断合法请求）
   - 基础攻击射程回退到 `currentStats.range`

4. **伤害结算与写回**
   - `executor.executeUniversalSkill(skillKey, exeCaster, exeTarget, ctx, inlineDef)`
   - 命中则将 `result.final_damage` 写回 `writeBackTarget.currentStats.hp`（前端 `refreshState()` 重新拉取生效）。

5. **响应结构对齐前端消费**
   前端 `executeAttack/executeSkillAttack` 读取 `result.data.combat_result.final_damage`，因此响应包装为：
   ```json
   { "success": true,
     "combat_result": { "triggered": true, "final_damage": 12, "attack_type":"melee",
                        "attack_stat":"melee", "damage_kind":"kinetic", "dice":{...}, "message":"..." },
     "skill_id": null, "surprise_triggered": false, "engine":"combat-service/.cjs" }
   ```

### 2.3 与 #2/#3 的协同
`/attack` 与 `/skill` **共用** `resolveSkillRange()`（行 624）与 `hexDistanceOffset()`（行 78）校验块。技能攻击经 `/attack` 传入 `skill_id` → 解析出 glossary `key` → `resolveSkillRange` 用单位已拥有技能里的 `max_range`/`min_cast_range` 校验。至此 #2（超距拦截）与 #3（最小距离拦截）在游戏内攻击路径上真正生效。

## 三、#2 / #3 / #4 修复回顾（上轮已部署）

### #2 + #3：后端 `/skill` 距离 + 最小距离校验（`combat.ts:616-746`）
- 新增 `resolveSkillRange(skillKey, skillId, exeCaster, skillDefinition)`：从 `skillDefinition` → 施法者已拥有技能 → 单位基础 `range` 三方解析；字段兼容 glossary 原生 `max_range/cast_range/min_cast_range/min_range` 与归一化 `range/range_max/range_min`（字符串 `"1-3"` 正确取 max/min）。
- 路由兼容前端真实字段别名 `attacker_id/target_id/skill_id/attack_type`。
- `dist>max → OUT_OF_RANGE`，`dist<min → BELOW_MIN_RANGE`。

### #4：前端范围预览排除 `min_range`（`NewBattleView.vue`）
- 新增 `getSkillRangeMin(skill)`，`skillRangeHexes` 的 BFS 增加条件 `cur.dist+1 >= rangeMin`，黄圈高亮与目标判定同步排除最小施放距离内的格。

## 四、验证结果

### 4.1 编译与部署
- `docker compose build --no-cache mecha-gateway`：**tsc 校验通过**（无类型错误）。
- 镜像：`mecha-universe-engine-mecha-gateway`（注意镜像名带前缀，需 `up -d --no-deps mecha-gateway` 拉起新镜像）。
- 网关 `/health` → HTTP 200；前端 → HTTP 200。

### 4.2 路由注册冒烟测试（服务器实跑）
```
POST /api/combat/test/attack  body={}                      → 400 {error:"VALIDATION_ERROR", message:"attacker_id 为必填项"}
POST /api/combat/test/attack  body={target_id:"x"}         → 400 {error:"VALIDATION_ERROR", message:"attacker_id 为必填项"}
```
→ 确认 `/attack` 路由已注册、前置校验生效（不再 404）。

### 4.3 引擎级结算验证（gateway 容器内复刻路由逻辑，同一套 `.cjs`）
| 场景 | 结果 |
|------|------|
| 近战 距离1，base_damage=12 | `triggered=true, final_damage=12`（掷骰失败仍保底出 base）✅ |
| 远程 距离2，base_damage=8 | `triggered=true, final_damage=8` ✅ |
| 近战 距离2（>max_range=1） | 引擎自身拦截：`melee攻击 需要 1~1 格距离（当前 2 格）`，`triggered=false` ✅（纵深防御） |

> 关键发现：`.cjs` 引擎**自身也按内联定义的 `max_range` 做距离校验**。即路由层与引擎层双重校验，即使请求绕过路由层，越界攻击也不会结算伤害（`final_damage=undefined` → HP 写回被 `>0` 守卫阻断）。

### 4.4 算法级校验（上一轮，node 复刻 `resolveSkillRange`/`hexDistanceOffset`）
- 近战 `max=1` 打距离 5 → `OUT_OF_RANGE`
- 投掷 `max=3/min=1` 距离 2 合法、距离 0 → `BELOW_MIN_RANGE`
- 字符串 `"1-3"` → `max=3, min=1`

## 七、残留事项与说明（非阻塞）

1. **前端错误呈现**：`/attack` 返回 `400 OUT_OF_RANGE/BELOW_MIN_RANGE` 时，前端 `catch` 仅在战斗日志面板记 `攻击失败: OUT_OF_RANGE` 并 `cancelAction()`，**不会绕过校验、不会错误结算伤害**。如需更醒目的 toast 提示，可后续增强（非阻塞）。
2. **前端目标选择已限制**：攻击目标点击受 `skillRangeHexes`/`moveRangeHexes` 高亮范围约束，叠加服务器权威校验形成双重保险。
3. **技能攻击（UUID→key）**：映射逻辑依赖 `exeCaster.skills` 中携带 `id`(UUID) 与 `key`(glossary key)，与 `/skill` 既有约定一致。
4. **其余已知缺口（与本审计无关）**：胜利条件 `checkVictoryConditions` 未接入网关实时结算；掩体系统仅标签未实装；装备独立耐久类型结算未全面接入。
