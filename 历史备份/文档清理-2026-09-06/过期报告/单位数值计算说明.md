# 任务二：单个棋子完整数值（主机体 + 全部装备）计算说明

> 调研对象：`mecha-universe-engine` 数值管线
> 日期：2026-07-22
> 结论：**目前数值在 Excel 导入阶段一次性算定**，战斗中使用的是导入结果；装备的"加成/耐久/抗性"子系统的代码存在但**未被接入**，故当前数值 = 所有部件四维之和的线性映射。

---

## 一、数值从哪来（完整管线）

```
Excel 原始文件
   │  parse (excel-parser.ts)
   ▼
ParsedResult.units = { 主机体, 跟随, 左手, 右手, 其它 }   ← 每个部件含 格斗/射击/结构/机动 四维
   │  normalizeParsedData (excel-schema-normalizer.ts)
   ▼
UnitStats = mapToUnitStats(Σ格斗, Σ射击, Σ结构, Σ机动)
   │  存为单位 .stats
   ▼
deploy-unit (backend-gateway/src/routes/combat.ts)
   │  unitData.stats → BattleUnit.currentStats
   ▼
战斗全程以 currentStats 为唯一数值真相（hp/attack/defense/speed/range/armor）
```

**关键事实**：`currentStats` 直接来自导入时算好的 `unit.stats`，战斗内**没有**再叠加装备Bonus。

---

## 二、详细计算公式（excel-schema-normalizer.ts）

### 第 1 步：跨所有部件累加四维
```js
const totalMelee     = sumPartStat(parsed.units, '格斗')   // 主机体+跟随+左手+右手+其它 全部相加
const totalShooting  = sumPartStat(parsed.units, '射击')
const totalStructure = sumPartStat(parsed.units, '结构')
const totalMobility  = sumPartStat(parsed.units, '机动')
```
`sumPartStat` 遍历 `parsed.units` 所有部件，把每个部件的对应四维数值累加（只要是 number 就加）。

### 第 2 步：四维 → UnitStats（线性映射，宪法红线，严禁硬编码偏离）
```js
hp     = structure * 5 + 20          // 0-99 → 20-515
armor  = floor(structure * 0.25)     // 结构派生护甲
shield = 0                           // ⚠️ 恒为 0，装备护盾从不计入
attack = melee * 2 + 5               // 0-99 → 5-203
defense= floor(mobility * 0.3)       // 机动派生防御
speed  = 2 + floor(mobility / 20)    // 0-99 → 2-6
range  = 1 + floor(shooting / 25)    // 0-99 → 1-4
```

### 汇总表
| 最终属性 | 公式 | 取值范围 |
|---------|------|---------|
| hp / maxHp | 结构×5+20 | 20 – 515 |
| armor | floor(结构×0.25) | 0 – 24 |
| shield | **0（固定）** | 0 |
| attack | 格斗×2+5 | 5 – 203 |
| defense | floor(机动×0.3) | 0 – 29 |
| speed | 2 + floor(机动/20) | 2 – 6 |
| range | 1 + floor(射击/25) | 1 – 4 |

## 三、装备到底怎么参与数值？

### 已生效的部分：四维被加进总和
装备部件（左手/右手/跟随/其它）的 `格斗/射击/结构/机动` 在 `sumPartStat` 里**已经和主机体一起累加**。
→ 所以一把高格斗的右手武器，确实会通过 `attack = 格斗×2+5` 提升攻击。这是装备影响数值的**唯一通道**。

### 未生效的部分：equipManager 加成系统（孤儿代码）
`services/combat-service/.../equipManager.cjs` 里有：
- `getWeaponBonus(unit, attackType)` → 读 `left_hand_melee` / `right_hand_melee` 等字段
- `getArmorDefense(unit)` → 读 `left_hand_defense` / `left_hand_type` 等
- `getResistances(unit)` / `consumeArmorDurability(unit)` → 读 `*_durability` / `*_resistance`

但这些字段（`left_hand_melee`、`left_hand_defense`、`left_hand_durability`、`left_hand_resistance`…）**从未被 Excel 归一器写入**。`buildAttributes` 里存的部件结构只有：
```js
parts[name] = { type, 格斗, 射击, 结构, 机动, skillSlots }   // 没有 per-slot bonus/durability/resistance
```
→ 因此 `equipManager` 对 Excel 导入的单位**拿不到任何数据，加成恒为 0**，是一套未被接入的死代码。战斗中 `currentStats` 也不引用它的输出。

### shield 永远是 0
映射里 `shield = 0` 写死，没有任何装备/四维能给它贡献值。

---

## 四、战斗中数值如何使用 / 变化

- `currentStats.hp` 会在受击时扣减（DamagePipe），归 0 判死亡。
- `attack` / `defense` / `speed` / `range` / `armor` 在战斗内基本只读不写（除非 BuffManager 施加临时 buff——需另查 BuffManager 是否改 currentStats）。
- **装备耐久、装备抗性、装备额外加成**目前都不参与实战（见上）。

---

## 五、为什么"数值好像不对"——疑似问题点（待你确认）

下面列出**当前实现与直觉可能不一致**的地方，供你判断哪条是你的"不对"：

1. **装备只通过四维间接生效**：若你预期"装备在四维之外再额外加攻击/防御"，那目前**不会**发生——只有部件四维被算进总和。
2. **shield 恒为 0**：任何带"护盾"语义的装备都不会体现在数值上。
3. **range 只看射击总和**：近战武器（高格斗低射击）不会提升 range，range 上限仅 4。
4. **speed 上限 6、attack 上限 203**：四维饱和后数值封顶，多堆无效。
5. **装备加成/耐久/抗性系统整体未接线**：`equipManager` 是孤儿，若策划文档要求装备提供独立加成/抗性，则**当前数值缺了这一块**。
6. **可能双重来源混淆**：如果某装备既在四维里贡献、又期望在 `equipManager` 里再加一次，会造成"重复计算"的观感——但目前 `equipManager` 没接，反而只算了一次（仅四维）。
7. **导入口径**：`sumPartStat` 把"其它"部件也全加进去了，若"其它"是弹药/消耗品而非属性部件，会被错误计入。
