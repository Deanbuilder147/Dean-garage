# NewBattleView vs NewBattlefieldView — 前端双页面对比分析报告

**生成日期**: 2026-06-19  
**分析对象**: `NewBattleView.vue` (战场端) vs `NewBattlefieldView.vue` (地图编辑器端)

---

## 一、综述

两个页面均基于 Vue 3 Composition API，使用六角格战场渲染管线，共享 `hexUtils.js` 的核心数学基础设施。但它们在功能定位、架构复杂度、布局模式和交互逻辑上存在显著差异。

- **NewBattleView.vue**: 2801 行 — 完整的战斗回合制交互页面，包含阵营管理、单位选择/移动/攻击、技能释放、部署系统。
- **NewBattlefieldView.vue**: 607 行 — 轻量级地图编辑器，专注于地形绘制与地图导出。

---

## 二、共同区域 (Common Ground)

### 2.1 共享的 hexUtils.js 导入

两者均从 `../utils/hexUtils.js` 导入以下模块：

| 导入项 | 说明 |
|--------|------|
| `HEX_WIDTH`, `HEX_HEIGHT`, `HEX_APOTHEM`, `HEX_RADIUS` | 六边形几何常量 |
| `DEFAULT_SPACING_H`, `DEFAULT_SPACING_V`, `DEFAULT_OFFSET_FACTOR` | 间距默认值 |
| `pointyTopCenter`, `pointyTopToHex` | 尖顶六边形坐标转换核心函数 |
| `drawHexPath` | 六边形路径绘制 |
| `UNIVERSAL_TERRAIN_MAP` | 地形字典（16种地形） |
| `convertMapFormat` | 地图格式转换 |
| `ISO_DEFAULTS` | 等距矩阵基准参数 (shearX=0.25, shearY=0.44, scaleX=1.00, scaleY=0.39) |

### 2.2 Canvas 渲染管道

两者采用完全相同的 Canvas 渲染管道结构：

- Canvas 容器层级: `.game-canvas-sandbox` > `.canvas-container` > canvas
- CTM 变换链: `ctx.translate(offsetX, offsetY)` → `ctx.scale(scale, scale)` → `ctx.transform(ISO.scaleX, ISO.shearY, ISO.shearX, ISO.scaleY, 0, 0)`
- 每帧调用 `draw(hlQ, hlR)` 进行全量重绘
- 使用沙盒容器 `.game-canvas-sandbox` 作为 CSS `contain: layout` 边界
- 坐标工具函数包装: `hexToPixel(q, r)` / `pixelToHex(px, py)`

### 2.3 事件系统

两者共享相同的事件绑定范式：

- **拖拽模式**: `mousedown` 记录起点 → `window.addEventListener('mousemove/mouseup')` 全局绑定防止鼠标出界中断
- `_windowDragMove` / `_windowDragEnd` 闭包变量管理拖拽生命周期
- `isDragging` 标志区分点击与拖拽
- `wheel` 事件处理缩放（`preventDefault` + 缩放到指定中心点）
- `mousemove` 更新 hover 坐标 → `draw(hlQ, hlR)` 重绘高亮

### 2.4 响应式状态

| 状态 | 说明 |
|------|------|
| `scale` | 缩放比例 (范围 0.2~3) |
| `offsetX` / `offsetY` | 相机平移量 |
| `hoverCoord` | 鼠标悬停坐标字符串 |
| `canvasWrapper` / `canvasContainer` | DOM refs |
| `ISO` | 等距矩阵参数引用 |

### 2.5 Vue 基础设施

| 项目 | 说明 |
|------|------|
| `useRouter` / `useRoute` | 路由访问 |
| `inject('sidebarActionLog')` | 日志管道 |
| `addLog(type, message)` | 日志记录 |
| `formatCoord(q, r)` | 坐标格式化 (colToLetter + rowIndex) |
| `hexToRGBA(hex, alpha)` | 颜色转换工具 |

## 三、差异分析 (Key Differences)

### 3.1 架构规模

代码总量差异约 **4.6 倍**。

### 3.2 布局结构

#### NewBattleView (战场端) — 四面板布局

- 外层 `.dm-battle-layout { display: flex; height: 100vh }`
- **左**: TheSidebar 组件 (侧边栏, 外部组件)
- **中**: `.dm-main { flex: 1 }` — Canvas + 工具栏 + 底部阵营盒
- **右**: `.dm-action-panel` (200px) — 部署池、战斗日志

#### NewBattlefieldView (编辑器端) — 单列垂直流式

- 外层 `.bf-editor-layout` (Block 布局)
- 顶部: 文件栏 (加载/保存/导出/重置)
- 中: Canvas 区域
- 底: 工具栏 (地形画笔、间距滑块、缩放按钮)

### 3.3 Canvas 创建方式

| | 战场端 (BV) | 编辑器端 (BF) |
|---|---|---|
| 创建方式 | 模板声明 `<canvas ref>` | JavaScript `document.createElement()` |
| 尺寸初始化 | `onMounted` 中读取容器尺寸后设置 | `initCanvas` 中手动设置 `width`/`height` |

### 3.4 数据源

| | 战场端 (BV) | 编辑器端 (BF) |
|---|---|---|
| API | `combatAPI`, `hangarAPI` | `mapAPI` |
| 核心数据 | `battleState` → `cells` + `units` | `battlefield` → `terrainMap` |
| Store | `useUserStore` | 无 |

### 3.5 默认网格

| | 战场端 (BV) | 编辑器端 (BF) |
|---|---|---|
| 默认网格 | 10×10 | 15×10 |

### 3.6 缩放行为

| 维度 | 战场端 (BV) | 编辑器端 (BF) |
|------|-------------|---------------|
| 缩放锚点 | ISO 逆矩阵 `worldCenter.wx/wy` | 纯 2D `offset` 插值 |
| Wheel 步进 | ×0.9 / ×1.1 | ×0.92 / ×1.08 |
| `zoomReset` | 自适应内容尺寸 | `scale=1` + 重居中 |
| 按钮缩放步进 | ×1.2 / ÷1.2 | ×1.08 / ÷0.92 |

### 3.7 交互事件差异

| 事件 | 战场端 (BV) | 编辑器端 (BF) |
|------|-------------|---------------|
| click | 多分支: 部署/移动/攻击/选择单位/显示格子信息 | 单分支: 涂抹当前画笔地形 |
| 右键 | 无特殊处理 | 擦除地形 (`delete terrainMap`) |
| 光标样式 | 默认 `'grab'` → 拖拽时 `'grabbing'` | 默认 `'crosshair'` → 拖拽时 `'grabbing'` |
| mouseleave | 清空 `hoverCoord` + `draw()` | 清除 `hoveredQ/hoveredR` + `draw()` (不重置 `isDragging`) |
| 事件绑定方式 | `canvas.onclick` + `canvas.addEventListener` 混合 | 全部使用 `addEventListener` (更规范) |

### 3.8 生命周期与响应式

| 维度 | 战场端 (BV) | 编辑器端 (BF) |
|------|-------------|---------------|
| `onMounted` | 加载战斗状态 → 判断阶段 → 加载部署池/冷却/胜利条件 → `initCanvas` → `setupEvents` | 加载地图数据 → `initCanvas` (内部调用 `setupEvents`) |
| `onUnmounted` | 无 (未导入) | 已导入但未使用 |
| `watch` | 监听 `battleState.faction_turn` 更新阶段文本 | 无 |
| `nextTick` | 2 次: Canvas DOM → `initCanvas` → `setupEvents` | 1 次: 数据加载后 → `initCanvas` |

### 3.9 CSS 样式

| 维度 | 战场端 (BV) | 编辑器端 (BF) |
|------|-------------|---------------|
| 样式行数 | ~957 行 | ~56 行 |
| 全局 reset | 无 (依赖外部样式) | `* { margin:0; padding:0; box-sizing:border-box }` |
| 布局策略 | Flexbox 四面板 (`display: flex`) | Block + Flex 单列流式 |
| 样式组织 | 区域分组注释 (`/* LEFT SIDEBAR */`, `/* MAIN CONTENT */`, `/* ACTION PANEL */` 等) | 组件级平铺 (无分组注释) |
| `pointer-events` | 工具栏/面板/按钮有 `pointer-events: auto` (穿透层) | 部分控件有 `pointer-events: auto` |

### 3.10 间距参数

| 维度 | 战场端 (BV) | 编辑器端 (BF) |

## 五、优化建议

### 5.1 统一化建议

1. **`getWorldPos` 返回值格式统一** — 两页面返回格式不同，建议抽象为公共工具函数
2. **Canvas 创建方式统一** — 建议统一使用模板声明方式，避免编辑器端的 `document.createElement` 模式
3. **Wheel 缩放步进值统一** — 0.9/1.1 vs 0.92/1.08，建议统一为一个常量

### 5.2 编辑器端补漏

1. **`onUnmounted` 事件清理** — 已导入但未实现，缺少 `removeEventListener` 清理，有内存泄漏风险
2. **`zoomIn/zoomOut` 缺少锚点补偿** — 缩放时未像战场端那样计算世界坐标中心作为锚点

### 5.3 战场端优化

1. **事件绑定统一** — `onclick` + `addEventListener` 混用应统一为 `addEventListener`
2. **`draw()` 函数拆分** — 过于庞大 (BFS + 单位 + 技能 + HP)，建议拆分为独立 draw 子函数
3. **添加 `onUnmounted` 清理** — 防止切换页面时的内存泄漏
