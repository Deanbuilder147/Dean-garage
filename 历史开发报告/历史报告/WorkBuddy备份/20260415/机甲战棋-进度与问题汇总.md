## 二、问题汇总与解决方案

### 问题1: VALUES问号数量不匹配

| 项目 | 内容 |
|------|------|
| **文件** | `services/hangar-service/src/routes/units.js` |
| **症状** | `37 values for 40 columns` |
| **原因** | create-from-json API的INSERT语句中，列名有40个但VALUES只有37个问号 |
| **定位** | 第823行的VALUES子句 |
| **修复** | 将37个 `?` 改为40个 `?` |
| **状态** | ✅ 已修复 |

### 问题2: cleanSkills空值访问错误

| 项目 | 内容 |
|------|------|
| **文件** | `services/hangar-service/src/routes/units.js` |
| **症状** | `Cannot read properties of null (reading 'name')` |
| **原因** | cleanSkills函数中直接访问 `s.name`，但s可能为null |
| **定位** | 第797-805行的cleanSkills函数 |
| **修复** | 添加可选链和空值检查 |
| **状态** | ✅ 已修复 |

### 问题3: 前端预览数据访问错误

| 项目 | 内容 |
|------|------|
| **文件** | `frontend/src/views/UnitEditorView.vue` |
| **症状** | `Cannot read properties of null (reading 'name')` |
| **原因** | 在 `previewData.value = null` 之后访问了 `previewData.value.name` |
| **定位** | 第912-918行 |
| **修复** | 先保存名称变量，再清空数据 |
| **状态** | ✅ 已修复 |

## 四、Excel导入新流程说明

### 流程对比

**旧流程:**
```
选择文件 → 立即上传 → 后台解析 → 直接入库
```

**新流程:**
```
选择文件 → 解析预览 → 确认导入 → 保存入库
    ↓          ↓           ↓         ↓
 弹窗打开   /parse-excel  显示预览  /create-from-json
```

### 新增API

#### 1. parse-excel (解析Excel)
- **端点:** `POST /api/hangar/units/parse-excel`
- **功能:** 上传Excel文件，返回JSON预览数据

#### 2. create-from-json (保存棋子)
- **端点:** `POST /api/hangar/units/create-from-json`
- **功能:** 接收JSON数据，保存到数据库
