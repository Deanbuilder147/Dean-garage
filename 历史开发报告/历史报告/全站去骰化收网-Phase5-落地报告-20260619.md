## 3. 三个关键踩坑与修复

### 3.1 路由顺序冲突 → API 返回 "未授权"

**现象**: 请求 `/api/combat/glossary-config` 返回 `{ "error": "未授权" }`

**根因**: Express 路由 `router.get('/:id', authenticate, ...)` 在 glossary 路由之前，`/glossary-config` 被 `:id` 参数捕获并触发认证中间件。

**修复**: 将 glossary 路由（GET 和 POST）移到 `router.get('/:id', ...)` 之前。

```javascript
// 修复前：glossary 在 /:id 之后，被 /:id 捕获
router.get('/:id', authenticate, ...)   // ← 先匹配到 glossary-config
router.get('/glossary-config', ...)      // ← 永远不会到达

// 修复后：glossary 在 /:id 之前
router.get('/glossary-config', ...)      // ← 精确匹配优先
router.get('/:id', authenticate, ...)    // ← 只匹配真正 ID
```

### 3.2 POST 覆写导致数据丢失

**现象**: `POST { skills: { block: { reduction: 5 } } }` 后，sweep、throw 等 8 个其他技能消失。

**根因**: 原代码使用 `fs.writeFileSync` 直接覆写，前端/部分更新请求缺少其他字段。

**修复**: 实现 `deepMerge(target, source)` 深度合并策略：

```javascript
function deepMerge(target, source) {
  const result = { ...target };
  for (const [key, value] of Object.entries(source)) {
    if (value && typeof value === 'object' && !Array.isArray(value)) {
      result[key] = deepMerge(result[key] || {}, value);
    } else {
      result[key] = value;
    }
  }
  return result;
}
```

**验证**: 只修改 `block.reduction=5`，sweep/throw 等 8 个技能和后端私有的 `_format` 字段完整保留。

### 3.3 Docker 容器代码未更新

**现象**: 修改磁盘文件后 API 不生效。

**根因**: Docker 镜像在构建时 `COPY` 源代码，修改磁盘文件后需重新 `docker compose build` + 重建容器。

**修复**: 每次源代码变更后执行：

```bash
docker compose build combat-service
docker stop mecha-combat && docker rm mecha-combat
docker compose up -d combat-service
```

## 4. 数据水管流程

### 4.1 读流程 (GET)

```
GlossaryView.vue.mounted()
  → glossaryAPI.getConfig()
  → GET /api/combat/glossary-config
  → Nginx proxy_pass → combat-service:3004
  → battles.js router.get('/glossary-config')
  → configLoader.getGlossaryConfig()
  → fs.readFileSync('glossary-skill-config.json')
  → JSON.parse → 返回前端
  → Vue 渲染 9 skills + 3 systems 分类卡片
```

### 4.2 写流程 (POST)

```
用户操作: [编辑模式] → 修改参数 → [保存并同步规则]
  → glossaryAPI.saveConfig({ skills: { block: { reduction: 5 } } })
  → POST /api/combat/glossary-config
  → battles.js router.post('/glossary-config')
  → 参数存在性验证 (skills 或 systems 至少一个)
  → configLoader.saveGlossaryConfig(body)
  → deepMerge(diskData, body) — 保留未修改字段
  → fs.writeFileSync 原子写入
  → 返回更新后的完整配置
  → 前端重新渲染
```

### 4.3 运行时消费

```
combatResolver / skillExecutor / turnManager
  (每次战斗触发时)
  → configLoader.getSkillConfig('block')
  → fs.readFileSync → JSON.parse → 提取 block 节点
  → 返回 { reduction: 2, value: 0.5, ... }
  → 注入技能计算逻辑
```

**关键优势**: 无需重启 Docker 容器或 Node 进程，修改即刻在下次战斗/下次打开编辑器时生效。

## 7. 后续建议

1. **并发写入保护**: 当前无锁，多管理员同时编辑可能产生竞态。建议添加文件锁或乐观锁（ETag/版本号）。
2. **配置版本历史**: 每次保存记录变更，支持回滚。
3. **配置校验**: 对数值范围（如 `reduction 0~100`）在后端做白名单校验，防止非法配置注入。
4. **WebSocket 推送**: 配置变更后推送给所有在线 GM，避免手动刷新。
