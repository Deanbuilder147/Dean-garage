> 生成时间：2026-07-27
> 范围：地形画笔调色板、自定义地形管理弹窗、后端战斗管道（glossary / terrainMovement / terrainCosts / skillExecutor）、地图落库与战场读取全链路
> 结论先行：**你的第 2 步（地图只填 id）完全吻合；第 1 步（统一入库并投送到各处）和第 3 步（战场由 id 解析属性）在程序里并未按你的设想实现。** 程序没有"单一地形库"作为真相源，而是 4 套硬编码表（A/B/C/D）+ 1 套已弃用游离表（E），且地图内嵌的地形属性在落库时被丢弃，战场解析属性时也不读地图内嵌定义。

## 一、数据流程逐步核对

### 步骤 1：地形定义生成 → 入库 → 投送到各处（程序实际）
- **不存在"生成地形并推送到各处"的统一流程。**
- 地形定义分散在 4 处（见第二节 A/B/C/D），互相独立、无自动同步：
  - **A 画笔**（`hexUtils.js · UNIVERSAL_TERRAIN_MAP`）：前端硬编码 20 种，含 `cost/height/color`。
  - **B 自定义地形管理**（`NewBattlefieldView.vue · loadTerrainDefinitions`）：合并 glossary(C) 的 10 种 + A 的 10 种 seed，编辑后 `saveTerrainConfig` 只回写 **C(glossary)**。
  - **C glossary**（`glossary-skill-config.json · terrains`）：后端战斗引擎（防御/破坏）实际读取的表，仅 10 种。
  - **D 移动消耗**（`terrainCosts.ts · TERRAIN_COST`）：网关寻路读取，20 种，硬编码且与 A 对齐。
  - **E `terrainMovement.cjs`**：第 5 套游离表，已弃用未接线。
- **"管理"保存推送到哪里？** 只推到 **C(glossary)**。C 被战斗引擎读取 → 所以在"管理"里改防御/可破坏**会影响战斗**。但它**不会**回流到：A(画笔/渲染)、D(移动消耗)、E、或地图本身。
- **新增地形更尴尬**：在"管理"里"添加地形"会写入 C，于是该地形出现在管理列表与战斗引擎里；但 A(画笔硬编码)没有它 → 渲染器（`HexGridCanvasEngine` 读 A）拿不到颜色/名称（走兜底）；D 没有它的 move cost（走默认）；地图画笔按钮虽借 `allTerrainTypes` 能显示，但画出来的格在战斗里属性残缺。

### 步骤 2：地图用画笔填地形 `id`（程序实际）
- **✅ 完全吻合"地图只存 id"。**
- 落库链路（已代码核实）：
  - 前端 `NewBattlefieldView.saveMap`（line 724-738）发出 `{ terrain: {"q,r": id}, terrain_defs: <全量属性>, hex_config }`。
  - 后端 `maps.ts · terrainDictToCells`（line 68-81）把 `terrain` dict 转成 `cells: [{q, r, terrain: <id>}]`。
  - `maps.ts` UPDATE/INSERT（line 274-289）只写 `cells` 列 = 上面的数组，**不含任何属性**。
- **⚠️ 附带损失**：前端发出的 `terrain_defs`（你以为"投送到各处"的那份属性）在后端**无对应列、被静默丢弃**（`maps` 表结构 line 272-287 无 `terrain_defs` 字段）。即"地图自带地形属性"在程序里并未持久化。

### 步骤 3：战场读地图 id → 解析属性 → 计算（程序实际）
- 战场读 id 正确：`combat.ts · buildTerrainMap`（line 42-49）遍历 `battle.map.cells`，取 `c.terrain`（id）建 `"q,r"→terrainId` 图。
- **属性解析来源 ≠ 统一库，也 ≠ 地图内嵌 defs：**
  - **移动力 / 寻路**：`combat.ts · tsFindPath`（line 114-165）→ `terrainCost(terrainOf[nk])` → **D(`terrainCosts.ts`, 20 种)**。wall=99 不可通行。
  - **防御减伤 / 可破坏**：`skillExecutor._getTerrainDefenseBonus / _applyTerrainDamage` → `_getTerrainConfig()` = `getGlossaryConfig().terrains` → **C(glossary, 仅 10 种)**。
  - **10 种地形（void/wall/base/mothership/repair_station/spawn_*/desert/space）在 C 中无定义** → 解析为默认（防御 0、不可破坏）。编辑器能画、地图能存 id、但战斗无语义。
- 结论：**战场从未读取地图内嵌的 `terrain_defs`（本来也没存进去）**，而是从 C(防御/破坏)+D(移动) 两套硬编码表反查 id。

## 四、后端管道统一核查（C / D / E）

### 4.1 移动消耗：A ≡ D（已对齐），与 C 冲突
- `terrainCosts.ts` 注释明确"与前端 `UNIVERSAL_TERRAIN_MAP.cost` 对齐"。实测 20 项 cost 与 A 完全一致。
- 但 **C(glossary) 的 `move_cost` 与之冲突**：`water` C=99 / A·D=2.5；`fortress` C=1 / A·D=5。
- 更严重：**C 的 `move_cost` 实战根本不参与寻路**（`_getTerrainMoveCost` 仅有定义、零调用），只在管理弹窗展示。于是"管理"弹窗里 fortress 显示 move_cost=1，玩家真实移动却被收 5 点——**录入与读取脱节**。

### 4.2 防御减伤 / 可破坏：唯一真相 = C（仅 10 种）
- 战斗防御减伤、可破坏判定全部走 `getGlossaryConfig().terrains`（10 种）。
- 10 种之外的地形（void/wall/space/base/mothership/repair_station/spawn_*/desert）**在战斗引擎中无定义** → 默认 `defense_bonus=0`、不可破坏。编辑器能画 20 种，但战斗只认 10 种。

### 4.3 `terrainMovement.cjs`（E）：游离第四表
- 与 C 字段名不同（`defense` vs `defense_bonus`、`cost` vs `move_cost`），实战读不到。
- 但其数值与 C 大规模冲突（见下节），一旦被误接线将引发灾难性不一致。

## 八、整改建议（目标：让你的 3 步逻辑在程序里真正成立）

**总目标：确立单一地形真相源，让"步骤1 入库 → 步骤2 填 id → 步骤3 由 id 反查同一份定义"闭环。**

1. **扩表到 20（补步骤3缺口）**：将 10 个"额外"地形（space/void/base/mothership/repair_station/spawn_*/desert/wall）正式写入 `glossary.terrains`，补齐 `move_cost`/`defense_bonus`(=0)/`is_destructible`(false)/`max_hp`(0)/`damage_kind_modifiers`(全1.0)。使战场对任意 id 都能解析到属性。
2. **统一 move_cost（补步骤1/3 一致性）**：以 A/D 为权威（驱动真实寻路），把 C 的 `water` 改 2.5、`fortress` 改 5，使 C 与 A/D 一致。
3. **让"管理"保存真正"投送到各处"（补步骤1）**：`saveTerrainConfig` 回写 C 的同时，应同步刷新 A(画笔/渲染，可由前端拉取 glossary 派生) 与 D(移动表)；或改为**前端只读 glossary 派生画笔**，消除 A 与 C 双份硬编码。
4. **地图持久化地形定义（补步骤2 附带属性）**：给 `maps` 表加 `terrain_defs` 列，落库前端发来的全量定义；战场 `buildTerrainMap` 优先用地图内嵌 defs，缺失时回退 glossary（实现你"地图携带属性、战场就地解析"的设想）。
5. **退役 E（terrainMovement.cjs）**：删除或改为 `getGlossaryConfig().terrains` 的薄封装；删除 `combatIntegrator.cjs` DEPRECATED 文件，消除游离第四表。
6. **颜色对齐**：将 C 的 10 个颜色同步为 A 的 TERRAIN_COLORS（或反向），消除 6 项展示差异。
7. **加一致性校验**：启动或 CI 中加入 A/B/C/D diff 断言，任一处冲突即告警，防止再次漂移。
8. **前端暴露可破坏状态**：画笔/管理弹窗展示 `is_destructible`/`max_hp`，让玩家知晓防御圈等可被摧毁。
