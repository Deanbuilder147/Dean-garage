# 战场内棋子形象读取链路审计报告

> 日期：2026-07-31
> 范围：`frontend/src/views/NewBattleView.vue`（Canvas 绘制）、`frontend/src/resolvers/unitSpriteResolver.js`、`backend-gateway/src/routes/combat.ts`（deploy-unit）、`backend-gateway/src/battleStateFactory.ts`（createBattleUnit）、`backend-gateway/src/routes/rooms.ts`（start 路由）
> 直接回答：**局内棋子形象链路确实是"优先读所有棋子的七视图"，这一设计是对的；但当前线上它没生效，于是回退链路一路掉到"阵营 Logo"——而该 Logo 是按棋子固有 faction（经 factionRoles 对应到轮转角色）去请求 logoUrl 的，文件根本不存在，所以在 Network 里看到一堆 404。** 并不存在一条"专门读 Rotation Role logo"的代码路径，你看到的 404 是阵营 Logo 回退。

---

## 一、局内棋子形象的完整读取链路（4 级降级金字塔）

绘制函数位于 `NewBattleView.vue` 的 Canvas 绘制块（约 L2281-2371），每个棋子单位按以下优先级选图：

| 优先级 | 来源 | 代码 | 资源路径 |
|---|---|---|---|
| **1（最高）** | **七视图** | `resolveSevenView(unit.viewUrls \|\| unit.view_urls, direction)` (L2283) | 后端下发的 `view_urls`（七视图上传图） |
| 2 | 2D 切图精灵 | `unitSpriteResolver.getTexture(unitCode, direction, state)` (L2309) | `/assets/sprites/units/{unitCode}_{dir}_{state}.png` 或 `/api/hangar/units/sprites/...` |
| 3 | **阵营 Logo** | `getFactionLogoImage(unit.faction)` (L2333) | `loadFactionLogos()` 从 `hangarAPI.getFactions()` 取 `f.logoUrl`（按 `f.code` 即固有 faction） |
| 4（兜底） | 纯矢量圆 + 首字母 | (L2354-2370) | 无网络请求，永远成功 |

绘制分支（L2284-2371）：
- 若七视图加载成功（`_hasSeven`）→ 直接画七视图，**完全跳过精灵与 Logo**（L2285-2306）。
- 否则若精灵存在 → 画精灵（L2314-2321）。
- 否则若阵营 Logo 存在 → 画 Logo + 首字母（L2333-2353）。
- 否则 → 纯矢量圆 + 首字母（L2354-2371）。

**结论：七视图是第一优先级，链路确实指向"读取所有棋子的七视图"。** 只要你上传的七视图 URL 能正确到达每个 `BattleUnit.viewUrls`，棋子就会用七视图渲染。

## 二、七视图为何没生效（你看到 Logo 404 的根因）

### 2.1 七视图数据传播链（设计上是通的）
1. 准备房 `rooms.ts` start 路由构建 `pendingUnit` 时写入 `view_urls`（**Bug 1 修复，本地已改，见下**）。
2. 部署阶段 `combat.ts` deploy-unit（L2231/2253）读取 `unitData.view_urls ?? unitData.viewUrls`，解析后传给 `createBattleUnit({ viewUrls })`。
3. `createBattleUnit`（`battleStateFactory.ts:210`）把 `viewUrls: params.viewUrls` 写进 `BattleUnit`。
4. 前端 `normalizeUnit`（L1161-1163）把 `u.view_urls` 归一成 `u.viewUrls`。
5. 绘制时 `resolveSevenView(unit.viewUrls || unit.view_urls, direction)` 取图。

### 2.2 线上断点：Bug 1 修复尚未部署
- 上一轮我已在 `rooms.ts` start 路由补了 `view_urls`（及 `codename`/`attributes`，含 `parts`），但**该改动停留在本地编辑器，未部署到服务器**（部署用的 SSH 命令在你那次被取消）。
- 因此**线上 `pendingUnit` 没有 `view_urls`** → deploy-unit 读到 `undefined` → `createBattleUnit` 写入 `viewUrls: undefined` → 每个部署棋子的 `unit.viewUrls` 为空。
- `resolveSevenView(undefined)` 直接 `return null` → `_hasSeven=false` → 七视图整条路被跳过。
- `resolveSevenView` 本身写得是健壮的（L1009-1034）：支持数组/对象两种格式、按 `direction` 索引、`onerror` 会触发重绘降级。问题不在它，而在**输入 `viewUrls` 为空**。

### 2.3 于是掉进"阵营 Logo"回退（Network 里的 404）
- 七视图为空后，二级精灵 `/assets/sprites/units/{unitCode}*.png` 通常也不存在（无对应切图资源）→ 404。
- 三级 `getFactionLogoImage(unit.faction)`（L2333）：`unit.faction` 是**棋子固有阵营**（earth/maxion/balon），由 `loadFactionLogos()`（L1599-1631）预先为每个 `faction` 请求 `f.logoUrl`（L1606-1609）。
- 这些 logo 文件在服务端并不存在 → `<img src=logoUrl>` 返回 **404**（这就是你在 Network 里看到的"读不到 logo"）。
- 因为 `getFactionLogoImage` 只在 `img.complete && naturalWidth>0` 时才返回图像（L1591-1592），404 的图不会渲染，最终落到四级纯矢量圆 + 首字母。

### 2.4 关于"Rotation Role 对标的 logo"
- **代码里并不存在任何按 Rotation Role（attack/defense/ambush）取 logo 的路径**。唯一取 logo 的地方是 `getFactionLogoImage(unit.faction)`，key 是**固有 faction**。
- 你之所以觉得它"对标 Rotation Role"，是因为 `battle.factionRoles` 把固有 faction 映射到轮转角色（earth→attack、maxion→defense、balon→ambush）。Network 里请求的是 `earth/...logo` 这类**固有阵营 logo URL**，视觉上它"对应"到某个角色，所以被理解为"角色 logo"。本质是：阵营 logo 回退 + 该 logo 文件缺失 = 404。

## 三、重要澄清：链路是否"指向读取所有棋子的七视图"？

**是，设计意图就是如此，且代码已正确实现优先级**——七视图 > 精灵 > 阵营 Logo > 矢量。当前你看到 Logo 404，不是因为代码改去读角色 logo，而是因为：
1. 线上的 `BattleUnit.viewUrls` 为空（Bug 1 修复未部署），七视图这一级被整段跳过；
2. 回退到的"阵营 Logo"按固有 faction 请求 `logoUrl`，而该文件不存在，产生 404。

修复后（部署 Bug 1 + 保证七视图 URL 有效），棋子会直接走第一级七视图，根本不会去碰 Logo。

## 五、修复建议

1. **（关键）部署 Bug 1 修复**：把 `rooms.ts` start 路由补的 `view_urls`（及 `codename`/`attributes`）同步到服务器并重建 `mecha-gateway`。这样 `BattleUnit.viewUrls` 才有值，七视图第一级才会生效。
2. **确认七视图 URL 有效**：`resolveSevenView` 支持数组或 `{方向: URL}` 两种格式（L1014）。上传的七视图需是可达的 HTTP URL；若 URL 本身 404，仍会掉到 Logo/矢量。
3. **消除 Logo 404 噪音（可选）**：`loadFactionLogos`（L1606）在 `f.logoUrl` 不存在时应跳过请求，避免无意义的 404；或补上真实 logo 资源。但按你的意图，**棋子主形象应统一用七视图**，阵营 Logo 只是降级层，不必作为主形象。
4. **验证口径**：部署后进入战场，Network 应只出现七视图 URL 请求（成功），不再有 `factions` 的 logoUrl 404；棋子显示为上传的七视图。

## 六、补充：与上一版 faction 报告的关系
- 上一份报告已指出：`BattleUnit` 只带固有 `faction`，回合门控靠 `resolveRole` 还原轮转角色。本报告的"阵营 Logo"恰好也按固有 `faction` 取图——这与上一份"技能/敌我判定读固有 faction"是同一类问题。
- 但**棋子形象的正确来源应是七视图，而非 faction/role 任何形式的 logo**。所以这里不需要把 Logo 改成"按 role 取"，而是让七视图链路生效即可。
