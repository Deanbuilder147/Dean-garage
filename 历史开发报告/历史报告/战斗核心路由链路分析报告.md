# 战斗核心完整路由链路分析报告

> 生成时间：2026-07-25
> 分析范围：从「数值提取 → 伤害结算 → 结果展示/记录 → 跨容器数据代号一致性」全链路
> 涉及容器/服务：`mecha-frontend`(8081) · `mecha-gateway`(3006) · `combat-service`(.cjs 引擎) · `mecha-battle-db`(PG，仅单位/地形/词条库) · `onlineBattleAPI`(3006 SQLite，联机战局历史)

## 0. 全链路总览图（请求 / 数据流）

```
[前端 NewBattleView.vue]  onHexClick → executeAttack(target)
   │  ① 仅 tactical模式 或 已选技能 才发起；否则查看信息
   │  ② isMyTurn(attacker) 门控（阵营回合）
   │  ③ duelCheck 预检（斩杀词条前端驱动）
   │  payload: { attacker_id, target_id, attack_type:'ranged'|'melee' }
   ▼  axios (baseURL /api, Vite proxy → 3006)
[网关 mecha-gateway]  POST /api/combat/:battleId/attack   (combat.ts:862)
   │  toExecutorUnit(caster/target)  ← 内存 battleStore 取 BattleUnit
   │  inlineDef 构造（基础攻击 melee/ranged）
   │  距离/最小距离校验（hexDistanceOffset）
   │  getSkillExecutor().executeUniversalSkill(skillKey, caster, target, ctx, inlineDef)
   ▼  require('combat-service') 经 combatBridge
[引擎 combat-service]  skillExecutor._executeAttackSkill  (伤害公式在此算出)
   │  读取：attacker[attackStat] / dice / height / resistance / terrainMap / counter
   │  applyDamageModifiers（抗性+专注射击）→ 地形减伤 → 反击
   │  产出 result { final_damage, dodged, formula[], dice, ... }
   ▼
[网关]  回写 writeBackTarget.currentStats.hp = hp - final_damage  (内存态)
        组装 res.json({ combat_result:{...}, reaction_events, victory, ... })
   ▼
[前端]  handleAttackResponse → refreshState() 重新拉 /state → 弹 AttackReportModal
        同时消费 reaction_events 驱动 7 个反应弹窗
```

**存储现状（关键）**：战局态 `battleStore` 是**网关进程内 Map**（combat.ts:54 注释「后续迁移至 Redis/PostgreSQL」）。`state.log`、每步 HP 写回均为内存态，**单机/沙盒战局结算结果不落任何数据库**，容器重启即丢失。

## 1. 数值提取阶段（棋子 & 技能）

### 1.1 棋子数值的来源与提取路径

| 数据项 | 最终提取位置 | 提取路径（逐跳） |
|--------|--------------|------------------|
| 攻击力（近战/远程） | `attacker.melee` / `attacker.ranged` | 前端 `unit.currentStats.melee/ranged/attack` → 部署 `deploy-unit` 写入 `BattleUnit.currentStats` → 网关 `toExecutorUnit` 映射 `melee: u.currentStats?.melee ?? u.melee` / `ranged: ...` |
| 防御/HP/最大HP | `target.hp` / `target.max_hp` | 同上；`toExecutorUnit`: `hp = u.currentStats?.hp`, `max_hp = u.currentStats?.maxHp \|\| u.currentStats?.max_hp` |
| 机动/移动力 | `unit.mobility` | `createBattleUnit` 经 `computeMobility(parts)` 算出（机体 2:1 最低5；载具/背包 3:1），与后端 `/move` 同源 |
| 射程 range | `casterUnit.currentStats.range` | 部署注入 `currentStats.range`；普通攻击 `inlineDef.max_range = rangeVal` |
| 最小射程 min_range | `currentStats.min_range` | 同上 |
| 高度 height（高地加成） | `unit.height` / 六角格高度 | 执行器 `getUnitHeight` 优先 `unit.height`（骆驼），回退 `context.battleState.map.hexes[q,r].height`（蛇 `_h`） |
| 闪避 evasion | `target.evasion_mod` | 源字段 `currentStats.evasion`（无驼峰）→ `toExecutorUnit` 重命名为 `evasion_mod` ⚠️ |
| 命中 accuracy | `attacker.accuracy_mod` | 源字段 `currentStats.accuracy` → 重命名 `accuracy_mod` ⚠️ |
| 抗性 resistance | `target.resistance.damage_kind_modifiers` | 部署 `currentStats.resistance`；`damageModifiers.getUnitResistance` 兼容 `equipment.resistance` |
| 阵营/持有者 | `unit.faction` / `unit.ownerId` | `toExecutorUnit`: `faction = u.ownerId ?? u.faction` ⚠️（见 §4-B） |
| 视图图 viewUrls | `unit.viewUrls`（键 '0'~'6'） | `deploy-unit` 取 `unitData.view_urls ?? unitData.viewUrls` → `BattleUnit.viewUrls` |

### 1.2 技能数值的来源与提取路径

| 来源 | 路径 | 备注 |
|------|------|------|
| **普通攻击**（melee/ranged） | 网关 `inlineDef` 内联构造（combat.ts:909-930） | `attack_stat`、`base_damage`(=exeCaster.ranged/melee)、`dice_type:'1d6'`、`success_line:4`、`damage_kind:'kinetic'` |
| **技能攻击**（attack_type='skill'） | 词条库 `glossary-skill-config.json` → `configLoader.getSkillConfig(key)` | `skill_id`(UUID) → 施法者 `owned.skills` 映射出 glossary key → `getSkillConfig` 取 `base_damage/dice_type/success_line/damage_kind/attack_stat/height_bonus_per_diff/accuracy_mod/evasion_mod/status_effects` 等 |
| 词条库加载 | `combat-service/src/config/glossary-skill-config.json` | 段：`damage_kinds`(5) / `action_types`(5) / `skills`(18+) / `systems` / `terrains`(10) |
| 地形数值 | 同上 `terrains.*` | `defense_bonus`（固定减伤%）、`move_cost`、`damage_kind_modifiers` |
| 伤害类型 | `glossary.damage_kinds` | `kinetic/beam/explosive/corrosive/...`，`label` 为中文展示名 |

**提取核心函数**：`toExecutorUnit`（combat.ts）是唯一「前端 BattleUnit → 引擎 unit」的翻译器，所有 snake/camel 映射在此集中发生（见 §4）。

## 2. 伤害结算阶段（完整公式 + 数据项来源）

执行器 `_executeAttackSkill` 内联公式（skillExecutor.cjs:281-371），每一步的数据项与来源代号：

```
① 基础攻击力 baseDamage
   来源：attacker[attackStat]  (attackStat = 'melee'|'ranged'，取自 inlineDef.attack_stat 或 glossary.attack_stat)
         回退 attacker.attack；普通攻击另由 inlineDef.base_damage 预置
   来源代号：currentStats.melee / currentStats.ranged / currentStats.attack

② 骰子加成 diceBonus
   解析：dice_type='1d6' → roll=1+floor(rand*6)
         isSuccess = roll >= success_line (普通攻击=4)
         bonusDamage = isSuccess ? success_bonus_damage : 0
         （dice_ranges 分段模式：按区间给 bonusDamage）
   来源代号：skillDefinition.dice_type / success_line / success_bonus_damage / dice_ranges

③ 高地加成 heightBonus
   高度差 heightDiff = getUnitHeight(attacker) - getUnitHeight(defender)
         （attacker.height 优先，回退 map.hexes[q,r].height）
   heightBonus = height_bonus_enabled ? heightDiff * height_bonus_per_diff : 0
   来源代号：unit.height / context.battleState.map.hexes[].height / glossary.height_bonus_per_diff

④ 小计 subtotal = baseDamage + diceBonus + heightBonus

⑤ 抗性减伤 resistReduction
   applyResistance(target, subtotal, damageKind)
   取 target.resistance.damage_kind_modifiers[damageKind]
   来源代号：currentStats.resistance.damage_kind_modifiers / damageKind(=glossary.damage_kind)
   finalDamage = subtotal - resistance

⑥ 专注射击 focusedFire（攻击方增益，叠加在减伤之后）
   条件：caster 持有 focused_fire 技能 + attackStat==='ranged' + caster.has_moved!==true
   行为：1d6 → 1-4:+3 / 5-6:+5，并入 finalDamage
   来源代号：caster.skills / glossary.focused_fire.dice_ranges / caster.has_moved

⑦ 地形减伤 terrainReduction
   _getTerrainDefenseBonus(target.q, target.r, terrainMap)
         = round( (地形 defense_bonus/100) * 当前伤害 )
   terrainMap 来自 context.terrainMap = buildTerrainMap(battle)（"q,r"→terrainId）
   来源代号：context.terrainMap / glossary.terrains[terrainId].defense_bonus

⑧ 反击 counterDamage（反向，单独展示）
   条件：target 持有 'counter' 技能 且 target 在反击射程内
   来源代号：target.skills / glossary.counter / uf.max_range

⑨ 最终伤害 final_damage = max(0, ⑦后值) ；若 dodged → finalDamage = 0
   闪避判定：netDodge = max(0, target.evasion_mod - attacker.accuracy_mod)；1d6<=netDodge 即闪避
   来源代号：target.evasion_mod / attacker.accuracy_mod
```

**引擎回传 `result` 字段（skillExecutor.cjs:350）**：
`triggered, type, action_type, attack_type, attack_stat, damage_kind, base_damage, dice, height_bonus, height_diff, final_damage, bonus_value, dodged, counter_triggered, counter_damage, accuracy_mod, evasion_mod, status_effects, formula[]`

## 4. 数据一致性审查（跨容器数据代号核对）

逐跳核对 `前端发送 → 网关 → 引擎 → 网关响应 → 前端读取` 的代号/格式。以下为**已发现的不一致点**，按严重程度标注。

### ⚠️ 不一致 A：`faction` 语义被覆盖（高风险，逻辑层 vs 展示层语义分裂）
- **位置**：`toExecutorUnit`（combat.ts）`faction: u.ownerId ?? u.faction`
- **现象**：引擎里 `unit.faction` 实际 = **ownerId（玩家ID）**，而非 UI 展示用的阵营（earth/balon 等）。执行器 `sameFaction = getFaction(attacker) === getFaction(target)` 比较的是 ownerId。
- **后果**：单人沙盒（两阵营单位同 ownerId）在引擎内被视为「同阵营」；而前端 `AttackReportModal` 用 `unit.faction`（真实阵营）做颜色/标签。展示与逻辑对「faction」的定义不一致，存在友军判定/展示错位的隐患。

### ⚠️ 不一致 B：闪避/命中的字段重命名（中风险，源名≠引擎名）
- **位置**：`toExecutorUnit` `evasion_mod: u.currentStats?.evasion ?? u.evasion_mod`；`accuracy_mod: u.currentStats?.accuracy ?? u.accuracy_mod`
- **现象**：`currentStats` 里的源字段叫 `evasion` / `accuracy`（无驼峰、无 `_mod` 后缀），经映射后变成引擎用的 `evasion_mod` / `accuracy_mod`。
- **后果**：若上游（前端/单位库）只产出 `evasion` 而引擎各处统一读 `evasion_mod`，则依赖 `toExecutorUnit` 这一处翻译；一旦某路径绕过该翻译直接拿原始 unit，字段名即对不上。属「命名约定不统一」。

### ⚠️ 不一致 C：`maxHp`(camel) vs `max_hp`(snake)（中风险，双写容错掩盖）
- **位置**：前端 `currentStats.maxHp`(camel)；引擎/DB `max_hp`(snake)。
- **现象**：`toExecutorUnit` 做 `max_hp = u.currentStats?.maxHp || u.currentStats?.max_hp`；执行器内 `ConditionEvaluator` / `applyDamageModifiers` 多处用 `unit.max_hp || unit.maxHp` 双向容错。
- **后果**：靠「`||` 双写容错」维持运行，源字段命名未统一；新增代码若只写其一可能取到 undefined。前端 `unitSnapshot` 读 `u.maxHp ?? u.currentStats?.maxHp`（始终是 camel）。

### ⚠️ 不一致 D：公式「抗性减伤」步骤混入专注射击，且专注射击不单独展示（中风险，展示归因错误）
- **位置**：skillExecutor.cjs:298 `resistReduction = subtotal - mod.damage`，其中 `mod.damage` 已含 `抗性减伤 - 专注射击 +`。
- **现象**：`applyDamageModifiers` 先减抗性、再加专注射击，但 `resistReduction` 取的是两者净额（`resistance - focusedFire`）。公式数组里**只有「抗性减伤」一行**，没有「专注射击」独立项。
- **后果**：① 若专注射击(+5) > 抗性(-6)，「抗性减伤」会显示为负值（实为净增益），标签误导；② 专注射击的 +伤害**完全不出现在公式明细**，玩家看不到这笔加成来源。属「计算与展示不对称」。

### ⚠️ 不一致 E：请求体 `attack_stat` 为死字段（低风险，文档/路由不符）
- **位置**：`/attack`（combat.ts:862）`const { attacker_id, target_id, attack_type, skill_id, context } = req.body`。
- **现象**：普通攻击路径**只读 `attack_type`**，据此构造 `inlineDef.attack_stat`；`attack_stat` 虽在别处被 `body.attack_stat || body.attack_type` 引用，但普通攻击分支不取它。`/skill` 路径又用 `skillType`/`skill_id`。
- **后果**：同一概念在 `/attack` 叫 `attack_type`、在 `/skill` 叫 `skillType`/`skill_id`，命名风格不统一；`attack_stat` 在 `/attack` 请求层实际无效，易误导调用方。

### ⚠️ 不一致 F：`dice` 数据已回传但结算弹窗不消费（低风险，展示冗余/不对称）
- **位置**：引擎 `result.dice { roll, isSuccess, successLine, bonusDamage, diceType }` → 网关包进 `combat_result.dice` → 前端 `data.combat_result.dice` 但 **`AttackReportModal` 不读取 dice**。
- **现象**：骰子明细已产生并返回，普通攻击弹窗只以「骰子加成」文字展示；完整 `dice` 对象仅在技能攻击的 `diceRollState` 弹窗里用。
- **后果**：数据冗余、展示不对称；若想让玩家看骰子点数，需前端补消费。

### 一致性通过项（已核对无误）
- ✅ 网关响应用 `combat_result` 包裹，字段 `final_damage / dodged / formula / dice / attack_type / damage_kind` 与前端读取 `data.combat_result.*` **完全对应**（非 `result.*` 直读，需注意此包一层）。
- ✅ 普通攻击 `attack_type:'ranged'|'melee'` 由前端 `attacker.range>1` 推导，网关据此正确注入 `inlineDef.attack_stat` 与 `base_damage`，执行器 `attackStat` 经 `_getUniversalFields` 正确取 `skillDefinition.attack_stat`，melee/ranged 分支生效。
- ✅ `formula[]` 每步 `{label, value, desc, isSubtotal, isFinal, isCounter, warn}`（camel）前后端一致；`isFinal/isSubtotal/isCounter/warn` 标记正确驱动样式。
- ✅ `viewUrls` 键 '0'~'6'（字符串）在部署/渲染/弹窗快照三处一致（camel）。

## 5. 结论与建议

1. **链路贯通性**：请求→结算→响应→展示链路**已正确接通**；结算公式权威在 `skillExecutor._executeAttackSkill`，网关仅做翻译与 HP 回写。
2. **最需修复**：
   - **A（faction 语义）**：明确区分 `ownerId`（玩家）与 `faction`（阵营），不要在 `toExecutorUnit` 用 ownerId 覆盖 faction，否则引擎友军判定与 UI 阵营不符。
   - **D（公式归因）**：将「专注射击」作为公式独立步骤展示，并让「抗性减伤」只反映抗性本身（`resistReduction` 不应包含 focusedFire）。
3. **命名统一**：推动 `maxHp↔max_hp`、`evasion/accuracy↔evasion_mod/accuracy_mod` 在 `currentStats` 与引擎间统一为单一约定，移除 `||` 双写容错。
4. **持久化缺口**：单机/沙盒战局结算结果当前不落库（仅内存+stdout 日志），如需复盘/审计应接入 `state.log` 落 SQLite 或文件。
