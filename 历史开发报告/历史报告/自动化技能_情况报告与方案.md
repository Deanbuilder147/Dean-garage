# 自动化（auto）技能 · 情况报告与方案说明（修订版 v2）

> 核对日期：2026-07-28
> 依据：用户 6 条确认意见（持续回合 5/3/3、改为 duration 模型、自动化必须是"消耗 AP+持续增益"、focused_fire 改 2AP 强化攻击、scout 改 +机动值且时限同防御）
> 核对范围：glossary-skill-config.json、skillExecutor / damagePipe / buffManager / conditionTrigger、combat.ts（`/attack` `/skill` `/action` `/end-turn`）、NewBattleView.vue

---

## 一、现状核对（程序真实形态，未改动前）

1. **auto 技能清单（glossary）**
   - `assist`（auto/passive）：applies_on=attack，bonus=3，`consumption=counter count 5`
   - `guard`（auto/passive）：applies_on=defense，reduction=5，`consumption=counter count 3`
   - `blockade`（auto/passive）：applies_on=attack_debuff_target，mobility_debuff=5，`consumption=counter count 3`
   - `scout`（auto/active）：evasion_mod=2，aoe_radius=3
   - `focused_fire`：**定义分裂** — skills 段 `category:ranged`/`action_type:attack`/`bonus:4`/`base_damage:4`；systems 段 `category:auto`/`trigger:on_attack_declared`/`condition:forfeit_move_this_turn`/`dice_ranges`
2. **生效机制（已落地）**：`executeUniversalSkill` 对带 `applies_on` 的技能经 `buffManager.buildStatusInstance` 生成 statusEffect，`damagePipe.cjs:101-110` 用 `getMatchingStatus` + `conditionTrigger.matchTrigger` 按 `applies_on` 提取数值，`consumeStatus` 递减 counter。
3. **致命缺口**：`assist/guard/blockade/scout` 全在 `passiveTypes` 集合（`NewBattleView.vue:2567,2585`）被过滤出战术面板，前端从不向 `/skill` 发这些 key → statusEffect 永不创建 → **实际休眠、不可发动**。
4. **消耗模型**：当前是 `counter`（按事件次数），非 duration（按回合）。
5. **“防御”对照基准**：点击 → `/action defend` → 写 `statusEffect{type:'defense',duration:1,remainingTurns:1,value:3,source:'defend_action'}`；衰减靠 `applyNewRoundEffects`（`combat.ts:132-140`）轮首整体清除 `source==='defend_action'` —— **无通用 remainingTurns tick**。前端"状态效果"区（`NewBattleView.vue:264-266`）已同时支持「剩 N 次 / 剩 N 回合」两种展示。

## 二、用户确认的设计决策（6 条）

| # | 决策 | 要点 |
|---|------|------|
| 1·2 | **持续回合固定 5/3/3** | assist=5、guard=3、blockade=3（回合）。理由：发动自动化技能消耗 1 个战术行动"额度"，应换得相应量的增益机会。 |
| 3 | **自动化类别定位** | 绝不能粗暴定义为普通攻击（否则类别无意义）。必须是"**消耗行动 AP + 获得持续性增益**"的存在。assist/guard/blockade/scout 均归此类。 |
| 4 | **模型切换** | 由 counter（按事件次数）改为 **duration（按回合）**，解决结算消耗过猛问题。 |
| 5 | **focused_fire 重定义** | 类别内唯一"**攻击型自动化**"特例：消耗 **2 AP 点（= MOVE+ATTACK，取代原 forfeit_move_this_turn，复用现有 AP 系统、无需新码）**，换取一次强化攻击：攻击距离 **4–6**，伤害按骰子加成（**1→20%、2-5→50%、6→100%**）。 |
| 6 | **scout 重定义** | 时限**同防御**（直到自己下个回合开始）；效果改为 **+自身机动值**（非闪避）；"暴露 3 范围视野"实现为**对身边距离 ≤3 的所有敌方造成 0 点伤害**（占位钩子，供未来偷袭阵营"隐匿"技能作用）。 |

**AP 消耗汇总（决策）**
- `assist` / `guard` / `blockade`：消耗 **1 AP**（建议 DEFEND 类，与"像防御"一致）
- `scout`：消耗 **1 AP**（DEFEND 类），时限同防御
- `focused_fire`：消耗 **2 AP**（MOVE+ATTACK），一次性攻击

## 三、落地规格（glossary 字段改造）

| 技能 | category | type | 效果数值 | 持续 | 消耗 | 发动方式 |
|------|----------|------|----------|------|------|----------|
| `assist` | auto | passive→buff | 自身后续攻击 **增伤 +3** | **5 回合** | 1 AP(DEFEND) | 点击发动，duration statusEffect |
| `guard` | auto | passive→buff | 自身后续受击 **减伤 -5** | **3 回合** | 1 AP(DEFEND) | 点击发动，duration statusEffect |
| `blockade` | auto | passive→buff | 自身攻击时 **削敌机动 -5** | **3 回合** | 1 AP(DEFEND) | 点击发动，duration statusEffect |
| `scout` | auto | active→buff | **自身机动 +X**（建议 +2，待确认）、暴露 3 范围=对 ≤3 敌 0 伤 | 同防御（轮首清除） | 1 AP(DEFEND) | 点击发动 |
| `focused_fire` | auto | active(攻击型) | 强化攻击：距离 4–6，骰子加成 20/50/100% | 一次性 | 2 AP(MOVE+ATTACK) | 点击发动后执行一次攻击 |

**glossary 字段写法（建议）**
```json
"assist":   { "category":"auto","type":"passive","action_type":"buff","applies_on":"attack",
              "modifier":"attack_buff","bonus":3,"duration":5,
              "consumption":{"mode":"duration","count":5} },
"guard":    { "category":"auto","type":"passive","action_type":"buff","applies_on":"defense",
              "modifier":"defense_buff","reduction":5,"duration":3,
              "consumption":{"mode":"duration","count":3} },
"blockade": { "category":"auto","type":"passive","action_type":"buff","applies_on":"attack_debuff_target",
              "modifier":"mobility_debuff","value":5,"duration":3,
              "consumption":{"mode":"duration","count":3} },
"scout":    { "category":"auto","type":"active","action_type":"buff",
              "applies_on":"self","modifier":"mobility_buff","value":2,
              "aoe_radius":3,"duration":1,"consumption":{"mode":"duration","count":1},
              "note":"轮首清除(同防御)；暴露=对≤3敌0伤占位" },
"focused_fire": { "category":"auto","type":"active","action_type":"attack","damage_kind":"kinetic",
              "cast_range":6,"range_min":4,"range_max":6,"ap_cost":2,
              "dice_ranges":[{"min":1,"max":1,"bonus_pct":20},
                             {"min":2,"max":5,"bonus_pct":50},
                             {"min":6,"max":6,"bonus_pct":100}] }
```
> 说明：`assist/guard/blockade` 由 `counter` 改 `duration`，数值(bonus/reduction/value)保留原值；`focused_fire` 删除 systems 段 auto 冗余 + `forfeit_move_this_turn`，统一以 skills 段为准；骰子加成以 `bonus_pct` 表示（作用于最终伤害）。

## 四、代码改造清单

1. **glossary 字段调整**：按第三节改写 assist/guard/blockade/scout/focused_fire；删除 systems 段 focused_fire 的 auto 冗余定义。
2. **前端战术面板（`NewBattleView.vue`）**：把 `assist/guard/blockade/scout` 从 `passiveTypes` 移除（或单列 `automationTypes`），在「可用行动」生成可点击发动按钮 → `executeAction('automation', {skill_id})`；`focused_fire` 作为攻击技能保留在主动攻击列表，发动时消耗 2 AP 后进入攻击选靶。
3. **后端发动路由（`combat.ts`）**：新增 `actionType:'automation'`（或复用 `/skill`）→ `executeUniversalSkill(skillKey, caster)` 生成 duration 型 statusEffect；消耗 DEFEND(1) AP。
4. **核心新增 · 通用回合衰减 tick（必需）**：新增 end-round 的 `remainingTurns--` 递减逻辑，对 `consumption.mode==='duration'` 的 statusEffect 归零即移除。defend 当前靠轮首清除，自动化 duration 必须走此 tick，否则常驻。建议与 `applyNewRoundEffects` 合并为通用清理。
5. **damagePipe 适配**：duration 模式下**不再** `consumeStatus`（counter 递减），仅读取 `value`；`matchTrigger` 已按 `applies_on` 提取，无需大改。
6. **focused_fire 攻击分支**：消耗 MOVE+ATTACK(2) AP；攻击距离取 `range_min..range_max`(4–6)；伤害结算时按骰子 `bonus_pct` 加成最终伤害。骰子机制此前已去骰化（DiceEngine 移除），需恢复一个**轻量受控 rng 分支**（仅 focused_fire 用）。
7. **scout 机动增益**：新增 `mobility_buff` statusEffect 类型，移动寻路（`tsFindPath`/`computeMobility`）读取活跃机动 buff；或激活期直接给 unit 加机动值、轮首清除时回退（二选一，推荐 statusEffect 法以统一模型）。暴露 3 范围 = 对距离≤3 敌方单位执行一次"0 伤"占位结算（为偷袭阵营隐匿技能预留钩子）。
8. **AP 接线**：assist/guard/blockade/scout 消费 DEFEND(1)；focused_fire 消费 MOVE+ATTACK(2)。所有消费后调用既有 `markStandbyIfDone`（已存在于 battleStateFactory，系统级待机兜底）覆盖组合。

## 五、待确认 / 注意

- **5/3/3 回合的递减时点**：默认"每轮结束递减 remainingTurns"（5 回合≈5 轮）。若您意指"自身回合"递减，需改为在单位回合结束时 tick，请确认。
- **scout 机动值具体数值**：上文暂用 +2（沿用原 evasion_mod 量级），待您给定精确值。
- **骰子机制回归**：DiceEngine 此前已移除，focused_fire 需重新引入受控 rng（仅 1/2-5/6 三档），注意与去骰化的整体架构不冲突。
- **counter 模型已联调跑通** assist/guard/blockade，改 duration 后需回归：增伤/减伤/削机动数值是否仍正确，以及 duration tick 是否准确归零。
- **`focused_fire` 攻击距离"4–6"**：理解为射程**区间** [4,6]（最小 4、最大 6，狙击式不可打近身）。若您本意是"最大 6、无最小"，请告知。
