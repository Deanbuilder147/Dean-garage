# 自动化技能战斗机制 · 落地开发文档

> 日期：2026-07-28
> 范围：将 5 个自动化技能（助攻 / 守护 / 阻碍 / 侦察 / 专注射射）从「配置 + 编辑器可编辑」推进到「战斗引擎真实结算」。
> 配套前置：上一阶段已完成「词条编辑器全字段可编辑 + 完整中文释义」与配置层 duration 模型改造。

---

## 1. 机制总览

5 个自动化技能统一采用 **duration（持续 N 个阵营回合）** 消费模型，替代旧 counter（触发 N 次）模型：

| 技能 | 配置 key | action_type | 作用对象 | 生效时机 applies_on | 数值字段 | 持续 | 战斗效果 |
|------|----------|-------------|----------|---------------------|----------|------|----------|
| 助攻 | `assist` | buff | 自身 | `attack`（造成伤害时） | `bonus:3` | 5 回合 | 增益期间每次造成伤害额外 +3 |
| 守护 | `guard` | buff | 自身 | `defense`（受到伤害时） | `reduction:5` | 3 回合 | 增益期间每次受到伤害额外 -5 |
| 阻碍 | `blockade` | debuff | 自身生效、作用于攻击计算 | `attack_debuff_target` | `value:5` | 3 回合 | 施法者攻击时，对方机动值 -5（更易命中） |
| 侦察 | `scout` | buff | 自身 | `mobility`（机动） | `mobility_buff:2` | 1 回合 | 持续期间自身移动 +2、攻击端机动优势 +2 |
| 专注射射 | `focused_fire` | attack | 敌方 | （攻击结算） | `dice_ranges[].bonus_pct` | 单次 | 远程 + 放弃移动：按骰点 +20% / +50% / +100% 伤害 |

> 关键约定：**阻碍（blockade）的状态落在施法者身上**，由 `damagePipe` 在「施法者攻击」时读取 `attack_debuff_target` 来削敌机动。这与旧版「把 debuff 推给敌方目标」的写法是不同的（旧写法会让增益在结算时读不到）。

---

## 2. 配置层（`glossary-skill-config.json` → `skills` 段）

5 个技能均带 `category:"auto"` / `is_auto:true` / `is_automation:true`，并声明 `consumption:{mode:"duration",duration:N}`：

- `assist`: `bonus:3`, `applies_on:"attack"`, `modifier:"attack_buff"`, `duration:5`
- `guard`: `reduction:5`, `applies_on:"defense"`, `modifier:"defense_buff"`, `duration:3`
- `blockade`: `value:5`, `applies_on:"attack_debuff_target"`, `modifier:"mobility_debuff"`, `duration:3`
- `scout`: `mobility_buff:2`, `expose_radius:3`, `duration:1`（无 `applies_on`，由引擎特判为机动增益）
- `focused_fire`: `category:"ranged"`, `cast_range:6`, `min_cast_range:4`, `dice_ranges:[{min:1,max:1,bonus_pct:0.20},{min:2,max:5,bonus_pct:0.50},{min:6,max:6,bonus_pct:1.00}]`

> 编辑器（GlossaryView）通过 `skillContract.SKILL_FIELD_DEFS` 数据驱动渲染上述全部字段，并为每个字段附中文释义（见前置阶段）。

## 3. 引擎层改动（`services/combat-service/src/services/combatCore/`）

### 3.1 `buffManager.cjs`
- **`buildStatusInstance` 支持 duration 模式**：原来只识别 `consumption.count`（counter 模式），duration 配置会被兜底成 `remaining:1`（导致增益只生效 1 次就被攻击消耗）。
  修复后：当 `consumption.mode === 'duration'` 时生成 `{mode:'duration', remaining:duration, max:duration}`，由 `tickStatus` 在回合末递减。

### 3.2 `skillExecutor.cjs`
- **`_getUniversalFields` 新增字段**：读取 `mobility_buff` / `expose_radius` / `expose_damage`，使侦察技能字段贯通到内部统一结构 `uf`。
- **`_executeBuffSkill` 侦察分支**：当 `uf.mobility_buff && !uf.applies_on` 时，构造 `applies_on:"mobility"`、`action_type:"mobility_buff"`、`value:mobility_buff` 的状态实例写入自身。
- **状态去重（`_refreshOrAddStatus`）**：同 `source + action_type + applies_on` 的状态只保留一份，重复施放改为刷新 `remaining`，避免助攻/守护/侦察被无限叠层。
- **`_executeDebuffSkill`**：阻碍减益正确落在 `destUnit`（自身类→施法者），与 `damagePipe` 读取口径一致；同样走去重。

### 3.3 `damageModifiers.cjs`
- **`applyFocusedFire` 改为读 `bonus_pct`**：原逻辑读 `bonus_damage`（固定值），而配置现在是百分比。改为：
  `pct = r.bonus_pct != null ? r.bonus_pct : (r.bonus_damage || 0)`，
  并在 `applyDamageModifiers` 中按 `dmg += Math.round(dmg * pct)` 施加，回传 `focusedFirePct` / `focusedFireBonus`。
  - 触发条件：持有 `focused_fire` + 远程攻击 + 本回合 `has_moved !== true`（放弃移动）。

### 3.4 `damagePipe.cjs`
- **攻击端读取侦察机动增益**：在 `_executeAttackSkill` 中通过 `BuffManager.getMatchingStatus(attacker, ctx, 'mobility')` 累加攻方有效机动，使侦察的 +2 机动在攻击命中计算中生效。

### 3.5 引擎自检（本地 Node 验证，全部 PASS）
`buildStatusInstance` duration、`tickStatus` 递减、`applyFocusedFire`（骰点 1→20% / 3→50% / 6→100% / 已移动→0）、`scout` 生成机动状态、`assist`+3 持续 5、`blockade` 落施法者 +5、`assist` 重复施放不叠层 —— **ALL_PASS**。

## 4. 网关层改动（`backend-gateway/src/routes/combat.ts`）

- **`/end-turn` 接入 `BuffManager.tickStatus`**：回合末对结束阵营单位同时调用 `tickBuffs`（旧 duration 字段）与 `tickStatus`（新 consumption.duration），实现自动化增益倒计时，归零即清除。
- **`/move` 读取侦察机动状态**：移动范围计算在原有 `mobility_buff` 标量之外，额外累加 `statusEffects` 中 `applies_on:"mobility"` 且 `consumption.mode:"duration"` 的状态值，使侦察 +2 真实扩大移动范围。
- **`/skill` 路由**：自动化自身技能（assist/guard/blockade/scout）由前端经此路由施放，引擎写回 `statusEffects` 到对应单位；攻击类（focused_fire）仍走 `/attack`（沿用 ATTACK 行动点消耗）。

## 5. 前端改动

### 5.1 `frontend/src/api/client.js`
- 新增 `skill: (id, data) => apiClient.post('/combat/${id}/skill', data)`。

### 5.2 `frontend/src/views/NewBattleView.vue`
- 新增 `onTacticalSkillClick(skill)` 分发器：
  - `assist / guard / blockade / scout`（自身增益/减益）→ 直接调用 `castAutomationSkill(skill, null)`，经 `/skill` 对自身施放。
  - 其余（含 `focused_fire`，远程攻击）→ 走原有 `selectTacticalSkill` → `/attack` 流程（含 `bonus_pct` 加成与 ATTACK 行动点消耗）。
- 战术技能按钮 `@click` 由 `selectTacticalSkill` 改为 `onTacticalSkillClick`。

### 5.3 `frontend/src/contracts/skillContract.js`（修复）
- 修复导出：补齐 `export function hydrateSkill`（上一轮编辑器改造遗留的导出缺失，导致前端构建失败），保证 GlossaryView 加载方向字段贯通、保存不丢。

## 7. 已知限制 / 后续待办

1. **技能施放不强制消耗行动点**：`/skill` 路由未接入 AP 模型（assist/guard/blockade/scout 免费施放）。如需平衡，可让 `/skill` 消费 ATTACK 行动点或新增「技能点」。
2. **`expose_radius`（侦察暴露）为占位**：当前仅把值带入状态对象，未接「战争迷雾/视野」系统（项目本无该机制），对实战暂无影响。
3. **`focused_fire` 需 `has_moved === false`**：引擎按 `caster.has_moved` 判定是否放弃移动；后端 `toExecutorUnit` 是否同步该字段取决于 `/move` 是否回写，实战需确认。
4. **真实战局 E2E**：建议开一局含上述技能的单位实战验证（增益数值、持续回合、专注射射百分比、侦察移动+2）。
