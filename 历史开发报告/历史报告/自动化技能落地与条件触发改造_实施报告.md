## 二、代码改动清单（7 个文件）

### 1. `services/combat-service/src/services/combatCore/conditionTrigger.cjs`（新增）
- 条件触发匹配引擎。`matchTrigger(buff, ctx)`：
  - `unconditional` → 恒返回 `true`；
  - `conditional` → 攻击类型(attack_type) **AND** 伤害类型(damage_kind) 同时命中才返回 `true`（任一为 `null`/空 = 不限）。
- 纯函数，不修改任何状态（契合"单向数据管道"宪法）。

### 2. `services/combat-service/src/services/combatCore/BuffManager.cjs`（重构）
- 顶部引入 `matchTrigger`。
- 保留旧标量 API（`addAttackBuff` 等）作为回退壳。
- 新增结构化 API：
  - `buildStatusInstance(skillType, uf)`：由词条通用字段构造实例（含 `id/source/label/action_type/value/consumption/trigger/applies_on`）。
  - `addStatus(unit, instance)`：写回单位。
  - `getMatchingStatus(unit, ctx, appliesOn)`：按生效方向 + matchTrigger 过滤。
  - `consumeStatus(unit, id)` / `consumeStatuses(unit, ids)`：counter 模式 `remaining--`，归零移除。
  - `tickStatus(unit)`：duration 模式回合末扣减。

### 3. `services/combat-service/src/services/combatCore/skillExecutor.cjs`（核心）
- 引入 `BuffManager`。
- `_getUniversalFields` 透传 `trigger` / `applies_on` / `modifier` / `consumption` / `target_scope`。
- `_executeAttackSkill` 集成（**真实生产结算管线**）：
  - 阶段 1.5：`attack_debuff_target` 提取 blockade，从目标有效机动扣减（机动削弱）。
  - 阶段 3.5：`attack` 提取 assist，加入伤害（未闪避才生效）。
  - 阶段 8.5：`defense` 提取 guard，减伤（未闪避才生效）。
  - 产出 `result.triggered_status`（被命中且使用的 statusEffects.id 列表）。
- `_executeBuffSkill` / `_executeDebuffSkill`：仅当词条显式声明 `applies_on` 时，构造并写回 statusEffects 实例（老 buff 走原路径，不影响 stable/sniper/scout）。
- **删除** `executeAssist/executeGuard/executeBlockade` 及 `initAssistCounter/initGuardCounter/initBlockadeCounter`。

### 4. `services/combat-service/src/services/combatCore/damagePipe.cjs`（Phase 4 纯函数管线）
- 引入 `BuffManager`。
- 阶段 1.5/3.5/8.5 同样用 matchTrigger 过滤 attack/defense/attack_debuff_target。
- 产出 `result.triggered_status`（供 `/damage` 测试端点与一致性校验）。

### 5. `services/combat-service/src/config/glossary-skill-config.json`（配置）
- `assist`：`applies_on:"attack"`, `modifier:"attack_buff"`, `consumption:{mode:"counter",count:5}`
- `guard`：`applies_on:"defense"`, `modifier:"defense_buff"`, `consumption:{count:3}`
- `blockade`：`applies_on:"attack_debuff_target"`, `modifier:"mobility_debuff"`, `consumption:{count:3}`
- 未来条件技能只需配 `trigger:{type:"conditional",attack_type:[...],damage_kind:[...]}` 即可落地，引擎零改动。

### 6. `backend-gateway/src/routes/combat.ts`（真实路径接线）
- 引入 `BuffManager`。
- `toExecutorUnit` 新增 `statusEffects` 字段（传入引擎供动态提取）。
- 新增 `applyStatusEffectsWriteback(casterUnit, exeCaster, targetUnit, exeTarget, result)`：消费 `triggered_status` 层数 + 写回真实单位（引擎保持纯函数，单向管道末端落盘）。
- `/skill` 与 `/attack` 路由在结算后调用，完成激活持久化与攻击消费。

### 7. `frontend/src/views/NewBattleView.vue`（前端反馈）
- 战斗面板新增"状态效果"区：显示每个 statusEffects 的标签、数值（增伤/减伤/削敌机动）、剩余次数/回合、条件标签（如"仅 近战 · 任意伤害"）。
- 新增 `conditionLabel(trigger)` 方法翻译条件文案。

## 三、架构要点（回应三点拍板）

1. **补给射程自相矛盾**：已在上一版报告修正（`{min:1,max:1}`，禁止对自己释放），本次代码未触碰但随 glossary 一并部署。
2. **架构脱节已消除**：Phase 5 彻底**废弃 `executeAssist/executeGuard/executeBlockade`**，增伤/减伤/削机动全部由 `_executeAttackSkill` 遍历 `unit.statusEffects` + `matchTrigger` 动态提取，与技能名解耦。
3. **blockade 生效目标**：`applies_on` 枚举扩充 `attack_debuff_target`，`_executeAttackSkill` 新增阶段 1.5 在机动差计算前扣除目标有效机动——blockade「下几次使对方机动-5」有了唯一落点。

## 四、验证结果

### 4.1 引擎逻辑验证（node 直连生产代码，模拟生产路径）
脚本直接 `new SkillExecutor()` 调用生产 `skillExecutor.cjs`，结果：

| 场景 | 结果 |
| --- | --- |
| 激活 assist | 生成 statusEffects 实例（applies_on:`attack`, counter:5）✓ |
| assist 单位攻击 | 伤害 +3，`triggered_status` 含 assist id，counter 5→4 ✓ |
| 激活 guard | 实例（applies_on:`defense`, counter:3）✓ |
| 受击 | 伤害 -5，counter 3→2 ✓ |
| 激活 blockade | 实例（applies_on:`attack_debuff_target`, counter:3）✓ |
| blockade 单位攻击 | 目标有效机动被扣减，counter 3→2 ✓ |
| 条件技能 guard_melee（仅近战） | **近战受击**→触发，counter 2→1 ✓；**远程受击**→不触发、不消耗（counter 维持）✓ |

> 关键：条件匹配用 AND 语义（攻击类型 + 伤害类型同时命中）；不命中 = 既不增减伤害也不扣层数。

## 五、部署注意事项（关键坑）

- **glossary 是软链 + 镜像内 `/app/data` 目录**：Dockerfile 的 `RUN` 在全新构建时会把打包的 glossary 复制到 `/app/data` 并软链。由于 `/app/data` 是镜像内目录（**非** volume，`gateway_data` 卷只挂 `/data` 存 DB），每次 `docker compose build` 都会重新复制最新 glossary，**无需手动写容器**。
- **整目录 rsync 偶发漏传单文件**：本次 `BuffManager.cjs` 被整目录 rsync 跳过（疑似 exclude 规则/时序），最终用单文件 rsync 补齐。建议后续部署对关键 `.cjs` 做单文件校验后再 build。
- 重建顺序：rsync → 服务器 `cd frontend && npm run build` → `docker compose build --no-cache mecha-gateway mecha-frontend` → `up -d --no-deps` 各自。

引擎逻辑与部署均已验证，但**真实战局内的可视化链路**（开战 → 激活 assist/guard/blockade → 攻击 → 观察 buff 条剩余次数递减与条件标签）建议用户在浏览器实战确认：
- 开含 assist/guard/blockade 技能的单位战局；

- 自定义条件技能（词条配 `trigger` 对象）仅命中条件时生效。
