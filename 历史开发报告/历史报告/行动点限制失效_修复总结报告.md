## 一、背景与根因

行动点（AP）数据层是正确的：`createBattleUnit` 已把 `actionPoints` 重命名为 `action_points={MOVE:1,ATTACK:1}` 写入单位，`/state` 正常返回，回合重置（`isNewRound`）也正确恢复满点。

**失效根因（两个未接线 bug）**：
1. 后端 `/move` 与 `/attack` 路由执行后**从不校验 / 消费** `action_points` → 可无限移动、无限战术。
2. 前端按钮禁用依赖**后端根本没写的死字段** `has_moved`/`has_acted`（后端未生成、normalizeBattleState 未派生）→ 按钮永不置灰。
3. 「防御」按钮是**纯视觉空壳**：前端 `executeAction('defend')` 调用 `actionType:'defend'`，但后端 `/action` 无此分支 → 返回 `400 UNKNOWN_ACTION` 被前端 `try/catch` 静默吞掉。

本次修复将 P0–P3 全部实施，并把「防御」定义为「清零 AP + 结束本轮 + 持续到下次自己回合的 -3 减伤」。

---

## 二、改动清单

### P0 — 移动行动点限制（`combat.ts` `/move` 路由）
- 移动前插入 `hasActionPoints(unit, 'MOVE')` 校验，无点返回 `400 NO_MOVE_AP`。
- 移动成功后调用 `consumeActionPoint(unit, 'MOVE', 1)` 扣点（在 Royroy 自动重定位之后、`res.json` 之前）。
- 坐标硬编码 `1,1` 起点 bug 不在本次范围（与 AP 无关），保留。

### P1 — 战术行动点限制（`combat.ts` `/attack` 路由）
- 执行 `executeUniversalSkill` 前插入 `hasActionPoints(casterUnit, 'ATTACK')` 校验，无点返回 `400 NO_ATTACK_AP`。
- 结算写回（`applyStatusEffectsWriteback`）后调用 `consumeActionPoint(casterUnit, 'ATTACK', 1)` 扣点。
- 普通攻击与技能攻击**同源**共用 `ATTACK` 点 → 每回合仅 1 次战术，符合用户「1 战术行动」直觉。

### P2 — 前端按钮禁用接管（`NewBattleView.vue` `normalizeBattleState`）
- 由 `action_points.MOVE/ATTACK` 派生 `has_moved`/`has_acted`：
  ```js
  u.has_moved = (u.action_points?.MOVE ?? 1) <= 0
  u.has_acted = (u.action_points?.ATTACK ?? 1) <= 0
  ```
- 模板原有 `:disabled="u.has_moved"` / `:disabled="u.has_acted"` 逻辑**无需改动**即自动生效，避免重写大量 UI。

### P3 — 待机 / 防御终结单位行动
**(a) 待机**：`wait` 分支在原有 `standby=true` 基础上补 `u.action_points = {MOVE:0, ATTACK:0}`，待机后该单位不可再移动/战术。

**(b) 防御（新增 `defend` 分支）**：
- 非当前行动阵营返回 `400 NOT_YOUR_TURN`。
- 清零 `action_points = {MOVE:0, ATTACK:0}`（终结本轮）。
- 标记 `standby=true`（走现有全员待机自动跳阵营逻辑）。
- 写入「防御姿态」减伤 statusEffect（详见第三节）。
- 调用 `maybeAutoAdvance` 推进回合。

**(c) 减伤过期挂钩**：`applyNewRoundEffects`（于 `isNewRound` 调用）新增清除所有单位 `source==='defend_action'` 的 statusEffect，精确等价于「直到该单位下个自己的回合开始」。

### 前端防御按钮（`NewBattleView.vue` `executeAction('defend')`）
- 去掉 `try/catch` 吞错，改为真实 await 后端（后端无分支时由外层捕获报错）。
- 日志文案由误导性的「+15 护盾」修正为「进入防御姿态（受击 -3，直到下个自己回合）」。
- 防御后 `refreshState()` 拉回的新状态经 P2 派生，按钮自动置灰。

## 三、防御减伤机制（需求 2 可行性落地）

**结论已验证可实现**：复用现有 `guard` 技能的减伤管道，零新减伤公式。

- 伤害管道 `DamagePipe.calculate`（`services/combat-service/src/services/combatCore/damagePipe.cjs`）在 `_calcDefense` 中把 `BuffManager.getMatchingStatus(defender, ctx, 'defense')` 命中的 statusEffect 的 `value` 累加进 `guardVal`，再从总伤害扣除。
- 防御写入的 statusEffect：
  ```js
  {
    id: `defend_${u.unitId}_${Date.now()}`,
    type: 'defense',
    duration: 1, remainingTurns: 1, params: {},
    source: 'defend_action', label: '防御姿态',
    action_type: 'defense_buff', value: 3,        // 每次受击 -3
    consumption: { mode: 'duration', remaining: 1, max: 1 },
    trigger: { type: 'unconditional', attack_type: null, damage_kind: null },
    applies_on: 'defense',                        // 与 guard 同源
  }
  ```
- 生命周期：用 `duration` 模式 + `isNewRound` 清除（非 `counter`），语义严格对应「持续到下次自己回合开始」。

> 注：`StatusEffect` TS 类型仅声明 `id/type/duration/remainingTurns/params`，运行时引擎（.cjs）按 `any` 读取 `source/applies_on/value/consumption/trigger` 等字段，故推入时以 `as any` 保留运行时形状，已通过 `tsc` 类型检查。
