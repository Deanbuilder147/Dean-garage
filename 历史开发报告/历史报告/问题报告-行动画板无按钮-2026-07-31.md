# 问题报告：返回/进入战局后行动画板无任何动作按钮，所有角色无法行动

**日期**：2026-07-31
**现象**：战场与 UI 已正常显示（此前的 TDZ 崩溃已修复），但行动画板（Action Panel）中**不出现任何动作按钮**（移动 / 战术行动 / 防御 / 待机），无论选中哪个棋子，所有角色均无法进行任何行动。

---

## 一、根因结论（一句话）

**`factionRoles` 的数据结构在「方案A（faction×role 双语义）」重构时发生了语义变更，但前端 `isVisitor` 等判定仍用旧的「userId → 阵营信息」语义去查，导致 `isVisitor` 恒为真，整个行动按钮组被 `v-if="!isVisitor"` 隐藏。**

这是 2026-07-31 方案A 重构引入的回归，而非 TDZ 修复的连带问题。

---

## 二、证据链（关键代码定位）

### 1. 后端真实结构：`factionRoles` = `{ faction: role }`

`backend-gateway/src/routes/combat.ts` — `reconcileFactionRoles()`（第 70–114 行）：

```ts
70:  function reconcileFactionRoles(battle: BattleState): void {
...
78:    const fr: Record<string, string> = {};           // ← 键是 faction，值是 role 字符串
...
90:        fr[fs] = role;                                // fr['earth'] = 'attack'
...
113:   battle.factionRoles = fr;                          // 例如 { earth:'attack', maxion:'defense' }
114: }
```

`getBattleState` 返回时（第 778 行）直接透传 `factionRoles: battle.factionRoles || {}`，前端 `commitState`（NewBattleView.vue 第 3459 行）`factionRoles.value = rawState.factionRoles` 同步为后端结构。

### 2. 前端 `isVisitor` 用 `userId` 当键查 `factionRoles` → 恒为 true

`frontend/src/views/NewBattleView.vue`（第 783–790 行）：

```js
783:  // Batch C-4: 访客视图——当前用户非参战者（不在 factionRoles 且非 GM）则隐藏操作栏/AP 条
784:  const isVisitor = computed(() => {
785:    const myId = user.value?.userId
786:    if (!myId) return true
787:    const role = userStore.user?.role
788:    if (role === 'REFEREE' || role === 'DOMINATOR') return false   // GM 类账号放行
789:    return !factionRoles.value?.[myId]                            // ← 用 userId 查 faction→role 映射
790:  })
```

- `factionRoles.value` 实际是 `{ earth:'attack', maxion:'defense' }`，键是 **faction 名**。
- `factionRoles.value[myId]`（`myId` 是用户 ID，如 `deantest` 的 uid）必然为 `undefined`。
- `!undefined === true` → **`isVisitor` 对所有非 GM 普通玩家恒为 `true`**。

### 3. 模板：整个行动按钮组被 `v-if="!isVisitor"` 包裹 → 直接消失

`NewBattleView.vue` 第 225–317 行行动画板：

```vue
225:  <div class="ap-actions" v-if="!isVisitor">
226:    <div v-if="selectedUnit" class="ap-action-row">
227:      <!-- 移动 / 战术行动 / 防御 / 待机 四个按钮全在此块内 -->
...
317:  </div>
...
320:  <div v-else-if="selectedUnit" class="ap-visitor-note">观战模式…</div>
```

`isVisitor === true` 时，`.ap-actions` 整块不渲染，只显示「观战模式」提示 → **用户看到「行动画板里没有任何动作按钮」**。

### 4. 同类错配扩散：多处用 `factionRoles[myId].faction` 取「我的阵营」也恒为 undefined

- 第 2246 行：`const myFaction = user.value?.faction || battleState.value?.factionRoles?.[myId]?.faction`
- 第 3705 行：`const myFaction = userStore.user?.faction || battleState.value?.factionRoles?.[userStore.user?.userId]?.faction`

这两处预期 `factionRoles[userId]` 是 `{ faction, role }` 对象，但后端给的是 `role` 字符串，故 `?.faction` 恒 `undefined` → `myFaction` 解析失败（除非 `user.faction` 本身有值）。进一步导致「我的单位」识别、归属判定可能失真。

### 5. 排除项（已核查，非根因）

| 方向 | 结论 |
|------|------|
| `selectedUnit` 选中逻辑（第 2595 行 `selectUnitById`） | 正常，点击棋子可正确设置 `selectedUnit` |
| `isMyTurn` 门控（第 2963 行） | 正确：用 `getFactionRole(unit.faction)` 比 `activeFaction`，与后端一致 |
| `getFactionRole`（第 1669 行） | 正确：用 **faction** 查 `factionRoles`，与后端结构匹配 |
| 后端 `action_points` 返回 | `getBattleState` 展开 `{...unit}`，`createBattleUnit` 默认注入 AP 积木，`has_moved/acted/defended` 派生为 `false`，按钮不会因 AP 耗尽被 disabled |
| TDZ 修复 | 已正确（上移非响应式变量声明），与本次无关 |
| `canIssueCommand`（后端，第 301 行） | 正确：用 `resolveRole(factionRoles, faction)` 比对，与后端结构一致 |

> 注：GM/referee/dominator 账号（如测试账号 `deantest`）因第 788 行 `return false` 放行，`isVisitor` 为 false，按钮可正常出现——这进一步反证：普通玩家账号按钮消失正是 `userId` 键错配所致。

---

## 三、影响范围

- **全部非 GM 普通玩家账号**：进入任意战局（新建或返回）后行动画板为空，无法进行移动/攻击/防御/待机等任何操作。
- GM 类账号（referee/dominator）不受影响（被 isVisitor 放行）。
- 单人对战/沙盒模式若用普通玩家账号登录，同样受影响。

---

## 四、修复建议

核心思路：方案A 后，`factionRoles` 语义已固定为 **faction → role**。**「用户是否属于参战方」与「我的阵营」必须改用 `ownerId` / 单位归属判定，而非用 userId 查 factionRoles。**

### 修复点 1：`isVisitor` 改为基于「是否拥有场上单位」判定（推荐）

`NewBattleView.vue` 第 784–790 行。参战判据应改为：当前用户 `userId` 是否与任一单位的 `ownerId` 匹配（或房间配置其参战），GM 类仍放行：

```js
const isVisitor = computed(() => {
  const myId = user.value?.userId
  const role = userStore.user?.role
  if (role === 'REFEREE' || role === 'DOMINATOR') return false
  if (!myId) return true
  // 方案A：参战判据 = 场上存在 ownerId === 当前用户 的单位
  const units = battleState.value?.units
  const list = units ? (Array.isArray(units) ? units : Object.values(units)) : []
  const ownsUnit = list.some(u => String(u.ownerId) === String(myId))
  return !ownsUnit
})
```

### 修复点 2：`myFaction` 改用「我的单位 faction」推导

第 2246、3705 行，去掉对 `factionRoles[myId].faction` 的错误引用（该结构已不存在）：

```js
const myUnits = allUnits.value.filter(u => String(u.ownerId) === String(myId))
const myFaction = user.value?.faction || myUnits[0]?.faction || null
```

### 修复点 3（可选增强）：前端门控与后端对齐

后端 `canIssueCommand`（combat.ts 第 301 行）已用 `resolveRole(factionRoles, faction)` 比对，前端 `isMyTurn`（第 2963 行）已用 `getFactionRole(unit.faction)`，二者一致，无需改；仅 `isVisitor`/`myFaction` 两处须按上述修复。

---

## 五、验证方法

1. 修复后用**普通玩家账号**（非 referee）登录，进入战局：行动画板应出现「移动 / 战术行动 / 防御 / 待机」四个按钮。
2. 选中己方单位（ownerId === 当前用户）：按钮可用（`has_*` 为 false）；非当前行动阵营的单位点击时 `isMyTurn` 拦截并提示「当前行动阵营为 X」。
3. 用 referee 账号回归：仍正常显示按钮（GM 放行路径保持）。
4. 部署验收口径：资产哈希匹配 + 8081 在线可见按钮。

---

## 六、结论

本次「行动画板无按钮、所有角色无法行动」是 **方案A（faction×role 双语义）重构遗留的前后端 `factionRoles` 键语义不一致**所致：`isVisitor` 用 userId 查询实际以 faction 为键的映射，恒返回 true 隐藏了整个行动按钮组。TDZ 修复与本次现象无因果关系。修复集中在前端 `isVisitor` 与 `myFaction` 两处改用 ownerId/单位归属判定即可。
