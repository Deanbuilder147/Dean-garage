# 双子星功能模块拆分蓝图

> **版本**: v1.0  
> **颁布日**: 2026-06-22 (Phase 20)  
> **总监指令**: 长治久安工业化 — 将项目按功能物理拆分为两大独立工程  
> **适用范围**: 全栈 `frontend/` + `services/` 架构演进

---

## 一、拆分总纲

本项目当前为单体仓库，包含从单位编辑到实战操作的全链路功能。为达成长效工业化治理，即日起按**关注点分离**原则，拆分为两大独立工程：

```
┌──────────────────────────────────────────────────────────┐
│                   机甲战棋项目                             │
│                                                          │
│  ┌─────────────────────┐  ┌─────────────────────────────┐ │
│  │  工程一：战术侦察     │  │  工程二：实战演练             │ │
│  │  (Tactical Recon)    │  │  (Combat Drill)              │ │
│  │                     │  │                             │ │
│  │  · 单位编辑器        │  │  · 战前整备室                 │ │
│  │  · 词条造词教学      │  │  · 六角格战场 Canvas 核心     │ │
│  │  · 地图制作查看器    │  │                             │ │
│  └─────────────────────┘  └─────────────────────────────┘ │
│                                                          │
│  共享基础设施: hexUtils.js · 格纳库API · 词条库 · Docker  │
└──────────────────────────────────────────────────────────┘
```

---

## 二、工程一：战术侦察 (Tactical Recon)

**定位**: 战前情报准备 — 编辑单位、查阅词条、制作/查看地图

### 2.1 构成模块

| 模块 | 路由 | 核心文件 | 功能描述 |
|------|------|---------|----------|
| **单位编辑器** | `/unit` | `UnitView.vue` | 创建/编辑/配置机甲单位属性、装备、技能 |
| **词条造词教学** | `/glossary` | `GlossaryView.vue` | 词条百科浏览、造词向导、战斗机制讲解 |
| **地图制作查看器** | `/battlefield` | `NewBattlefieldView.vue` | 地图编辑器 + 预览器，支持六角格地形绘制与导出 |

### 2.2 对外接口（读/写）

- **格纳库 API** — 读取/修改单位数据 (`hangarAPI`)
- **词条 API** — 读取词条库配置 (`glossaryAPI`)
- **地图 API** — 读取/保存地图数据 (`battlefieldAPI`)
- **文件导出** — 地图 JSON 导出供实战演练加载

### 2.3 依赖关系

```
UnitView ──→ hangarAPI
GlossaryView ──→ glossaryAPI
NewBattlefieldView ──→ battlefieldAPI + hexUtils.js
                         ↑
                    独立渲染器（非 HexGridCanvas，地图编辑需精细像素控制）
```

### 2.4 治理红线

1. **战术侦察不得启动战斗** — 严禁调用 `combatAPI.createBattle` 或 `campaignAPI.startCampaign`
2. **地图编辑器可独立于 HexGridCanvas** — 地图编辑需要像素级精度，允许使用独立 Canvas 渲染管线
3. **格纳库写入必须带版本号** — 防止并发编辑覆盖

## 三、工程二：实战演练 (Combat Drill)

**定位**: 战斗全流程 — 从整备到战场到结算

### 3.1 构成模块

| 模块 | 路由 | 核心文件 | 功能描述 |
|------|------|---------|----------|
| **战前整备室** | `/preparation` | `NewPreparationRoom.vue` | 选择/配置出击单位、确认装备、选择地图 |
| **六角格战场核心** | `/battle/:id` | `NewBattleView.vue` | 回合制战术战斗：移动/攻击/技能/骰子 |
| **(剧情模式)** | `/campaign/:id` | `CampaignView.vue` | 剧情远征队管理 + 嵌套 NewBattleView 沙盒 |

### 3.2 对外接口（读/写）

- **战斗 API** — `POST /api/combat/:id/move`, `/attack`, `/action`, `/end-turn`
- **战役 API** — `POST /api/campaign/:id/move`, `/attack`, `/action`, `/end-turn`
- **格纳库 API** — 读取单位数据（只读，不出击时修改格纳库）
- **词条 API** — 读取技能/装备词条配置

### 3.3 核心共享基础设施

| 设施 | 路径 | 两工程共享 |
|------|------|-----------|
| `hexUtils.js` | `frontend/src/utils/hexUtils.js` | ✅ 六角格数学常数 + 坐标转换 |
| `HexGridCanvas.vue` | `frontend/src/components/HexGridCanvas.vue` | ✅ 实战 + 部分侦察功能 |
| `unitSpriteResolver.js` | `frontend/src/resolvers/unitSpriteResolver.js` | ✅ 单位精灵图解析（侦察预览 + 战场渲染）|
| `sanitizeUnitEquipment()` | 各文件内联 | ✅ DKM 清洗范式全局复用 |
| `combatAPI` | `frontend/src/api/client.js` | ✅ 战斗 REST (实战唯一，侦察不调用) |
| `hangarAPI` | `frontend/src/api/client.js` | ✅ 格纳库 (两工程读写) |
| `glossaryAPI` | `frontend/src/api/client.js` | ✅ 词条库 (两工程只读) |
| Docker Compose | 根目录 `docker-compose.yml` | ✅ 统一部署 |
| Nginx | `frontend/nginx.conf` | ✅ 统一反向代理 |

### 3.4 治理红线

1. **Canvas 是单向数据管道终点** — 严禁在 Canvas 渲染中读取 Vue ref/reactive（终极宪法第 1 条）
2. **装备 DKM 双防线清洗** — 提交前（整备室）+ 加载后（战场）各执行一次
3. **剧情/正常模式同壳分流** — `NewBattleView` 通过 `is_campaign` prop + `campaignApi` 适配器分流 API
4. **严防异步时序脱节** — 参见红线 #5

- 战术侦察 → `frontend-recon/` 独立 vite build

- 战术侦察: SPA 静态部署，无需后端（地图数据 localStorage）
- 实战演练: 全栈 Docker Compose，需远程服务器

## 五、拆分带来的收益

| 维度 | 拆分前 | 拆分后 |
|------|--------|--------|
| **变更风险** | 修改 UnitView 可能炸掉战场 | 两工程物理隔离，互不干扰 |
| **构建时间** | 全部 Vue 组件一起编译 | 独立构建，按需增量 |
| **团队协作** | 单文件多人修改冲突 | 工程边界明确，并行开发 |
| **故障定位** | 不确定是编辑问题还是战斗问题 | 错误堆栈自动指示所属工程 |
| **新人上手** | 3733 行 NewBattleView 难以阅读 | 工程隔离 + 文档导航 |
