# 词条库中枢 UI 补充计划（Phase F：让 B–E 机制在编辑器落地）

## 一、背景与目标

Phase B–E 已在**后端引擎**铺设机制（事件总线 19 键、六段式标准化、寿命管制 `checkCost/consumeCost`、伤害管道 13 段 hook、行动序事件），但**前端词条库编辑面板尚未开口**（见 2026-08-07 第十项核查）。

本计划目标：在现有 `GlossaryHub.vue` 的 `DetailPanel` 中补齐三类编辑面板，使六段式维度可被用户配置，并将触发条件选项统一到 `TIMING` 枚举真相源，消除契约错位。

**范围边界（强约束）**
- 加法式改造：仅新增编辑面板 / 字段，不删不改现有 9 条 runtime 词条的已读取逻辑。
- 默认不激活：`cost.enforce` 默认 `false`，UI 配置后仍需用户显式开启管制才生效（对齐后端 opt-in）。
- 旧扁平字段保留：`ap_cost` / 顶层 `trigger` 等继续可读，新面板写回时**双向映射**到六段式 `cost.*` / `timing.*`。

## 二、现状错位（必须修复的源头问题）

| 维度 | 前端现状 | 后端真相源 | 错位 |

## 三、设计原则（严格对齐前端风格规范）

新建面板遵循 `词条库中枢-前端风格.md` 的暗色控制台 / 琥珀主点缀 / 框中框层级：

- **背景层级**：面板 `rgba(0,0,0,0.1)` → 编辑区块 `rgba(0,0,0,0.12)` → 内联详情 `rgba(0,0,0,0.28)`。
- **框体**：外层暖灰 `rgba(159,142,120,0.12)`；越内层越琥珀（`.edit-block` 标题条 `#ffb000` 底 `rgba(255,176,0,0.06)`；`.block-body` 圆角 6px 琥珀描边）。
- **输入控件**：`.param-input/.param-select` 底 `rgba(0,0,0,0.35)`，文字 `#ffd597`，边 `rgba(255,176,0,0.22)`，聚焦发光 `box-shadow:0 0 0 2px rgba(255,176,0,0.15)`。
- **按钮**：新增用青 `#00b4dc`（`.btn-add`）；主保存琥珀渐变 `linear-gradient(90deg,#ffb000,#ff8c00)`；删除红 `#ff5252`。
- **提示文字**：冷蓝 `#7fb3d5`，11px，左对齐。
- **风格落地方式**：`DetailPanel.vue` 当前为 scoped `.dp-*` 样式，与 `GlossaryView` 的 `.panel/.edit-block` 不互通（scoped 隔离）。因此**新建子组件自带符合规范的 scoped 样式**（配色值逐字引用规范），保证与 `GlossaryView` 视觉一致。

## 五、详细方案（逐面板）

### 5.1 TimingPanel.vue（时机段 · 取代旧 trigger）

- **位置**：所有 `entryType` 均显示（对齐六段式 `timing` 为通用 WHEN 段）。
- **数据绑定**：`draft.timing.trigger`（新增标准字段）；保存时回写顶层 `draft.trigger = { type: timing.trigger }` 做读兼容。
- **下拉选项**：从 `enums.mirror.js` 的 `TIMING` 渲染，附中文 label 映射表：
  | 值 | 中文 | 值 | 中文 |
  |---|---|---|---|
  | `on_attacked` | 受击时 | `on_damage_dealt` | 造成伤害时 |
  | `post_melee_damage` | 近战伤害后 | `on_kill` | 击杀时 |
  | `on_attack_start` | 攻击开始时 | `on_target_selected` | 选定目标时 |
  | `on_turn_start` | 回合开始 | `on_round_start` | 回合开始（整局） |
  | `on_ally_attacked` | 友方受击 | `on_move_path` | 移动路径 |
  | `on_step_point` | 移动落点 | `on_airdrop_received` | 收到空投 |
  | `none` | 无（常驻/主动） | — | — |
- **风格**：`.edit-block`（琥珀标题「① 时机 Timing」）+ `.block-body` 内 `.param-row`（键|值 两列）。

### 5.2 CostPanel.vue（寿命管制 · cost 段）

字段（全部可选，对应 `CostSegment`）：

| 字段 | 控件 | 说明 | 后端映射 |
|---|---|---|---|
| `enforce` | 青/琥珀开关 `.btn.active` | **是否启用寿命管制**（默认关） | `checkCost/consumeCost` 仅 `enforce===true` 生效 |
| `ap` | number（max-width 80px） | 行动点消耗 | 与现有 `draft.ap_cost` **双向映射** |
| `charges` | number | 充能次数（用完即废） | `cost.charges` |
| `durability` | number | 词条自身耐久（独立于装备耐久） | `cost.durability` |
| `cooldown` | number | 冷却回合（时间轴，与 limit_scope 正交） | `cost.cooldown` |
| `limit_scope` | select（LIMIT_SCOPE） | 作用域：`match/faction/personal/per_turn` | `cost.limit_scope` |
| `slots` | number | 占用槽位数 | `cost.slots` |

- **提示**：`.param-hint` 冷蓝说明「`cooldown`（时间轴）与 `limit_scope`（作用域）正交，可叠加；`enforce` 不开启则本面板仅记录、不实际拦截」。
- **风格**：`.edit-block`（琥珀标题「④ 寿命管制 Cost」）+ `.block-body`。

### 5.3 RollPanel.vue（掷骰 · roll 段）

| 字段 | 控件 | 说明 | 后端映射 |
|---|---|---|---|
| `mode` | select（ROLL_MODE） | `none/dice/spinner/card_draw/rps` | `roll.mode` |
| `generator.method` | select（VALUE_METHOD） | `dice/spinner/card/rps`（可插拔 1–6 数值生成） | `roll.generator.method` |
| `segments` | 简易数组编辑（高级，可折叠） | 分支区间映射（如 1–3 精准命中） | `roll.segments` |

- **风格**：`.edit-block`（琥珀标题「③ 掷骰 Roll」）+ `.block-body`；`segments` 默认折叠（`.btn-ghost` 展开），避免日常编辑过载。

### 5.4 ConditionsEditor.vue（条件 · conditions[] 数组）

- **结构**：数组，每项 = `ConditionSegment { type, params }`。
- **`type` 下拉**（CONDITION_TYPE 中文 label）：`in_range` 在射程内 / `mutual_in_range` 互在射程 / `hp_compare` 血量比较 / `stat_compare` 属性比较 / `collinear_adjacent` 共线相邻 / `terrain_match` 地形匹配 / `damage_kind_match` 伤害类型匹配 / `has_not_acted` 未行动 / `not_in_scan` 未被扫描。
- **`params`**：键值对动态编辑器（`.param-row` 行 + 青色「+ 参数」`.btn-add`），值支持字符串/数字。
- **增删**：每项右侧红 `.btn-delete`；底部青 `.btn-add`「+ 添加条件」。
- **风格**：`.edit-block`（琥珀标题「② 条件 Conditions」）+ `.block-body`（数组项用 `.branch-card` 琥珀虚线描边区分）。

### 5.5 DetailPanel.vue 改造

- 移除现有 `v-if="special|faction|other"` 内的 `trigger.type` 下拉 + `trigger.condition` 阈值块（被 TimingPanel / ConditionsEditor 取代）。
- 在编辑模式区按序嵌入：`TimingPanel` → `ConditionsEditor` → `RollPanel` → `CostPanel` → 既有 `EffectStackBuilder`（保留）。
- 保留 faction 维度（limited_to / limit_count / stance）区块不变。
- 预览（只读）模式新增对应摘要行（timing / cost / roll / conditions 计数）。

### 5.6 HexCanvasEditor 连接适配（图层预览/适配栏 ↔ 新版本内容）

`HexCanvasEditor` 当前仅消费 `draft.range`（射程环 + 地图炮/AOE 打击层），对新面板内容**零响应**。本计划补三类连接，使图层预览/适配栏真正对六段式新版本内容做出反应：

**5.6.1 打通六段式 `target` 段 ↔ 射程图层（最关键缺口）**
- 现状：射程环由 `category + bonus_range` 经 `syncRangeToSkill` 推导，与六段式 `target{shape,range,count}` 是两套并行来源，新面板填的 `target` 不会反映到图层。
- 改造：`deriveRange()` 改为**优先读 `draft.target.min_range / draft.target.max_range`**（六段式真相），缺失时回退旧 `rangeStart/rangeEnd` 推导；双向映射——`onHexRange` 回写时同步填 `draft.target`。
- `target.shape` 增加绘制形态下拉：`circle`（默认环）/ `line`（线性，沿 facing）/ `custom`（沿用 mcShapes 自由绘制）。图层 tab「射程图层」加 `shape` 选择。

**5.6.2 新增「条件图层」tab（conditions 空间语义可视化）**
- 图层 tab(`layerOptions`) 增加 `{ value:'cond', label:'条件图层' }`。
- 仅对带**空间语义**的 condition 渲染覆盖层（非空间项跳过绘制）：
  | condition type | 图层表现 |
  |---|---|
  | `in_range` / `mutual_in_range` | 与射程环同构：符合格绿、超界灰 |
  | `collinear_adjacent`（共线相邻） | 以自身为中心的共线格高亮 |
  | `terrain_match`（地形匹配） | 需地图/地形数据；无数据降级为黄色「需实战地图校验」提示，编辑器内不绘具体格 |
  | 其余（`hp_compare`/`stat_compare`/`has_not_acted`/`not_in_scan`） | 非空间，跳过 |
- 多条件交集以叠加描边呈现；不符合项标灰，直观展示「该词条在哪些格子可发动」。

**5.6.3 适配栏摘要徽章（非空间维度连接）**
- `.he-head` 头部增加 `v-if` 徽章行，显示当前词条新维度概览：
  `⏱ timing:on_attack_start` · `🎲 roll:auto` · `♻ cost:enforce(开/关)` · `✦ conditions×N`。
- 即便 `cost/roll/timing` 无几何位置，预览栏也能"响应"新版本内容。

**5.6.4 响应式链路确认**
- `GlossaryHub` 已有 `watch(draft, …, deep)` 触发 `syncRangeToSkill` + 子组件 `watch(modelValue)` 重绘。
- 须确保 `draft.target` / `draft.conditions` 变动进入该依赖链，并在 `syncRangeToSkill` 内补 `target` 段回写，使 DetailPanel 改 target/conditions → 图层即时重绘。

## 六、数据模型对齐（六段式映射，保存时执行）

前端 `draft` 内部仍用易编辑的扁平结构，保存（`saveCurrent`）前做一次**标准映射**，确保落库数据符合 `GlossarySixSegmentEntry`：

```
timing.trigger      ← draft.timing.trigger            （同时回写 draft.trigger.type 兼容）
conditions[]        ← draft.conditions                （ConditionsEditor 直接维护）
roll                ← draft.roll                      （RollPanel 直接维护）
cost                ← { ap: draft.ap_cost, charges, durability, cooldown, limit_scope, enforce }
effects[]           ← draft.effects                   （EffectStackBuilder 已维护）
```

`loadConfig` / `onSelect` 时反向填充：`draft.cost = raw.cost || {}`；`draft.timing = raw.timing || { trigger: (raw.trigger&&raw.trigger.type)||'none' }`。

> 后端 `configLoader.normalizeEntry` 已对缺失六段字段补默认空值，前端即便漏填也不破坏装载（契约 `.passthrough()` 兼容）。
