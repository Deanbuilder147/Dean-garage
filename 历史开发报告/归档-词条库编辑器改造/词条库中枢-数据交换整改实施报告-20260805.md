# 词条库中枢改造 — 数据交换整改实施报告

**日期**：2026-08-05
**范围**：机甲战棋「词条库中枢」数据交换遗留问题（审计文档 `docs/机甲战棋-数据交换遗漏审计-20260804.md` 中的 P0 层1+层2）
**结论**：P0 两个核心遗漏（遗漏1 回查锚点 / 遗漏2 射程折算）已修复；P1/P2 列为后续项，不在本次强制范围。

---

## 一、根因回顾（与用户确认的共识）

- 战场**不是**只靠 `skill_key`，而是带着整包 skill 属性进场，再用 `skill_key` 回查 glossary 补全 AOE/射程词条。
- 编辑器旧版 `makeUnitSkill` 把射程写成**绝对字段** `cast_range: max`，而引擎 `getSkillRangeFields`（shared-kernel 唯一真相源）**只读相对字段** `bonus_range`（= 绝对射程 − 类型基准）。
- `passthroughSkills` 原本**剔除** `cast_range` 却**不折算成** `bonus_range` → 旧单位技能射程全部丢失（表现：技能能打、有名字有类型，但射程/AOE 词条补不回来）。
- 漏洞本质不是「editor 拆太碎」，而是「绝对射程字段 ↔ 相对射程字段」的两套模型在交换层没打通。

类型基准（来自 `shared-kernel/src/hexMath.ts`）：近战=1 / 远程=3 / 自动=0。

---

## 二、本次修改清单

### 1. 层2 前端源头治本 — `frontend/src/views/NewUnitEditorView.vue`
**函数**：`makeUnitSkill(s, min, max, label)`（第 949–971 行）

修改前：直接把 `cast_range: max` 等绝对字段透传到技能对象，无 `bonus_range`。

修改后：
- 新增**绝对→相对折算**：按 `s.type` 判定分类（ranged/auto/melee），`bonus_range = max(0, max − 类型基准)`。
- 技能对象新增**相对射程字段** `bonus_range` 与 `min_range`（自动类盲区 0，其余 1）。
- 保留绝对快照字段（`range`/`cast_range`/`rangeLabel` 等）**仅供前端录入回溯展示**，明确战场不读。
- 保留 `id`（UUID 防错位）、`skill_key`（回查锚点）、`prerequisite`（前置条件）透传。

### 2. 层1 网关交换层折算 — `backend-gateway/src/routes/rooms.ts`
**函数**：`passthroughSkills(rawList)`（第 38–99 行）

修改前：解构时**丢弃** `cast_range/max_range/range_max/rangeLabel`，但结果对象只接 `rest.bonus_range ?? null` → 旧数据（无 `bonus_range`）射程为 null。

修改后：
- 在结果计算处新增**绝对→相对折算块**：
  - `absMax = cast_range ?? max_range ?? range_max ?? rest.range`
  - `catForBase` 由 `rest.type` / glossary `type` 推导（ranged/auto/melee）。
  - `legacyBonus = absMax>0 ? max(0, absMax − BASE_RANGE[catForBase]) : null`
  - `bonusRange = rest.bonus_range ?? legacyBonus`（新数据优先，旧数据折算兜底）。
  - `minRange` 同理从 `min_cast_range/range_min` 折算，或用分类基准（auto=0 / 其余=1）。
- 显式保留 `skill_key` / `prerequisite` / `id`（即**遗漏1 回查锚点**，此前已透传，本次以注释固化约束）。
- `bonus_range` / `min_range` 成为引擎唯一合法射程入口，与 `getSkillRangeFields` 加法模型对齐。

### 3. 连带确认（非改动）
- `frontend/src/views/NewBattleView.vue` 的 `getSkillRange/getSkillRangeMin` 已调用 `getSkillRangeFields(skill)`，只认 `bonus_range/min_range` —— 交换层修通后前端射程预览自动恢复。
- `frontend/src/components/glossary-editor/JsonCompilerPanel.vue` 的词条 JSON 编译早已把 `cast_range` 折算为 `bonus_range` 并强制剔除绝对字段（`delete obj.cast_range` 等）——与本次方向一致，无需改。
- `passthroughSkills` 仅 rooms.ts 内部调用，无外部依赖，改动隔离安全。

## 四、部署步骤（按服务器纪律）

1. **前端**：rsync → 服务器 `cd /root/mecha-universe-engine/frontend && npm run build` → `docker compose build --no-cache mecha-frontend` → `up -d --no-deps mecha-frontend`。
2. **网关**：rsync → 服务器 `cd /root/mecha-universe-engine/backend-gateway && npm run build`（tsc 编 src→dist，须无隐式 any 报错）→ `docker compose build --no-cache mecha-gateway` → `up -d --no-deps mecha-gateway`。
   - ⚠️ 漏掉 `npm run build` 会导致 rooms.ts 改动不进容器 dist，线上射程仍丢失。
3. **验证**：开新战局，选带技能单位，确认技能射程 = `类型基准 + bonus_range`（远程=3+加成、近战=1+加成），AOE 形状正常投影。
