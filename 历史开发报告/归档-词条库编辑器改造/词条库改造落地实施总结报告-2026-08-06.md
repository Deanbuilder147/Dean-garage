## 三、§8.9 三处隐蔽细节落地

### ① 多 Effect 叠加的 L2/L6 谓语归属
- **定稿规则**：L2 `action_type` 仅决定主动作类型/主 UI 路由，**不参与子效果目标路由**；`effects[]` 每子效果携独立 `ef.target_type`，各自按目标二次子路由（主攻击走敌方、heal/buff 子效果走 SELF/SINGLE_ALLY，互不干扰）。
- **落点**：前端 `EffectStackBuilder.vue` 子效果 `target_type` 列（已有 TARGET_TYPES）+ 新增 L3/L6 注记；`DetailPanel.vue` 主谓语 `action_type` 与子效果 `target_type` 分离展示。
- **验证**：编辑复合技（攻击+自疗）时 UI 两列独立，无歧义。

### ② 状态效果 Duration 结算时机（expiry_phase）
- **定稿规则**：L6 状态挂接补 `expiry_phase ∈ {'turn_end','turn_start'}`，默认 `'turn_end'`；被动 `on_turn_start` Buff 默认 `'turn_start'`，避免“刚挂上就秒失效”。
- **落点**：
  - `shared-kernel/.../skill.contract.ts` `EffectContract` 新增 `expiry_phase` + `target_type`。
  - `skillExecutor.cjs` `_getUniversalFields` 将首个 status 效果的 `expiry_phase` 串入 `uf`。
  - `BuffManager.cjs` `buildStatusInstance` 写 `expiry_phase` 到实例；`tickStatus(unit, phase)` 改按相位递减，新增 `tickStatusStart`。
  - `combatIntegrator.cjs` `cleanupExpiredBuffs`(turn_end) + `startTurn`(turn_start) 接线（均 try/catch 防御）。
  - 前端 `EffectStackBuilder.vue` 状态效果新增 `expiry_phase` 下拉（默认 turn_end）。
- **验证**：contract 编译通过；引擎结构化 status 实例带 `expiry_phase`；双相位 tick 按相位递减。

### ③ 灰度平滑过渡期旧数据兼容（P0-4 软着陆）
- **定稿规则**：阶段 3（软着陆）读路径自动回填 `skill_key = skill_key || id || slugify(name)`，写路径 `normalizeSkillForSave` 补 `skill_key` 回填并剥 `id`；阶段 4 再在 `SkillContract` 硬拦截。
- **落点**：`glossary.ts` 读路径全量回填 + 写路径归一 + 新增 `slugify()` 辅助。
- **验证**：仅含 `id`/`name` 的旧词条 `GET` 回读已带 `skill_key`，无契约告警。

## 六、遗留与注意事项

1. **§8.9② 引擎状态应用主路径**：本次补齐 `expiry_phase` 采集与双相位 tick 接线，但结构化状态效果的实际挂接仍依赖 `skillExecutor._executeActiveSkill` 对 `uf.effects` 的既有处理。若实测发现被动 Buff 未严格按 `turn_start` 衰减，需进一步核查 `_executeActiveSkill` 是否将 `effects[].status` 落到 `unit.statusEffects`（该路径在 combatCore 中由 `applyStatus` 调用链承载）。
2. **阶段 4 硬拦截**：`SkillContract.skill_key` 当前未强制非空（依赖阶段 3 软着陆回填）。待存量数据全量回填 / 迁移脚本跑完后再摘除 `rooms.ts` 的 `effectiveKey` 兜底并硬约束 `skill_key`。
3. **历史报告一致性**：审计报告 §8.1/§8.4 的若干行号与路由签名已在之前的核查中修正（详见审计报告修订记录），本次实现以**实际代码**为准，未沿用旧行号。
