🗺️ 核心通用战棋规则母体系统（Universe Engine）策划文档
本策划文档旨在将原有的具体机甲战棋业务，向上全面抽空、归一化重构为一套通过元数据配置（Metadata-Driven）即可复刻一切 TRPG、跑团规则与战棋玩法的通用引擎系统。

🎯 一、 用户痛点（User Pain Points）
线下跑团与 TRPG 算伤地地狱
传统实体模型比赛、战锤 40K、TRPG 跑团等游戏，由于规则过于硬核，玩家在局内需要依赖繁琐的 Excel 自动卡、手动投骰子并依赖 DM（地下城主）进行复杂的肉眼和计算器伤害判定。这导致一局对战动辄数小时，流畅度极差，严重消耗玩家热情。

实体模型数字化（UGC 资产制作贵）
模型玩家亲手拼装、喷漆的实体塑料模型，长期以来由于缺乏便捷、低成本的数字化工厂通道，无法轻松转化为线上游戏内的高精度、多视态、带动作的专属数字棋子。

微服务烟囱乱象与环境死锁
原有分布式系统过于臃肿（7 个独立微服务、散落的内存与持久化两套实现），且受到历史交织修改的严重污染（如 CSP 安全头熔断、Autofill 与旧命令行视图冲突），导致真机环境高频卡死，无法长线进行生态开发。

规则复刻改动成本高
市面上大多数战棋游戏将属性、地形和技能公式在底层代码里硬编码死锁。一旦想要更换题材（如从机甲切换到龙与地下城、方格中世纪），必须将前后端推倒重来，无法实现“一套地基，吞噬一切规则”的母体化愿景。

🧭 二、 核心场景（Core Scenarios）
场景 1：实体模型转化与智能表单引导
玩家将自己亲手涂装的真实塑料模型拍摄正面、背面、左侧、右侧四个视角的照片上传。系统通过“填空表单 + 趣味随机摇骰”的智能提示词引导机制，强行确保生成出的单位风格契合底层世界观。系统通过适配器网关进行异步生成，30 秒后，格纳库中属于玩家的实体模型瞬间蜕变为带有 16 帧基线动画、符合 0-6 七视态天条的数字棋子。

场景 2：语言学语法树可视化组装
非编程人员（如跑团 DM、模型比赛组织者）点开技能编辑器。他们不需要手写任何英文代码，而是像拼乐高积木一样，通过界面组装“主谓宾定状补”的自然语言句子。

玩家行为：“我（主）专注射击（谓）左上第 4 格的目标（宾）；定语：舍弃本回合移动行动；状语：投掷 1d6 骰子结果等于 6；补语：最终使这次攻击增加 5 点能量伤害。”
拼装完成后，系统秒变大一统抽象语法树 JSON，并在战斗引擎中无状态地高效执行。

场景 3：不可变地图焦土沙盒对战
玩家在地图编辑器中编辑自定义地图或直接上传 JSON 模板，并保存为服务器不可变资产（Immutable）。
开战瞬间，战斗引擎在 PostgreSQL 数据库中针对当前局特定的 battle_id 注入一份地图深拷贝（Deep Copy）。游戏中激光炮轰塌高山、战役剧情破坏桥梁，100% 仅改写局内动态沙盒，一局打完战局销毁，原始 JSON 文件完美隔离、绝对不被污染。

场景 4：多端无感知延迟观战与秒连
对战在 3006 网关独裁执政下高速推进，每一次移动与摇骰子结果都作为不可变日志（ActionLog）写入事件溯源库。
微信小程序端的玩家点开“观战大厅”，连接到 3005 纯净消息缓冲器。3005 队列内部自动挂载 5-10 秒的延迟阻尼进行流式推流，观战玩家获得极为平滑、自带电视台转播感的低带宽流式延迟画面，且断线玩家可利用 ActionLog 5 毫秒内原地完美复刻、重放秒连。

🎛️ 三、 功能列表（Function List）
1. 🔑 账号鉴权与四级权限系统
游客层（Guest）：免 Token 柔性放行。解锁试玩战役、输入精准房号延迟观战权限。支持地图/单位编辑器的【本地暂存（LocalStorage）】功能，注册/登录后可一键同步至云本格纳库。

普通用户（User）：拥有完整的私人格纳库与对战功能。上传的自定义资产需经管理员审核。限制每日 AI 形象生成积分（Credits 扣减锁）。通过累积对局可申请或被邀请提升为“裁判”。

裁判（Referee）：拥有创建联机房间、设置房间内容的独裁权限。在局内天然拥有【无延迟 / 强制全屏实时观战】的上帝视角裁决权限（区别于微信观战）。

管理员（Admin）：内置审核队列防撞锁，5 分钟自动过期。拥有内容最高审核权。可在创作者授权下，执行【一键物理影子深拷贝（Deep Copy）】，将私人优质棋子复制为 user_id: 0 的大一统官方公共资产包，保留原作者版权勋章。

Dominator（制作人/总监）：拥有最高统帅权，可一键封禁账号、撤销/设置管理员。

2. 🎨 大一统纯净前端 Canvas 渲染内核
无状态组件设计（HexGridCanvasEngine.vue）：彻底剥离具体业务逻辑。只认离散数据包，在渲染层彻底合并地图编辑器与对战视图，死锁 0 修改，全局无任何翘翘板污染。

外挂式双策略解耦：

外壳策略 A（地图编辑器）：监听画布点击坐标，纯粹执行地形刷子改写与不可变 JSON 生成。

外壳策略 B（对战视图）：监听画布点击坐标，注入 drawFn 动态闭包钩子，渲染回合高亮、16帧基线动画、伤害飘字，并调取后端网关进行算伤结算。

离屏缓存防爆机制（Offscreen Canvas Cache）：前端时钟利用帧率计时器柔性兼容 16 帧与最高 64 帧资产。仅对屏幕视野内的可见单位执行切片播放，视野外棋子强行死锁在第一帧，将移动端/低配手机 CPU 与内存开销压低 70%。

3. 🎲 自然语言学规则引擎与算伤管道
原子词元固化（Lexical Tokens）：

主客体：SELF（主语）、TARGET（宾语）、AOE_RADIUS（特性半径）、ALL_ALLIES、ALL_ENEMIES。

状态/代价：MOVE_ACTION、ATTACK_ACTION、CURRENT_ENERGY、STEALTH。

数值动作：DAMAGE_PHYSICAL、DAMAGE_ENERGY（原光束大归一）、REPAIR、DICE_ROLL、EQUALS、CONSUME、BUFF。

定状补断言状态机（skillExecutor.ts）：支持一个词条同时挂载代价层、投骰层、多级负面分流层等多组定状补语句的动态串联叠加。内置 MAX_LOOP_STEP = 10 UGC 内容安全沙盒拦截，以及最外层刚性 try...catch 异常常规物理碰撞形变兜底结算，确保真机永不假死。

层叠与冲突管理器（Clash & Stack Manager）：在算伤管道（damagePipe.ts）内对所有并发现行词条分配层叠权重与互斥矩阵过滤，杜绝 Buff 覆盖冲突死锁。

4. 🎞️ 形象生成工厂（万能生成适配器）
Vendor Agnostic 抽象网关：将具体的第三方 API（如 meowa.ai）与业务完全抽离。更换或升级生成服务商时，100% 核心文件 0 修改。

4轴动作集死锁限制：首发版本为了控制服务器带宽与性能，机甲仅死锁生成 ['walk_forward', 'walk_backward', 'skill_01', 'skill_02'] 四个最高频基准动作状态，其余长线扩展。

异步 Webhook 熔断守护：由于 AI 生成需要时间，在单位表挂载异步状态机。设置 TTL Timer 生成超时守护进程，3 分钟未收到第三方回调，强行逆转状态为 failed 并友好弹窗释放机甲，防止玩家处于永久扫描假死量子态。

5. 📦 规则包一键换装热更新
解耦设计：系统彻底解耦为“引擎壳（Core Engine）”与“规则资产包（Rule Mod Pack）”。

无重启秒变新游戏：Dominator 通过后台一键上传带有全新规则、词元别名字典与精灵图的 RuleManifest.json 压缩包，前后端在内存中动态切换 KV 映射，100% 做到不重启任何 Docker 容器，整个平台一秒从《超级机器人大战》蜕变成《战锤 40K》或《龙与地下城》。

🛠️ 四、 技术选型（Technical Selection）
1. 🏗️ 架构拓扑
项目组织形式：大一统仓单仓管理（Monorepo），确保前后端最高契约（shared-kernel）完美对账，消除微服务割裂内耗。

容器与网络闭环：废弃多服务乱象，物理收拢对外暴露接口。公网仅开放前端静态网页（8081）与大一统中央网关总线（3006），其余持久层、缓存网络一律移出公网映射，走 Docker 内部自锁网络网格。

2. 🎨 前端技术栈（Frontend Stack）
核心框架：Vue 3 + Composition API + Vite

图形渲染：HTML5 Canvas 2D / WebGL 2.0 上下文

本地暂存：Browser LocalStorage 离线数据沙盒

实时流控制：Socket.io-client 实时异步流式拉取器

3. 🛰️ 后端与计算层技术栈（Backend Stack）
运行环境：Node.js 20+ (TypeScript / ES Modules 规范编译)

大一统网关服务：Express.js 多路复用中心

随机投骰解析引擎：Dicescript 脚本解析执行引擎（沿用并死锁其 AST 执行力）

异步任务守护：Cron Job (凌晨配额自动重置) + TTL Timeout Guard

4. 🗄️ 数据持久层与中央缓存（Data Layer）
战局运行时沙盒：PostgreSQL 14+（承载高并发战场深拷贝状态、事件溯源 ActionLog 写入）

大厅配置与本地 UGC：Better-SQLite3 (进程内高轻量读取，承载房间、用户权限、UGC单位资产)

中央状态缓存器：Redis Alpine 容器（提供分布式限流锁、匹配队列优先级调度、Session 中央暂存）
