## 一、页面入口

### 添加按钮

```
GlossaryView.vue 顶部工具栏
┌──────────────────────────────────────────────┐
│  [ 🔒 编辑模式 ]     [ + 添加新词条 ]          │
└──────────────────────────────────────────────┘
```

- 仅在**编辑模式**下显示「+ 添加新词条」按钮
- 点击后调用 `addNewSkill()` 函数
- 新词条默认 KEY 格式：`new_skill_{timestamp}`

### 删除按钮

```
每个词条卡片右上角
┌──────────────────────────────────┐
│ 词条名称: sweep        [ ✕ 删除 ] │
│ 词条 KEY: sweep        [ ✏ 编辑 ] │
│ ...                              │
└──────────────────────────────────┘
```

- 删除前弹出 `confirm()` 确认对话框
- 加入 `pendingDeletes[]` 队列
- **保存时**统一提交 `_delete_skills` 指令，后端 `deleteSkills()` 原子写盘


```
┌──────────────────────────────────────────────────┐

│  描述: [____________________________]              │
├──────────────────────────────────────────────────┤
│  通用结构化字段                                      │
│ ┌──────────────────┬──────────────────┐          │
│ │ 施放对象          │ 施放距离           │          │
│ │ [ 敌方 enemy  ▼]  │ [ 1  ] 格         │          │
│ ├──────────────────┼──────────────────┤          │
│ │ AOE 半径          │ 基础伤害           │          │

│    │ sector_angle: [60]              │            │
│    │ damage_modifier_precise: [-2]   │            │

│    │ ...                             │            │
│    └────────────────────────────────┘            │
└──────────────────────────────────────────────────┘
```

### 字段说明

| # | 字段名 | 中文名 | 输入组件 | 说明 |
|---|--------|--------|----------|------|
| 1 | `target_filter` | 施放对象 | `<select>` 下拉 | `enemy`(敌方) / `ally`(友方) / `self`(自身) / `all`(全员) |
| 2 | `cast_range` | 施放距离 | `<input type="number">` | 0-20，代表能打几格，对应 BFS 寻路算法 |
| 3 | `aoe_radius` | AOE 半径 | `<input type="number">` | 0-10，0=单体，>0=六边形溅射半径 |
| 4 | `base_damage` | 基础伤害 | `<input type="number">` | 任意整数，用于伤害管道结算 |
| 5 | `status_effects` | 附加效果 | `checkbox` 标签多选 | 支持多选组合 |

## 五、高级参数折叠面板

### 过滤逻辑

```javascript
// 通用 5 字段常量
const UNIVERSAL_KEYS = [
  'target_filter', 'cast_range', 'aoe_radius',
  'base_damage', 'status_effects'
]

function getAdvancedParams(skill) {
  // 返回 skill 中所有不属于 UNIVERSAL_KEYS 且不是元信息的字段
  // type, label, category, description, deterministic 等也过滤掉
  return Object.fromEntries(
    Object.entries(skill).filter(([k]) =>
      !EXCLUDE_KEYS.includes(k)
    )
  )
}
```

### 折叠状态

- 每个词条独立维护 `advancedOpen[key]: boolean`
- 新词条默认折叠（`advancedOpen[newKey] = false`）
- 点击 `▶ 高级参数` / `▼ 高级参数` 切换

## 六、KEY 重命名

```
编辑模式下，点击 KEY 文本即可进入编辑状态：

  词条 KEY: [ sweep        ] ← 直接输入新名称
            (原 KEY: sweep)

失焦触发 onSkillKeyBlur(oldKey):
  1. 校验 newKey 非空、不与已有冲突
  2. editableConfig.skills[newKey] = editableConfig.skills[oldKey]
  3. delete editableConfig.skills[oldKey]
  4. 清理 skillKeyEdits 映射
```

`skillKeyEdits: Record<oldKey, newKey>` 追踪所有编辑中的 KEY 名称

## 七、保存流程

```
┌─────────────────────────────────────┐
│  用户点击 [💾 保存词条库配置]          │
└──────────────┬──────────────────────┘
               ↓
  前台构造 payload:
  {
    skills: { ...editableConfig.skills },    // 新增/修改的词条
    _delete_skills: [...pendingDeletes],     // 待删除的 KEY 列表
    system_params: { ... }                    // 伏击/战争迷雾/暴击等
  }
               ↓
  POST /api/combat/glossary-config
               ↓
  后端 battles.js:
  1. 检测 _delete_skills → 调用 configLoader.deleteSkills([...])
     → fs.writeFileSync 原子写盘（删除指定 KEY）
  2. 深度合并 skills → configLoader.saveGlossaryConfig(data)
     → fs.writeFileSync 原子写盘（新增/修改）
               ↓
  返回 { success: true, updatedAt: "2026-06-20T..." }
               ↓
  前台:
  - 清空 pendingDeletes[]
  - 显示 "配置已保存" 提示
  - 战场端下次 refreshState / onMounted 自动拉取最新配置
```

## 九、SkillsExecutor 消费端

战场端 `skillExecutor.cjs` 新增三个方法读取通用字段：

```javascript
// 获取技能的 5 个通用字段
_getUniversalFields(skillKey) // → { target_filter, cast_range, aoe_radius, base_damage, status_effects }

// 获取技能范围（优先读 cast_range）
getSkillRange(skillKey)       // → cast_range || 旧 hardcode

// 获取 AOE 半径
getAoeRadius(skillKey)        // → aoe_radius || 0
```

### 执行方法适配

| 方法 | 适配内容 |
|------|----------|
| `canSniper()` | `cast_range` 优先于旧 hardcode |
| `executeCounter()` | `cast_range` 优先 |
| `executeThrow()` | `cast_range` 优先 |
| `executeSweep()` | `cast_range` + `base_damage` 优先，伤害消息使用 `base_damage` |
| `executeFocusedFire()` | `base_damage` 优先于旧 bonus |
